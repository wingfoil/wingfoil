## Rulings W0 (approver, 2026-10-28)

- **W0-R1 — channel: the Agent tool for all of `w0` (R3 A2's fallback), with the reason.** `agent execute` with the
  built-in `claude-code` adapter refuses without a terminal, even under `--dry-run`: `error: interactive launch needs a
  terminal on stdin and stdout` (`src/agent/execute.ts` step 12, `processHasTerminal`), and a desktop session's Bash
  has none (`bug-392`, `dl-202`). Verified on 2026-10-28 without launching an agent: a pty wrapper (`script -qec …`)
  passes the check under `--dry-run`, but the real launch is the interactive interface, which does not end at the end
  of the phase; `launch.headless` is read only from v1.0 (`src/agent/schema.ts`). A custom adapter running `claude -p
  "{bootstrap}" --output-format json … --mcp-config "{mcp_config_file}"` with `terminal: optional`, named by
  `team.agents.adapter`, passes `--dry-run` without a terminal (probe in a scratch worktree of `release/0.3`, never
  pushed, removed), but needs a configuration change outside this patch's scope and a permission mode that lets an
  unattended agent run Bash. It is an input for `dl-188` and v0.4's retrospective, not a `w0` change. Every launch is
  recorded with the reason "W0-R1".
- **W0-R2 — PATH guard (`bug-369`).** Each task has a shim directory outside the repository whose `wingfoil` runs
  `node <task worktree>/dist/cli.js`. Every Bash call of a launched agent starts with `export PATH=<shim dir>:$PATH`
  (the Agent tool's shell state does not persist between calls). Each agent's first action is
  `command -v wingfoil && wingfoil --version`; the orchestrator records the output, and a path other than the shim is
  a stop. (Under `agent execute` the MCP server is already the launching build, `runningBuildMcpServer`.)
- **W0-R3 — order and merges.** `task-308` alone first, through its merge into `release/0.3`; then `task-305` and
  `task-307` in parallel; `task-306` starts after `task-305` is merged (its `depends_on`: the design reads `task-305`'s
  Execution Notes, `dl-015`, and both bump `git-conventions.md`, once per branch). Merge order: 308 → 305 / 307 (in the
  order they are approved) → 306. Each task syncs `git merge --no-edit release/0.3` at red and at the end of refactor
  when the line moved.
- **W0-R4 — sessions per task.** `task-308`, `task-306`, `task-307`: four agents — design (architect) → red (qa) →
  green + refactor (developer, a fresh agent; refactor resumes green) → review (reviewer). `task-305`: three agents, the
  v0.3.1 schema — design (architect) resumed for green + refactor, red (qa), review (reviewer): its criteria are all
  characterization (directive and workflow text), so a separate design agent adds nothing; `green` stays
  `distinct_from: [red]` and `review` distinct from all.
- **W0-R5 — approvals in an asynchronous queue (R3 A1).** The orchestrator queues each gate — design, the
  `in-review → approved` approve, the `memory amend` of elements past their first state — with the full command,
  amends before the approve, and goes on with the other tasks. After an approve on a task branch the orchestrator
  writes the hand `finalize [approved → done]`, the bug syncs, the merge into `release/0.3` and the cleanup. Push,
  tags, publish, approve, reject and amend are the approver's alone.
- **W0-R6 — bugs found during a task.**
  1. A defect the task's change causes, or a same-class instance in the files the task touches, is fixed in the task
     (review findings included); it is never left in the notes.
  2. A defect outside the task is filed by the orchestrator through `bug-ingest`, serially, up to `open` with an empty
     `release`, on an `ingest/` branch cut from `release/0.3` when it exists there (a `main`-only defect follows R2 of
     the planning plan, after the merge forward); the triage is queued with a proposed release.
  3. `v0.3.2` is proposed only when the bug meets A3 (low or medium, a local fix, a stated expected behaviour) **and**

  5. A bug admitted into `v0.3.2` that fits no existing task becomes a task the approver admits (`pending → backlog`),
