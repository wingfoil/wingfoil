## Context

On 2026-10-22 the approver set out how work on a WingFoil-managed project proceeds: a sequence of `wingfoil`
commands, alternating with writing Memory elements and with agent runs that do a step's work (implementation,
review, …), themselves launched by `wingfoil`. Leave the writing aside, which an agent can do, and the rest is
mechanical terminal work. The approver asked whether the next step is for an agent session, a *process coordinator*,
to run those commands and write those elements. The analysis of that session found three points where such a
coordinator would depart from the design:

- the vision puts the sequencing of mechanical steps in the engine (P4.10, P4.12, v1.0);
- the North Star is the determinism of that process;
- `dl-141` rules out a WingFoil-owned agent runtime.

The analysis recommended a split: a deterministic driver, which is the engine, and an optional, thin coordinator
agent for the judgement points only, with no gate authority. On 2026-10-24 the approver asked for that proposal to be
formalized as a decision-log. Under the traceability directive's filing rule (`dl-118`) it is a real choice among
options, so it is a decision-log, captured through `decision-log-ingest`
(`.wingfoil/workflows/custom/decision-log-ingest.yaml` v1.1). The work is on branch `ingest/dl-process-driver`, in
worktree `../.wf2-wt/ingest-process-driver`, cut from `main` at `084eafe0`.

Build in use: the Memory operations run on the code build (`npm run build && node dist/cli.js`, `wingfoil-cli`
directive). `node dist/cli.js --version` prints `0.3.0 (084eafe0…)`. The pinned build (`npm run -s wingfoil --
--version` → `0.2.2`) is used for reads only.
