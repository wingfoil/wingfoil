Per task, in its own worktree `../.wf2-wt/task-<n>` on `task/<id>` cut from `main`; the orchestrator writes the hand
commits and the records of W0-R3, launches the phase agents with the Agent tool (W0-R1) and queues the gates (W0-R8).

1. **`start` · orchestrator (developer).** Pre-checks (W0-R4, growth); `git worktree add -b task/<id> ../.wf2-wt/task-<n>
   main`; `npm ci`; `npm run build` under the heavy-gate slot; the shim (W0-R2); hand commits
   `wf(task): start <id> [backlog → in-progress]` and, for each bug of `bug:`, `wf(bug): sync <bug> [planned →
   in-progress]`, with the §7 trailers.
2. **`design` · architect agent · approver gate.** Per-criterion classification and what red must pin; files to touch
   and `version:` bumps; the existing tests of those files and every test pinning the behaviour that changes;
   `depends_on` notes read; the spec amendments the criteria name prepared for the gate (S6 of the planning); a modified
   `.wingfoil/` proved against the pinned build. Design notes committed; the gate queued: the approver rules the
   decisions and records the step (W0-R3); the orchestrator writes the rulings into the notes.
3. **`red` · qa agent (fresh).** Tests only, black-box from the criteria; `npx tsc --noEmit` and `npx jest test/lint`
   before the red commit; `### red (qa)` with the red sha; the `red` record.
4. **`green` → `refactor` · developer agent.** Red's files untouched (T4); refactor gates: full suite, coverage ≥ 80 %,
   `lint`, `docs:api`, typecheck, the document-parity suites; `git merge --no-edit main` if it moved; self-review;
   `memory submit` (`in-progress → in-review`) and the bug syncs `[in-progress → in-review]`; the `green` and
   `refactor` records.
5. **`review` · reviewer agent (fresh, read-only) · approver gate.** Full suite on the task's head, BDD, `docs.parity`,
   every claim re-run, T4 checked; findings (W0-R9) fixed in the task or filed (W0-R10). The approve queued, the task's
   pending amends first.
6. **`done` · orchestrator, after the approver's approve is in `git log`.** On `task/<id>`: `wf(task): finalize <id>
   [approved → done]`, each bug `wf(bug): sync <bug> [in-review → resolved → closed]`; then `git merge --no-ff task/<id>`
   into `main` from a scratch worktree detached at `origin/main` updated with the previous merges; worktree removed,
   branch deleted after `git merge-base --is-ancestor`. Post-checks: the `### Retrospective` of the task and of each
   closed bug; the engine frontier (W0-R3).

**Acceptance of a phase report (C-19, `task-344`).** From `task-344`'s merge, a phase report is accepted only when
`node scripts/check-phase-report.cjs report --worktree <task worktree> --report <report file> --base <head at launch>
--since <launch time, UTC>`, run from the checkout detached at `main`, exits `0`; exit `1` is a report git contradicts
(W0-R10), exit `2` a malformed report the agent re-emits. The report opens with the header
`REPORT <task> <phase> head=<sha>`, followed, up to the first blank line, by one line per claim — `commit <sha>`,
`file <path>`, `uncommitted <path>`, `gate <test|coverage|build|typecheck> exit=<n>` — as the script's module doc
declares; prose follows the blank line. This replaces the fixed list of W0-R6 for every report; the records of
`design`, `red`, `green` and `refactor` are written after an exit `0`.
