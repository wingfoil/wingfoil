## Context

**Restructuring Memory is a hand edit.** Long-lived projects consolidate their Memory: elements change id, folder
or type when the structure changes.

- **Templates (svc-018 F-036, item 1, seen on 0.3.0, confirmed on 0.3.2):** no verb changes an element's id, path or
  type. `npm run -s wingfoil -- memory move x` → `unknown command 'move'`; `memory rename x` → `unknown command
  'rename'`. A move is a hand edit of the file, its frontmatter and every element that cites it, with no audited
  transition. `dl-187` (adopt, rekey) remaps workflow step provenance only.
- **Benchmark (svc-020 F-035, seen on 0.2):** approved records copied as files into another repository (a scaffold,
  a fixture, a template project) show in `memory history` with no operation and no approver, and no verb keeps their
  approvals or marks them imported. Not reproduced here (design request).

**The vision already names an import.** `docs/01_vision/06_features.md` lists P1.4 `wingfoil memory import` ("scan
project for existing docs and import into Memory"), which no release has built
(`npm run -s wingfoil -- memory --help` lists add, amend, approve, deprecate, history, park, reject, search, submit).

**History already follows a rename made with `git mv`.** `memory history --follow` kept each element's history
across `task-111`'s move of `docs/self/` to `docs/04_memory/` (`bug-075`), so a verb can build on it.

## Decision

Options:
- **(a) Two verb families.**
  - `memory move <id> [--id <new-id>] [--type <type>]`: one commit `wf({type}): move <old> → <new>` that `git mv`s
    the file to the new type's path, rewrites `id` / `type`, rewrites the references to the old id in the elements
    whose declared relation fields cite it (`dl-225`), and lists those it
    cannot rewrite (body prose) without failing. A retype requires the element's state to exist in the target type's
    machine, or `--state <s>` naming one; needs the approver role when the element is past its first state.
    `memory history --follow` reads the move as an entry.
  - `memory import <path…> --from <repository-url>@<sha>`: one commit per imported batch `wf({type}): import <ids>`
    whose trailer paragraph records the source (`WingFoil-Imported-From: <url>@<sha>`); `memory history` reports the
    element as imported, with the source and, when the source history is readable, the source's last approve
    (`Approver:`, sha) rather than a null operation. This is P1.4's verb, narrowed to Memory records.
- **(b) Only `memory move`**; imports stay hand copies, documented as losing their approvals.
- **(c) No change**; document the hand procedure (`git mv`, edit, one commit).

**Recommendation: (a).** Both are the same problem — an element whose file appears without the history that
explains it — and both close with a commit format the history reader understands. (b) leaves P1.4 unbuilt and every
template project's records with a null approver.

## Rationale

- **An audit trail that breaks at a rename is not an audit trail** (P1.2). A verb makes the move itself an entry.
- **Provenance without forgery.** An import records where an approval happened; it never writes an `Approver:`
  line of its own, so it cannot be read as a new approval.
- **Ids stay allocated at commit time** (`git-conventions` §6): `move --id` refuses an id already taken.
