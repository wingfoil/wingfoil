## Context

`agent execute` (`task-218`, W3 B3) resolves every gating read at one commit: `dna.yaml`, `memory.yaml`, the
element, the adapter, the run log's count and the context are read at the `HEAD` that becomes the run's
`state_ref` (`spec-016` §3.2–§3.3, `spec-008` §11's committed-`HEAD` row). Step 11 of the pre-launch pipeline, the
**MCP pre-flight**, does not: it spawns `wingfoil mcp`, completes `initialize`, gets the `{role}-session` Prompt with
`element` and `state` = `state_ref`, and closes. `wingfoil mcp`'s own start-up check reads the working tree's
`dna.yaml` role set (`spec-014` §1, *Pre-flight* item 3: "a `dna.yaml` that cannot be loaded refuses the start").
So an uncommitted change to `dna.yaml` — deleted or invalid — refuses the pre-flight with `MCP_UNREACHABLE`
although every gating read of steps 2–7 passed at `HEAD`.

That is a read able to refuse the command, outside the `command-baseline` directive's read half: "A read that
gates an operation resolves against the repository as committed at `HEAD`". `task-218`'s review raised it (F2);
the approver ruled on 2026-10-09 to keep the behaviour as a **declared exception** and to file this decision-log.
The exception is now written in two places on `main` at `02121a96`:

- `spec-016-agent-execution` §3.3 step 11: "**Declared exception to the `HEAD` baseline:** the server is
  `wingfoil mcp`, whose own start-up check reads the working tree's `dna.yaml` role set (`spec-014` §1)";
- `spec-008-cli-grammar` §11, the committed-`HEAD` row for `agent execute`: "with one declared exception: the MCP
  pre-flight starts `wingfoil mcp`, whose own start-up check reads the working tree's `dna.yaml`".

`task-218`'s Execution Notes (*Review fixes*, F2) record that this is how the `MCP_UNREACHABLE` CLI case is
provoked in its tests: the committed config is whole, the working tree's `dna.yaml` is deleted. Any option that
removes the exception changes that test's set-up. The pre-flight is spawned with `cwd` = the project root
(`mcpPreflight`, `src/agent/execute.ts`), so the server and the pipeline share one repository and differ only in
the baseline they read.

The Prompts channel serves the role set it read at start-up for the server's whole life (`spec-004` §3.1,
`dl-049` (b)); the Prompt's *content* already resolves at `state` (`spec-016` §2.4). Only the role-set read at
start-up is at stake.

## Decision

Open. Three options:

- **(a) The server reads `HEAD`.** `wingfoil mcp`'s start-up reads the role set from `dna.yaml` at `HEAD`, like
  every other gating read. The exception disappears for every client of the server, not only for `agent
  execute`; a user who edits `dna.yaml` and starts an MCP client before committing sees the committed roles.
  `spec-014` §1 item 3 changes, and `dl-049` (b)'s "role set read once at start-up" keeps its shape.
- **(b) The pre-flight passes the run's commit.** `agent execute` starts the server with the run's `state_ref`
  (an option or an environment variable of `wingfoil mcp`), and the server reads the role set at that commit.
  The interactive server keeps today's behaviour; the pre-flight reads exactly what the pipeline read.
  `wingfoil mcp` gains an input it does not have today: `spec-014` §1 gives it no positional arguments
  and no command-specific flags.
- **(c) Keep the declared exception, permanently.** `spec-016` §3.3 step 11 and `spec-008` §11 already state it;
  the `command-baseline` directive gains a sentence naming it as the one exception, so a reviewer meeting it
  does not file it again.

No recommendation is made here: the choice depends on how `task-228` (`backlog`, the launch half of `agent
execute`) passes the MCP configuration to the launched agent, which starts the same server. If the agent's
server must read what the run read, (b) serves both; if the agent is meant to see the live working tree, (c)
holds and (a) would change the interactive server for no gain.

## Rationale

- (a) is the smallest rule ("every gating read is `HEAD`") but changes a long-running server's behaviour for
  every MCP client, which `spec-014` did not ask for.
- (b) aligns the pre-flight with the run's `state_ref` without touching the interactive server, at the cost of a
  new input to a command that has none.
- (c) costs nothing now and is already declared, but leaves one gating read outside the rule, which the
  `command-baseline` directive's history (`dl-080`) shows is how its instances started.
