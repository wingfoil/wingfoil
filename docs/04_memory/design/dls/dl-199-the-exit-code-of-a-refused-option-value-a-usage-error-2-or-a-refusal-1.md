## Context

A `--reason` that WingFoil refuses (blank, or with a line shaped like a trailer) exits 2, the usage-error code, by the declared contract (AGENTS.md §5.1, `dl-067`); a client cannot then tell a malformed command line from a refused value and show the latter as a refusal.

## Decision

Options: **(a)** a refused value exits 1 (a refusal), exit 2 stays for a malformed command line; **(b)** keep 2, documented as the rule for every refused option value.

Recommendation: (b) unless a client contract (MCP Tools, v0.4) needs (a).

## Rationale

Changing an exit code is a contract change for scripts; it is worth it only if a client depends on it.

## Actions

- At v0.4 planning, with the MCP Tools scope: rule.
- Source: a consumer note (`reported_by:`), restated; the behaviour is reproduced by the consumer and declared in AGENTS.md §5.1.
