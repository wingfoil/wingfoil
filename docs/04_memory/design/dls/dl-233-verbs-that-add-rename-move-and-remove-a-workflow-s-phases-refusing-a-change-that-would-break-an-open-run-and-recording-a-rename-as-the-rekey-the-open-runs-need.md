## Context

**Editing a workflow's phases is a hand edit of its YAML.** UI (svc-019 F-008, seen on 0.2.2, still unfiled) wants a
client to edit workflows, with protection for runs already in progress, after v1.0.

**What 0.3.2 offers** (`npm run -s wingfoil -- workflow --help`): `create` (a custom workflow with one phase) and
`remove` (refused when another workflow includes it or an open workflow runs it) work on whole workflows; `rekey`
(approver only, `dl-187`) remaps an open run's records from a renamed step key to its new one. Nothing adds, renames,
moves or removes a phase, and nothing stops a hand edit from removing a phase an open run has completed or is in.

## Decision

Options:
- **(a) A `workflow phase` family:** `workflow phase add <workflow> <phase> [--after <phase>] [--role …]`,
  `rename <workflow> <from> <to>`, `move <workflow> <phase> --after <phase>`, `remove <workflow> <phase>`, each one
  `wf(workflow): …` commit of the workflow file. Rules: `remove` and `move` refuse a phase that an open run has
  completed or is in (named in the refusal, from the deduction of `spec-017`); `rename` writes the edit and, for every
  open run, the `workflow rekey` record in the same command (approver role, as `rekey` requires); `add` affects only
  the phases open runs have not reached. The workflow file's `version:` is raised per `doc-versioning`.
- **(b) A check only:** `workflow list` warns when the committed definition no longer matches an open run's records;
  edits stay manual.
- **(c) No change.**

**Recommendation: (a), scheduled after v1.0.** It builds on what exists (`rekey` already defines how a rename reaches
open runs; the deduction already knows which phases each run has completed) and turns a hand edit that can corrupt
a run's state into a refused command.

## Rationale

- **A run's state is deduced from its definition** (P4.13); changing the definition under it changes the answer.
  The verb is where that can be checked.
- **Configuration changes keep their own scope** (`wf(workflow): …`), separate from Memory operations.
