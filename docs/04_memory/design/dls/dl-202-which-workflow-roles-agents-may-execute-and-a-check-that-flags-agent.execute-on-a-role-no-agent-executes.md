## Context

`retrospective.yaml` 1.6 gives its two agentic phases, `explore` and `collect-feedback`, the action `agent.execute` under role `facilitator` (lines 32–34, 60–62). The only `team.agents` entry (`Claude`, adapter `claude-code`, `.wingfoil/dna.yaml:142–146`) has `executes_as: [ developer, reviewer, qa, architect ]`, so `wingfoil agent execute --element decision-log:retro-v0.3 --role facilitator --dry-run` refuses: `error: no agent in dna.yaml with an adapter executes as role 'facilitator'` (`selectAgent`, `src/agent/execute.ts:279–289`). Nothing reports the mismatch before someone tries to launch: `workflow list` accepts the phase. The v0.3 retrospective's mining therefore ran as read-only sub-agents of the facilitator's session (`retrospective-rel-v0.3-plan`, S1 addendum). Two concurrent causes are tracked elsewhere: the interactive launch, and its `--dry-run`, need a terminal (`bug-392`); the pinned build 0.2.2 has no `agent` command (moved by patch-v0.3.1's pin to 0.3.0).

## Decision

1. **Which roles agents may execute** is declared per role, not inferred: the roles that stay human-only are named (at least `approver`, which `dl-094` and AGENTS.md §4 reserve; and the roles the project marks so, today `product-owner` and `tech-lead`), and every other role may appear in a `team.agents` entry's `executes_as`.
2. **A configuration check** (in the workflow validation that `workflow list` runs, a warning `W_WORKFLOW_AGENT_ROLE_UNEXECUTED` or similar): a phase whose `actions` contain `agent.execute` under a role that no `team.agents` entry with an `adapter` executes is reported, naming the phase and the role.
3. **This repository, as a quick fix in patch-v0.3.1:** `facilitator` is added to the `Claude` entry's `executes_as` (`wf(dna): update …`), its role directives (`traceability`, plus the globals) loaded as for any role.

Options considered: (b) giving the retrospective's phases a role the agent already executes (`architect`, `reviewer`) — rejected, the facilitator's role and directives are the right ones for mining and synthesis; (a) alone, with no check — rejected, the same mismatch would recur silently in other workflows and in adopters' projects.

## Rationale

A workflow that declares an agent action no agent can run is a configuration defect discovered only at launch; a check makes it visible where the configuration is read, and the human-only list keeps approval authority where `dl-094` puts it.
