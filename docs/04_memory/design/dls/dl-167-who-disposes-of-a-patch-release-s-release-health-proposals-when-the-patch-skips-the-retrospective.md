## Context

`release-cycle.yaml` 1.4 (`task-222`, `dl-089` §1) runs `release-health` between `release-publishing` and
`retrospective`: it measures the release, compares it with the previous run, and turns each regression or breached
floor into an improvement proposal `RH-{release.version}-NN` that "the retrospective disposes of" (`release-cycle.yaml`,
phase `release-health`, description; `release-health.yaml`: "The proposals are input to the retrospective's …").

`dl-092-tracking-a-patch-after-its-minor-is-released` (`ready`) ruled Q2 (ii): "a patch runs every release-cycle phase
except the retrospective" (approve `864d8bdf`, Reason), whose findings fold into the next minor's retrospective. So a
patch runs `release-health` and produces proposals that no phase of its own cycle disposes of. `task-222`'s independent
review raised it ("patch release RH proposals have no disposer (needs ruling)"); the W3 B4 triage (2026-10-10) filed it
as this decision-log.

## Decision

**Q1 — who disposes of a patch's RH proposals:**
- **(a) the next minor's retrospective**, as `dl-092` Q2 (ii) already does for the patch's other findings: the
  retrospective's `explore` reads every `release-health` report since the previous retrospective, patches included,
  and disposes of each proposal with the six outcomes `retrospective.yaml` 1.4 lists.
- **(b) a short disposal phase in the patch's own cycle** (product-owner or approver), run only when the patch's
  report holds proposals, writing the same outcomes; the retrospective stays skipped.
- **(c) a patch skips `release-health` too**, and the next minor's run compares against the last minor; the patch's
  window is folded into it.

**Recommendation: (a).** It keeps `dl-092`'s ruling whole (the patch's findings fold forward), needs one sentence in
`retrospective.yaml`'s `explore` and a selection over the reports, and loses no measurement. (b) adds a phase for
what is usually an empty list; (c) gives up the per-release history `dl-089` wants (its D01 already reports
`not-comparable` for patches).

## Rationale

- An RH proposal no step disposes of is the "proposal never disposed" case `retrospective.yaml` 1.4 was written to
  stop (`task-213`: `proposals.disposed` with six outcomes).
- The choice is real: (b) and (c) are each coherent, with different costs in phases and in measurement.

## Actions

1. Ratify Q1. Owner: approver, at v0.4 `release-planning`'s `reconcile-governance`.
2. Under (a): `retrospective.yaml`'s `explore` names the `release-health` reports of the patches since the previous
   retrospective; under (b) or (c), `release-cycle.yaml` changes accordingly. One task at v0.4 `build-backlog`.
3. A dated note on `dl-089` and `dl-092` records the ruling.
