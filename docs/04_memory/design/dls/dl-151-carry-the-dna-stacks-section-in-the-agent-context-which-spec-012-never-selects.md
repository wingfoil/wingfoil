## Context

`spec-012` §4 selects the DNA an agent's context carries: `project` and `team` always, the `modules` the element
selects, and `paths` whole. It does not select **`stacks`**, the section `spec-002` defines for the project's
technologies and methodologies (`[SPEC: P2.4]`), so an agent executing a task never sees from WingFoil what
language, runtime, test framework or methods the project uses. `task-176` (`done`, W2 B1) implemented §4 as
written: `DnaSelection` has `project`, `modules`, `team`, `paths` (`src/core/context.ts:220-227`), and
`grep -n stacks src/core/context.ts` finds nothing.

Facts read on `main` at `0b297169`:

- `dna.yaml`'s top-level keys are `version, project, modules, stacks, team, paths`; `stacks` lists 12
  technologies and 5 methodologies. Dumped as §7 does (`sortKeys`, no folding), it is **1 309 bytes**: the
  `task-218` context measured for the companion decision-log on §7's byte format is 315 167 bytes.
- P2.4 defines DNA as the project anatomy "(modules, tech stack, team members, conventions)"
  (`docs/01_vision/06_features.md:50`); P5.4.3 and P5.4.4 say the agent receives "DNA" without naming sections.
  `conventions` became directives (`spec-002` v1.1), which §5 loads; the tech stack has no such second route.
- Directives may mention the stack in prose (this repository's `testing` directive names Jest), but that is per
  project and per directive, not the declared source.
- §4 has been revised in place three times (Revision notes of 2026-10-05), so the spec change itself is cheap.
  What is not cheap is the payload: once `task-218` (`agent execute`) and `task-195` (the `{role}-session`
  Prompt) consume it, adding a section changes every payload's bytes, i.e. the format the Determinism Index
  compares. The finding said this "needs a superseding spec"; the precedent is an in-place revision, and the
  cost is the format change, not the spec procedure.

## Decision

The open question is whether the agent context carries the project's stack. Options:

- **(A) Always include `stacks`**, whole, in `dna.yaml`'s declared order (between `modules` and `team`, as the
  file declares it). Simple, deterministic, ~1.3 KB here.
- **(B) Include `stacks.technologies` only.** Methodologies (Lean Inception, BDD, TDD…) reach the agent through
  directives where they bind behaviour; the technologies are what the agent cannot infer safely.
- **(C) Do not include it.** The agent reads the repository (`package.json`, lockfiles) and the directives; the
  DNA stays out of the stack.

**Recommendation: (A)**, ruled now and implemented together with the §7 byte-format decision, so the payload
changes once, before its first consumer: the stack is declared DNA (`spec-002`, P2.4), the North Star asks that
two agents work from the same declared inputs rather than from what each infers from the tree, and the cost is
small and bounded by the file.

## Rationale

- (C) makes two agents infer the stack independently, which is the non-determinism the declared DNA exists to
  remove; it also leaves P2.4's "tech stack" with no reader in the agent path.
- (B) splits one `spec-002` section by a judgement about which half matters; methodologies are short, and a
  reviewer agent checking BDD/TDD conformance benefits from seeing them declared.
- Deciding after `task-218`/`task-195` ship would make the addition a payload format change for every consumer.
