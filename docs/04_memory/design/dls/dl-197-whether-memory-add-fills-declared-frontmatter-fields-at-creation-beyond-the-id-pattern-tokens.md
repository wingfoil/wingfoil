## Context

`memory add --set <name>=<value>` fills only the tokens of a type's `id_pattern` or path; a declared frontmatter field (required or not) cannot be given at creation: `memory add --type bug --title x --set severity=low` → `error: --set severity: memory type 'bug' has no token {severity} in its id_pattern or path` (0.3.0 code build, 2026-10-21). Two consumers report it.

## Decision

Options: **(a)** `--set` also fills a field the type's template declares (still refusing an undeclared one), recorded in the add commit; **(b)** a separate `--field <name>=<value>` option; **(c)** no change: fields are written before `submit`.

Recommendation: (b): `--set`'s meaning (an id token) stays exact.

## Rationale

A field known at creation has to be written by hand between add and submit, the step where hand edits drift.
