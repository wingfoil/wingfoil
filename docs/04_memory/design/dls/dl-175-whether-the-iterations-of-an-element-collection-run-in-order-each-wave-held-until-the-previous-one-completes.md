## Context

`task-230` made `release-cycle`'s implementation phase iterate over the release's waves (`iterate_over:
element:waves`, `sed -n 45,46p .wingfoil/workflows/custom/release-cycle.yaml`) and included `wave.yaml` there. Every
listed wave is open at once: `spec-017` says nothing makes a later wave wait for an earlier one, and a project that
wants waves in sequence lists only the waves to open now and appends the next at the previous one's re-plan
(`sed -n 328,332p docs/04_memory/design/specs/spec-017-*.md`, "A sequential `element:` iteration is not
specified here"). `task-230`'s independent review (finding F3, option (b)) asked whether the iteration itself should
run in order.

## Decision

Choose one:

- **(a) keep it as is.** Order is expressed by what the release lists in `waves:`; the re-plan appends the next wave.
- **(b) an ordered iteration.** `spec-003` gains a key on `iterate_over` (e.g. `order: sequential`) under which entry
  n+1 is eligible only once entry n is complete; deduction enforces it.

**Recommendation: (a) for v0.4**, revisited if a project needs more than one wave listed and held: (a) needs no
specification change and the re-plan already is the checkpoint `dl-100` §1 asks for.

## Rationale

- (b) adds a rule to `spec-003`'s iteration semantics and to every deduction reader; (a) keeps the order in data a
  person can read in the release.
