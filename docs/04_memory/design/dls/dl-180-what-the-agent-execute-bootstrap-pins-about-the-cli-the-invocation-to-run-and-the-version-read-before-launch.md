## Context

`agent execute` (`spec-016`) launches an agent CLI with a bootstrap (§2.4) and records the run (§4.2). Two by-hand
passes of the built-in adapters on 2026-10-14 showed that the bootstrap and the launch pin less about the CLI than the
run needs:

- **Which CLI the agent runs.** The bootstrap names the role, the element, the context served by the `wingfoil` MCP
  server and the attribution line, but no CLI invocation (`sed -n 190,197p
  docs/04_memory/design/specs/spec-016-*.md`, `main` at `bd55f70e`). In `task-237`'s pass the `codex-cli` agent ran
  the global `wingfoil` on `PATH` (the published 0.2.2) for its Memory operations, while its context came from the
  build under test (§2.5 registers the running build as the MCP server): `bug-369`.
- **Which version of the agent CLI ran.** `version_args` is read after the run (§3.3 step 16; `src/agent/launch.ts`
  lines 283-290). In `task-236`'s pass Claude Code updated itself from `2.1.296` to `2.1.299` during the session, and
  the record says `2.1.299 (Claude Code)` although the session ran `2.1.296`: `bug-366`.

Both are one question: what `agent execute` fixes before launch, so the run uses and records what was checked.

## Decision

For each half, choose:

- **CLI invocation:** (a) the bootstrap names the exact invocation of the build under test (`node <that build's
  dist/cli.js>`, or the project's declared command); (b) `agent execute` puts that build first on the agent's `PATH`
  (a temporary `wingfoil` shim), so a plain `wingfoil` is the build under test; (c) both.
- **Agent CLI version:** (a) `version_args` is read before launch and recorded; (b) read before and after, both
  recorded, a difference flagged in the record and as a warning; (c) as today (after the run only).

**Recommendation:** CLI invocation (c), so a pasted command and a plain `wingfoil` both reach the build under test;
version (b), since a self-updating CLI makes `verified_with` a moving target and the record should show it.

## Rationale

- A run whose context and whose Memory operations come from different builds cannot be reproduced from its record,
  which the Determinism Index needs.
- Reading the version only after the run records the version the CLI updated to, not the one that ran.
