## Context

`scripts/test-report.cjs` (`task-244`, `dl-136` Q4 (a)) classifies every test file of the published results into
`unit`, `integration`, `BDD`, `smoke`, `API-docs` or `lint.clean`. A file is `BDD` when its leading block comment
cites a `.feature` file of `docs/02_requirements/02_bdd/features/` in any spelling, full path, relative path or bare
file name (`sed -n 11,13p scripts/test-report.cjs`; `FEATURE_CITATION` at line 41, applied at line 83), as the
approver ruled at `task-244`'s review.

The rule makes some classifications arguable, because a header may cite a feature for traceability without the file
being an acceptance test of it. `task-244`'s re-review named four, each classified `BDD` on `main` at `bd55f70e`
(the `.feature` names their leading comments cite):

- `test/core/builtin-asset.test.ts` (`P3.3-directive-remove.feature`, `P4.9-workflow-remove.feature`): strings
  asserted by a P3.3 feature;
- `test/release-health/measure.test.ts` (`P1.2-versioning-audit-trail.feature`): REQ-STATE-10 scenarios;
- `test/docs/bdd-dna-sections.test.ts` (`P2.4-project-dna-config.feature`): a parity test between the feature and
  the DNA documentation;
- `test/core/query-latency.test.ts` (`P1.5-memory-search.feature`, `P1.10-memory-history.feature`): the BDD's latency
  clauses.

## Decision

Choose one:

- **(a) A declared marker.** A test file is `BDD` only when its leading comment carries a declared tag (for example a
  line `BDD: <feature file>` naming the scenarios it executes); any other `.feature` citation is traceability only.
  `test-report.cjs` reads the tag, and a test checks that every tag names an existing feature.
- **(b) As today.** Any `.feature` citation in the leading comment, with the arguable cases accepted as `BDD`.

**Recommendation: (a).** The published counts say how many acceptance tests ran; a rule that counts a parity check or
a latency test as BDD because its header cites a feature for traceability makes the count depend on how comments are
written.

## Rationale

- A declared marker makes the classification an explicit, checked declaration (REQ-SYS-07's preference for declared
  configuration over inferred behaviour), and leaves headers free to cite features for traceability.
- (b) costs nothing now, and the four files are a small share of the suite.

## Actions

1. Ratify a choice, or reject to `draft`. Owner: approver.
2. Under (a), one task adds the tag to the files that execute scenarios, changes `test-report.cjs` and its test, and
   states the rule in the `testing` directive.
