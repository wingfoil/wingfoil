## Context

`dl-032` (`ready`) fixed the illegal-transition message as
`illegal transition <from> -> <to> for type '<type>'` (REQ-STATE-01). A transition verb names no target of its
own, and an **illegal** call has, by definition, no legal edge from `<from>`, so `<to>` needs a rule.
`dl-053` (`ready`, option 1) chose the verb's **canonical edge**: the target the verb reaches from the first state,
in `sequence` order, from which it is legal (`contractTarget`, `task-045`).

That rule prints edges that do not exist from `<from>`. `bug-165`: `approve` on a `planned` bug reads
`planned -> triaged` (backward) and on `triaged` reads `triaged -> resolved` (skipping three states); `bug-127`
adds the end of the chain, a gate whose forward edge needs `approve`, and custom machines. The reason line under
the message (task-130's details, on CLI and MCP) already says why the call is refused; the first line is what
BDD pins and what `docs/agents.md` §6 tells agents to read, and it names a wrong move.

## Options

- **(A)** `<to>` is always `(none)`: a refused call has no legal target from `<from>`, so `(none)` is the only
  true target. The reason line is unchanged.
- **(B)** keep the canonical edge and reword only the reason line: the first line still prints the defect.
- **(C)** print the literal attempted move (e.g. `planned -> in-progress`): it names a waiting edge no verb can
  take, which `dl-053` already ruled out.
- **(D)** drop `<to>`: it reopens `dl-032` and the REQ-STATE-01 message format.

## Decision

**(A).** Every refused transition prints `illegal transition <from> -> (none) for type '<type>'`, on every verb
(`submit`, `approve`, `reject`, `park`) and on every machine; the reason line that follows names the verb, the
state and the cause, unchanged. `(none)` was already a token the contract printed (`dl-053`'s "legal nowhere"
case), so the message shape of `dl-032` is kept.

This replaces `dl-053`'s option 1, which is deprecated with a `Reason:` naming this decision-log.

## Rationale

- **True by construction.** The message's first line must not name a move that does not exist; `(none)` is the
  only target that is true for every refusal.
- **One string, not a rule to explain.** The canonical-edge rule needed a self-loop refinement and still printed
  backward and skipping edges; `(none)` needs neither.
- **The why already has a home.** Since `task-130` the details reach the operator on CLI and MCP, so the
  first line no longer has to carry a hint.
