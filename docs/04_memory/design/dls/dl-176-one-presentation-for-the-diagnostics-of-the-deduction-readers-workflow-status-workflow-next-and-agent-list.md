## Context

The commands that read a workflow deduction report its diagnostics in two different ways. `workflow status` and
`workflow next` print a count line on stdout (and the diagnostics in their JSON), while `agent list` (`task-240`)
writes each diagnostic as a `warning:` line on stderr. `task-240`'s independent review (W3 B6) asked for one rule.

Evidence on `main` at `0da232cb`: `sed -n 198p src/core/workflow-status.ts` → `${result.diagnostics.length}
diagnostic(s): --format json lists them`, a line of the human output on stdout (the same at `src/core/workflow-next.ts:663`); `sed -n 79p src/core/agent-list.ts`
and `sed -n 236p src/core/agent-list.ts` → `agent list`'s diagnostics "print on stderr as `warning:` lines".

## Decision

Choose one:

- **(a) stderr for every diagnostic.** Each reader writes one `warning:`/`error:` line per diagnostic on stderr, as
  `agent list` does; stdout carries only the answer, and `--format json` carries the diagnostics in its envelope.
- **(b) a count line on stdout.** Each reader prints a count line with the answer and the full list only in JSON or
  under a flag.

**Recommendation: (a).** It matches `spec-008`'s rule that stdout is the answer a script reads, and a count with no
detail sends the reader to a second command.

## Rationale

- One presentation lets a script and a person read every deduction reader the same way; today a pipeline must know
  which command it runs to find the diagnostics.
