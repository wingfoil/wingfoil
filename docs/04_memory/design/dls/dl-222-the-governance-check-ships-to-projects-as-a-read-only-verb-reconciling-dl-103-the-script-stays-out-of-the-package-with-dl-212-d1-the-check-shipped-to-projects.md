## Context

**Two ratified-or-pending decisions disagree.** `dl-103` (`ready`, v0.3) puts a governance check over `wf()` commits
outside the agent, on every push; its Actions say to amend `spec-015` "if the script ships in the package; it should
not", and `scripts/check-governance.cjs` says in its header that it is not shipped (`package.json` `files`:
`dist`, `README.md`). `dl-212` (`in-discussion`, v0.4) D1 assumes "the governance check shipped to projects"
flags an approval commit that carries an agent trailer.

**A consumer needs it.** The WingFoil UI shows that a hand-committed `status:` change with a CLI-shaped subject is
read as the new state and that `memory history` reports a forged approval as genuine (reproduced on 0.3.2; the bug
filed from the same row). WingFoil's own repository is protected by the script in CI and by the pre-push hook; a
project that installs WingFoil has nothing to run in its CI or before a merge.

## Decision

Options:
- **(a) A shipped read-only verb**, for example `wingfoil check governance [<range>]`: the authority and state rules
  of `dl-103` §1 (and `dl-212` D1's agent-trailer rule), exit 1 on a finding, `--format json`; WingFoil's own
  CI and pre-push hook call the verb, and the repository-only rules (this repository's `git-conventions` §7/§9
  specifics) stay in the script as an extension.
- **(b) Ship the script as a separate bin** in the package, unchanged.
- **(c) Keep it repository-only** and amend `dl-212` D1 to drop the shipped check.

**Recommendation: (a).** The rules are WingFoil's contract for any governed project, not this repository's; a verb puts
them under the CLI's grammar, exit codes and tests (`spec-008`), and `dl-212` D1 then has the vehicle it assumes. The
reason `dl-103` kept the script out — it encoded this repository's conventions — is met by splitting the generic rules
from the repository's own. (b) ships an unversioned interface; (c) leaves every consumer without a check.

## Rationale

- **State lives in frontmatter**, so the only defence against a forged transition is a reader that checks the commit
  history; it must be available where the history is.
- **One implementation**: WingFoil's CI running the shipped verb dogfoods it.
- **`memory history`'s unverified mark** (the bug filed with this) and the verb share the same checks.
