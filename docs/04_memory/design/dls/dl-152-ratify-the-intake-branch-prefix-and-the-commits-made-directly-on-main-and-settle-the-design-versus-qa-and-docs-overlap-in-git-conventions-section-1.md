## Context

`git-conventions` §1 (`task-178`, from `dl-024` rule 1 as amended by `dl-119` Q1 (b)) says a `dev-loop` task runs
on `task/<task-id>` and a workflow phase on its own branch, that both merge into `main` with `git merge --no-ff`,
"never fast-forward", and that a branch name takes one prefix from a **closed list** (`task/`, `design/`,
`ingest/`, `fix/`, `docs/`, `qa/`, `backlog/`), "an unlisted prefix is a deviation to fix, not a new convention".
The practice that keeps this repository's Memory current does not fit that text, and the `task-178` review
(F3, F4) and the approver's ruling 4 (b) at the W2 B2 gate asked for a decision rather than a silent exception.

  --format=%s | wc -l` → **376**, against 52 `--no-ff` merges in the same window (49 `task/`, 2 `fix/`,
  1 `ingest/`). Of the 376, 364 are `wf()` Memory operations: 68 `approve`/`reject` (the approver's decisions),

## Decision

Three questions, each with options.

**Q1 — commits made directly on `main`.**

- **(A) Ratify a closed list of on-main operations**: the approver's `approve`/`reject` and the triage
  mechanics that follow them (`assign`, `sync`, the absorbing tasks' `amend`), and the coordinator's
  `docs(plans)` bookkeeping of a plan already merged. Everything else (captures, new elements, content)
  goes through a branch.
- **(B) Every commit through a branch**, Memory operations included (a short-lived `backlog/` or `ingest/`
  branch per batch of approvals).
- **(C) Leave §1 as written** and treat the practice as a standing deviation.

**Q2 — the intake session.**

- **(a) Add `intake/` to the closed list**, meaning "a capture-only session that files elements, never code",
  and allow it to reach `main` by fast-forward, because its commits are themselves the record (one `wf()`
  operation each) and a merge commit adds nothing to them.
- **(b) Fold it into `ingest/`** (it is an ingest in all but name) and merge it `--no-ff` like the others.

**Q3 — `design/` against `qa/`/`docs/`.**

- **(i) The specific prefix wins**: `qa/` for a quality-gate phase (`e2e-smoke`), `docs/` for a
  documentation phase (`user-docs`), `design/` for every other lifecycle phase; the table says so.
- **(ii) `design/` for every lifecycle phase**; `qa/` and `docs/` only for changes outside a phase.

**Recommendation: Q1 (A), Q2 (a), Q3 (i).**

## Rationale

- Q1 (A) matches what the audit trail needs: an approval or a triage step is one `wf()` commit whose subject,
  `Approver:` and `Reason:` are the record (P1.7, P1.10), and wrapping each in a branch and a merge commit
  doubles the history without adding information. (B) adds a branch and a merge commit for every batch of
  the 364 Memory operations counted above. (C) teaches agents that a "closed" list is not closed, which is the drift the directive was
  written to stop.
- Q2 (a) names what the session is; (b) would make the closed list describe the practice by changing the
  practice, at the cost of a merge commit per intake batch. Allowing the fast-forward is safe for the same
  reason as Q1: each commit is already one Memory operation.
- Q3 (i) is what the history already does (four merges, all with the specific prefix) and keeps the prefix
  informative.
