## Context

WingFoil's listings print every record in full. In a project made with `wingfoil init --template Kanban`,
`wingfoil directives list | wc -lc` prints 205 lines and 4 549 characters on 0.3.2 (the ten scaffolded directives,
each with its whole frontmatter); `wingfoil memory search` prints several lines per match (path, id, title, type,
status, tags). A coding agent keeps each command's output in its context, and every later model call of the session
reads it again, so a listing printed once early is paid for at every call after it; agents following a WingFoil
workflow call these listings repeatedly (which directives apply, which documents wait at a gate). The Benchmark
consumer measured it and asks for a compact default. No element sets one: `dl-043` (in-discussion, v0.4) decides how
`--format console` renders, not how much a listing carries; `dl-209` (ready, v0.4) a short session context; `dl-211`
(ready, v0.4) a compact cheat-sheet view; `dl-147` (ready) the process cost.

## Decision

- **(A) Compact by default, full on request.** `directives list` and `memory search` (and `workflow list`,
  `agent list`) print one line per record — for a directive: id, title, the roles it applies to; for a match: id,
  status, title — and `--full` (or a `show` verb for one record) prints today's record. `--format json` follows the
  same choice, so a script that needs every field passes `--full`.
- **(B) Compact console, full JSON.** The one-line view is the `--format console` rendering `dl-043` defines; JSON
  stays complete. Agents that read JSON keep paying the full cost.
- **(C) No change to defaults; add `--compact`.** Every listing keeps its output; agents and the generated agent files
  (`dl-143`, `dl-209`) are told to pass `--compact`.

**Recommendation: (A)**, decided with `dl-043` so the console rendering and the default weight are one design. The
cost is paid by default, so only a default removes it; (C) relies on every agent being told, and (B) leaves the JSON
an agent most often reads unchanged. A `directive show <name>` verb, which 0.3.2 lacks, gives the full record of one
directive.

## Rationale

Every line a listing saves is saved once for every later call of the session. The full record stays one option away,
so nothing a reader needs is removed; the change is breaking for scripts that read today's JSON, which is why the
CHANGELOG's upgrade list must name it and the release that ships it must be a minor.

## Actions

1. Fix the compact fields per listing and the `--full` option in `spec-008` (CLI grammar), together with `dl-043`'s
   console rendering.
2. Add `directive show <name>`.
3. Update `docs/cli-reference.md`, `docs/agents.md` and the MCP Resources if they mirror the listings, and name the
   change under "Upgrading from …" in the CHANGELOG.
