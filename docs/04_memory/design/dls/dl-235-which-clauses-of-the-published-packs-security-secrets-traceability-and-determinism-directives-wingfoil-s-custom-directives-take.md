## Context

The design of `task-351` (adopt the published software template packs by hand, minor-v0.4) compared every file of
the packs, read from the git tags of the public templates repository, with its counterpart under `.wingfoil/`. Three
of WingFoil's custom directives lack clauses the packs state (the design's table, rows 7, 8 and 23):

- `security-secrets` (pack `base` 2.0.1): a leaked credential is revoked first, then removed; no personal email or
  postal address in a repository file.
- `traceability` (pack `base` 2.0.1): a rule taken from another project's element cites that element's id.
- `determinism` (pack `software` 1.0.0): sort what is written out; pin what the build reads; a test that passes or
  fails without a change is never retried; the reviewer checks these rules.

Writing them into the custom directives is a rule for all future work, which the `traceability` directive's filing
rule sends through a decision-log first (`dl-118` (B)). The approver ruled so at the design gate of `task-351` (D5
(a)): the clauses are weighed here, not in that task. The question matters beyond `task-351`: once the packs are
installed (`dl-186` S5), a custom directive with the same id shadows the pack's, so a clause WingFoil has not weighed
would be dropped silently.

Two of the clauses meet an existing WingFoil rule:

- "no personal email" meets the identity WingFoil records on purpose: the `Approver:` line of every approval
  (`P1.7`), the git author, and `dna.yaml` `team`.
- "never retried" meets this repository's practice of re-running a wall-clock assertion alone before calling a gate
  failure real, recorded in the execution notes of `task-147`, `task-150`, `task-196` and `task-212`.

## Decision

Each clause is decided on its own. The options:

- **C1, security-secrets: revoke first, then remove.** (a) Adopt as stated. (b) Leave it to the pack.
- **C2, security-secrets: no personal email or postal address.** (a) Adopt for document and fixture content. The
  identity lines WingFoil records by design stay exempt: `Approver:` lines, git author and committer, `dna.yaml`
  `team`. (b) Adopt as stated, which would forbid the approval record. (c) Leave it to the pack.
- **C3, traceability: cite the source element of a borrowed rule.** (a) Adopt, with the citation a public permalink
  so the reference resolves (`documentation` D2, resolvable references). (b) Leave it to the pack.
- **C4, determinism: sort what is written out.** (a) Adopt as stated: it states for output what `REQ-SYS-07`
  already requires of iteration. (b) Leave it to the pack.
- **C5, determinism: pin what the build reads.** (a) Adopt as stated (the lockfile, the pinned build of `dl-095`).
  (b) Leave it to the pack.
- **C6, determinism: a test that passes or fails without a change is never retried.**
  - (a) Adopt as stated, and drop the practice of re-running alone.
  - (b) Adopt with one exception. A single re-run of the failing test alone is a diagnosis, never a pass. A failure
    that passes alone is filed as a bug and is not recorded as a green gate.
  - (c) Leave it to the pack.
- **C7, determinism: the reviewer checks these rules.** (a) Adopt as stated. `roles.yaml` already binds
  `determinism` to the reviewer, so the clause states what the binding implies. (b) Leave it to the pack.

Recommended: C1 (a), C2 (a), C3 (a), C4 (a), C5 (a), C6 (b), C7 (a).

## Rationale

- **No silent loss.** A clause left to the pack is lost once WingFoil's same-id custom directive shadows it, so "leave
  it to the pack" means dropping it. Adopting each clause WingFoil agrees with keeps the custom directive a superset.
- **C2 (a) keeps the approval record.** The identity in an `Approver:` line is the evidence `P1.7` requires.
- **C3 (a) keeps references resolvable.** A citation that names a private or absent element would break the rule
  that repository documents never point where a reader cannot follow.
- **C6 (b) keeps the diagnosis but removes the escape.** A wall-clock assertion that fails under load is information
  about the test, not about the change. Re-running it alone separates the two, and filing it as a bug stops the re-run
  from turning a failure into a pass.
