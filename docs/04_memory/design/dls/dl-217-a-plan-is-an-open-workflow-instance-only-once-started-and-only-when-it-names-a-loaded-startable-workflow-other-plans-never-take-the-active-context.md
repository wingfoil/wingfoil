## Context

**Two kinds of plan silently take over the active instance** (spec-017 §3.3: the most recently started open instance
is the active one, and `workflow next`, `status` and `finalize` default to it). Both reproduced on 0.3.2 in scratch
repositories (`git init`, `wingfoil init --template Scrum --no-interactive`):

1. **A plan naming no loaded workflow** (a plan kept for ad-hoc work, such as a migration). With a run open
   (`wingfoil workflow start sw-life-cycle`), `wingfoil memory add --type plan --set workflow=adhoc …` and
   `memory submit` it; `wingfoil workflow status --format json` → `active` is the ad-hoc plan, with a
   `W_INSTANCE_WORKFLOW_UNKNOWN` warning; `wingfoil workflow next` answers for it ("workflow 'adhoc' is not loaded")
   instead of the real run.
2. **A plan merely added, still `draft`, naming a loaded main workflow.** With a run open, `wingfoil memory add --type
   plan --set workflow=sw-life-cycle …` (not started, not submitted); `wingfoil workflow status --format json` →
   `active` is the draft plan, no diagnostic; `wingfoil workflow next` answers for it.

**This is the specification working as written.** spec-017 §3.2 counts a plan as open when its status is `draft` or
`active` and ignores only a plan whose workflow is not startable or whose `parent` is set; §2 lists a plan naming a
workflow the registry does not load, with an empty frontier, rather than ignoring it; §3.3 makes no exception for
either. So the fix is an amendment of spec-017 §3.1–§3.3, not a defect fix. A plan type has no way to say "this plan
records work outside any workflow".

## Decision

Options:
- **(a) Only started plans are instances.** A plan is an open instance when it names a loaded startable workflow and
  its add commit was written by `workflow start` (or it carries an explicit instance marker that `start` writes);
  a plan added by `memory add` is never an instance, whatever it names, and a plan naming an unloaded workflow is
  ignored for the active context (still reported by `workflow list` as a warning). A phase plan stays as today
  (§3.2, `parent` set).
- **(b) Keep the rules, add diagnostics and a declaration.** A draft plan stays open but does not become active until
  submitted; a plan may declare `workflow: none` (or an `adhoc: true` field) to stay out of instance deduction;
  `workflow status` warns when the active instance changes because of a plan not opened by `start`.
- **(c) No change**; projects pass the instance ref to every command while such a plan is open.

**Recommendation: (a).** An instance is an act (`workflow start`), not a document's content; tying it to the start
commit makes the active context predictable and removes both cases at once. (b) keeps a document still being written
able to move the running context, and adds a field every project must learn; (c) leaves every tool that reads the
active instance showing the wrong run.

## Rationale

- **Determinism of the context.** The active instance decides what `workflow next` says; it must not change because
  someone saved a draft or recorded ad-hoc work.
- **The start commit already exists** as the instance's anchor (§3.3 orders by it), so (a) adds a condition on an
  existing record rather than a new store.
