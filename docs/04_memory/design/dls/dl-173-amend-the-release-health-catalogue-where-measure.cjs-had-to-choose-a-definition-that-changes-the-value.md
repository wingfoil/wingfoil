## Context

`task-231` wrote the history half of `release-health.measure` (`scripts/release-health/measure.cjs`). Where the
catalogue (`docs/08_health/metrics.yaml`, `dl-089`) leaves a choice, the script fixes one and lists it in its header
("Definitions this script fixes where the catalogue leaves a choice", `sed -n 38,72p
scripts/release-health/measure.cjs`). `task-231`'s independent review (finding D3) found five of those choices that
change a metric's value, not only its presentation, so they belong in the catalogue rather than in a script comment:

1. **G08 (AI attribution conformance), the start point.** The script judges commits after the `dl-117` ratification
   commit (`before_rule` counts the earlier ones apart). The conforming trailer form (`team.agents` name and email,
   plus `AI-Model:`) arrived only with `task-256` (`git-conventions` §7, `dl-158`), so every release measured with a
   window between the two scores 0 % by construction: the review's run at `v0.2.2` gave `conforming_share` 0 over 346
   judged commits, each carrying the then-practised model-named trailer.
2. **G09 (verbs outside the declared grammar), the grammar.** The verb list is `MEMORY_OPERATIONS` read from
   `src/memory/audit.ts` at the measurement point, and the measuring build's list when that file is absent there, so a
   historical point can be measured against a grammar it never had (the `v0.2.2` run: `verbs_from: "the measuring
   build"`, 4 of 306 outside).
3. **G15 (stale branches, duplicate ids), the refs.** It reads the live `refs/heads` and `refs/remotes` of the clone
   that runs it, so the same point answers differently later (`sed -n 29,31p scripts/release-health/measure.cjs`:
   "G15 is not reproducible at a fixed point"), which `dl-089` §1's "measured at the point" does not allow.
4. **P02 and P05 (illegal transitions, approval authority), the unchecked items.** A commit made before
   `memory.yaml`/`dna.yaml` existed is counted `unchecked`, not failing, and the share is taken over a total that
   includes the unchecked items (the `v0.2.2` run: P02 `checked` 529 with 121 `unchecked`; P05 92 with 59), which
   lowers the failing share by the history's age rather than by its conformance.
5. **P03 (phases complete with absent `produces:`), free-text entries.** A `produces:` entry written as prose, or
   left with an unresolved token, is counted `unresolved` and not judged (the `v0.2.2` run: 19 unresolved beside 10
   checked).

The figures are the review's run at `v0.2.2` with `--previous v0.2.1`; `node scripts/release-health/measure.cjs
--release v0.2.2 --previous v0.2.1` reproduces them, G15 excepted.

## Decision

For each item, the catalogue states the definition (choose one per item):

- **G08:** (a) the window starts at the commit that introduced the conforming form (`task-256`'s merge), (b) the
  `dl-117` ratification as today, with the metric reported `not-comparable` for windows before the form existed.
- **G09:** (a) the grammar at the point, and `not-measurable` where the point has none; (b) the measuring build's, as
  today, stated as such.
- **G15:** (a) the refs at the point's commit date, filtered to those whose tip is reachable then; (b) a `snapshot`
  metric, documented as not reproducible and excluded from comparisons.
- **P02/P05:** (a) unchecked items excluded from the denominator and reported beside it; (b) as today.
- **P03:** (a) free-text `produces:` entries are a conformance failure of their own (a `spec-003` warning first);
  (b) counted `unresolved` as today.

**Recommendation:** G08 (b), G09 (a), G15 (b), P02/P05 (a), P03 (b) for v0.3, with the free-text entries reported by
`spec-003`'s loader so they shrink. These keep every value reproducible from the point and make no metric depend on
the history's age.

## Rationale

- `dl-089` makes the report comparable across releases; a definition that lives only in a script comment can change
  with the script, and two releases measured by two versions of it would not be comparable.
- The catalogue is versioned (`catalogue_version` in every report), so a definition change is visible in the
  comparison.
