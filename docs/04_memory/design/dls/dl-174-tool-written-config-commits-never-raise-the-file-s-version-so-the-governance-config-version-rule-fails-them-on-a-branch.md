## Context

`scripts/check-governance.cjs`'s `config-version` rule (`bug-249`, `sed -n 886,913p scripts/check-governance.cjs`)
fails a `--base` range in which a versioned configuration file changed without a numeric increase of its `version:`.
The tool's own configuration writers never raise that field: `wf(workflow): create` and `remove` (`task-211`),
`dna set`, `add`, `update` and `remove`, `directive assign` and `remove` each commit the file with its `version:`
unchanged. So any branch that changes configuration through the tool fails the gate.

Reproduced on a throw-away clone of `main` at `0da232cb` (code build): `node dist/cli.js dna set
project.description --value probe` → a commit `wf(dna): set project.description`, `.wingfoil/dna.yaml` still
`version: 1.9`; then `node scripts/check-governance.cjs --base <the clone's base>` → `config: .wingfoil/dna.yaml:
changed in …..HEAD, but version: 1.9 → 1.9 is no numeric increase (bug-249, doc-versioning)`, `gated: 1 findings on
1 commits (config 1)`. `task-211`'s independent review found it first (W3 B6) for `wf(workflow): create`.

## Decision

Choose one:

- **(a) the writers raise the content revision.** Every tool command that writes a versioned configuration file
  raises its `version:` (the `dl-047` content revision) in the same commit, numerically (`x.9 → (x+1).0`), with no
  history entry, or with a generated one.
- **(b) the gate credits the tool's `wf()` scopes.** The `config-version` rule does not count a change made by a
  `wf(dna|workflow|directive): …` commit; a hand edit still needs the bump.
- **(c) bump by hand in the same range.** The rule stays; whoever runs a tool command on a branch also bumps the file
  once by hand before the merge, as `doc-versioning` asks of any edit.

**Recommendation: (a).** It keeps one rule for every writer and keeps the `version:` meaningful; (b) makes the
content revision lie about tool edits, and (c) puts on every user a step the tool could do.

## Rationale

- `dl-047` defines `version:` as the content revision "bumped on every content change"; a tool edit is a content
  change.
- `bug-249` made the rule mechanical so that no reviewer has to remember it; a writer that breaks it on every use
  undoes that.
