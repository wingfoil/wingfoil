## Context

`docs/04_memory` is the surface the REQ-SEC-08 test scans (`test/validation/secret-scan.test.ts`), but `memory submit` does not scan the document it commits: `bug-402` reproduced on its own body (it quoted the lines the scanner flags), caught only by the pre-push sweep and fixed by amend. Six such false positives in prose happened in v0.3 (friction inventory T10).

## Decision

Options:

- **(a)** `memory submit` and `memory amend` scan the document with the project's spec-007 patterns and refuse a blocking finding (exit 1), naming the line;
- **(b)** they warn only;
- **(c)** no change: the test suite and the sweep stay the only checks.

Recommendation: (b) until `bug-402`'s false positives are fixed, then (a).

## Rationale

The commit is the cheapest moment to catch it; the suite only runs later, and a pushed commit cannot be fixed in place.
