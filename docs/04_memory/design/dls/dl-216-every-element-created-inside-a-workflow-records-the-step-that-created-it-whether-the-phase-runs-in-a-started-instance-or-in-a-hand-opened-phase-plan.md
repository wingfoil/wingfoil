## Context

**Elements almost never say which workflow step created them.** On this repository,
`git ls-files docs/04_memory | xargs grep -l '^step:' | wc -l` → 0 of 1086 Memory documents, and
`git log --format=%B | grep -c '^WingFoil-Step:'` → 18 of 10125 commits. Source: input given privately to the approver,
2026-11-05.

**Why.** `memory add --workflow <instance> --step <key>` writes the `WingFoil-Instance:` / `WingFoil-Step:` trailers
(AGENTS.md §5.1), but only a started instance offers it, in a step's action binding. Every phase of the v0.3.x
release cycles ran in a phase plan opened by hand with a `parent` (spec-017 §3.1: a phase plan, not an instance), so
the elements made there carry no link. The chain task → dev-loop → wave → release-cycle → release can only be guessed
from the element's type against the phases' `produces:` and its `release` field.

**What exists.** `dl-187` (ready, v0.3.1) and `workflow adopt` link an existing element to a step afterwards, one
audited commit per element; `bug-442` (triaged, v0.4) records that no verb addresses a phase plan. Neither records the
step at creation for a phase plan.

## Decision

Options:
- **(a) `memory add` accepts a phase plan as the run.** `--workflow <plan id>` takes a phase plan as well as an
  instance; the step key is resolved inside the phase the plan's `parent` names, and the add commit carries the same
  `WingFoil-Instance:` (the plan id) and `WingFoil-Step:` trailers. The deduction reads them as it reads an instance's
  (spec-017 §4.8, linkage); `memory history` returns them.
- **(b) A frontmatter field.** Every type gains an optional `step:` (and `run:`) field that `memory add` writes, read
  by the deduction and by `memory search`.
- **(c) No change**; links are made afterwards with `workflow adopt`.

**Recommendation: (a).** It reuses the record the engine already reads, keeps provenance in history (where it cannot
be edited without a trace), and closes the phase-plan gap without a schema change to every type. (b) duplicates the
trailer in a field that a hand edit can change silently; (c) costs one adopt commit per element and is never done in
practice (the counts above).

## Rationale

- **Provenance at creation is free; reconstruction is not.** Adoption after the fact needs a judgement per element;
  the add command already knows the step.
- **Phase plans are how this project runs its phases** until the engine executes steps; a provenance rule that
  excludes them excludes almost everything.
