## Context

The role MCP Prompts (`<role>-session`) do not reach the model in two agent CLIs: one has no tool to get a Prompt, the other exposes Prompts only as user slash commands; Resources are read fine by both. The session Resource `wingfoil://session/{role}/{element}/{state}` covers runs launched by `agent execute`; an agent started by itself, with no element, has no MCP path to its role's directives (only the CLI, `wingfoil directives list --role`). `docs/agents.md` "Rules" item 3 (line 76) names the Prompt first.

## Decision

1. Options for the path:
   - **(a)** an element-less role Resource, `wingfoil://session/{role}`, listed by the server, with the role's directives embedded;
   - **(b)** a directives Resource (`wingfoil://directives/{role}`), listed;
   - **(c)** no new Resource; the CLI is the documented path.
2. In every option, `docs/agents.md` item 3 names first the path that reaches the model (the Resource, or the CLI), and the Prompt as the user's slash command.

Recommendation: (a) and 2.

## Rationale

The Prompt was designed as the delivery channel of role rules, and in practice it is the one channel the model cannot pull; a Resource is the read path both CLIs serve.
