## Context

**`dl-143` (`ready`, 2026-10-21) decides one generator, from DNA and Directives, for four
outputs:** `AGENTS.md`, Agent Skills, hooks for Claude Code and Copilot, an Agent Plugins 1.0
package. It does not say whether every vendor format is written by WingFoil's own code, and its
Action 2 widens the tech-spec to all four outputs. The order in `dl-140` D3 puts it first for v0.4.

**The vendor-neutral formats are few and stable; the vendor-specific ones move every week.**
Read 2026-10-21:
- Agent Plugins 1.0: "A plugin can bundle a skill with an MCP server"; hooks are not in the
  neutral core — "Custom agents, commands, rules, and hooks load from" a Copilot-specific
  namespaced directory,
  <https://github.blog/changelog/2026-08-12-agent-plugins-1-0-in-vs-code-copilot-cli-and-the-copilot-app/>.
- rulesync (MIT, <https://github.com/dyoshikawa/rulesync>) generates rules, skills, subagents,
  MCP configuration, **hooks** and **permissions** for several dozen agents from one canonical
  input. Latest 39.0.0 (2026-10-21, <https://registry.npmjs.org/rulesync>); 171,145 downloads in
  the week 2026-10-12..18 (<https://api.npmjs.org/downloads/point/last-week/rulesync>).
- It shipped ten major versions between 2026-10-08 (29.0.0) and 2026-10-21 (39.0.0). Their
  "Breaking Changes" are almost all per-agent output fixes that follow a vendor's own format:
  Claude Code hooks `failClosed` written as `onFailure: "block"` and removed settings keys
  dropped (36.0.0, 30.0.0); Grok CLI hooks carrying `if` skipped (38.0.0); Reasonix and
  Antigravity permission names (36.0.0, 35.0.0); Kiro global permissions (36.0.0)
  (<https://github.com/dyoshikawa/rulesync/releases>).

So the churn is in the vendors' hook and permission formats. Re-implementing them in WingFoil
means following that churn for every agent; leaving them all to a third party means taking a
dependency that breaks every few days.

## Decision

**D1 — written by WingFoil.** The generator of `dl-143` writes the vendor-neutral outputs through
its own code path: `AGENTS.md`, Agent Skills (`SKILL.md`), the Agent Plugins 1.0 package (skills
and WingFoil's MCP server). They carry WingFoil's rules and are what every agent reads.

**D2 — reached through an optional target.** For vendor-specific hooks and permissions beyond
what WingFoil's own gates need, the generator writes rulesync's canonical input from the same
configuration, and rulesync generates each agent's files. The target is optional: a project that
does not enable it gets D1's outputs only. The Claude Code and Copilot hooks that WingFoil's own
gates need stay in D1 if the tech-spec finds them small.

**D3 — pinned.** The rulesync version is pinned exactly; moving the pin is a deliberate step,
reviewed with the diff of the generated files, never a floating range.

## Rationale

- **Own what is stable and central, delegate what is volatile and peripheral.** The neutral
  formats are WingFoil's message to every agent; vendor hook and permission dialects change
  weekly and add reach, not meaning.
- **One source stays one source.** rulesync's input is generated from the committed configuration,
  so `dl-143`'s determinism and drift detection still hold up to the target's input; the pinned
  version makes its output reproducible.
- **Optional keeps the core light.** A project that uses only agents reading the neutral formats
  takes no extra dependency.
