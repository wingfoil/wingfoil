## Context

**A tool that writes a `.wingfoil/` learns WingFoil's rules only by running WingFoil.** Templates (svc-018 F-020,
seen on 0.2.2, unfiled since the v0.3 retrospective) composes configurations from packs. A `dna.yaml` holding only
`version` and `project` is refused by `dna show` with one `E_VALIDATION` per missing section (`modules`, `stacks`,
`team`, `paths`); directive frontmatter and an agent adapter's `executes_as` are checked the same way. These rules
live only in WingFoil's loaders.

**Where they live:** `src/agent/schema.ts`, `src/directives/schema.ts`, `src/dna/schema.ts`, `src/memory/schema.ts`,
`src/workflow/schema.ts` (`ls src/*/schema.ts`), all Zod (`package.json`: `zod ^4.4.3`). The npm package ships `dist`
and `README.md` only (`package.json` `files`); no schema file is published.

**Neighbours.** `dl-149` gives each file kind a `format`; `dl-177` (in-discussion, v0.4) asks for a capabilities
query naming the formats read; `dl-200` (in-discussion, v0.4) proposes a `validate` verb; `dl-138` (ready, v0.4)
requires fetched content to pass the REQ-SEC-10 schema checks.

## Decision

Options:
- **(a) Generated JSON Schema, shipped and served.** A build step emits one JSON Schema per file kind and format
  (`dna`, `memory`, `roles`, `workflows`, workflow file, bindings, directive frontmatter, Memory template frontmatter,
  agent adapter) from the Zod schemas into `schemas/<kind>.v<format>.json`, included in the package's `files`; a read
  command (`wingfoil schema <kind> [--format-version N]`, also an MCP resource) prints it. A test fails when a
  generated schema differs from the committed one, so the published file cannot drift from the loader.
- **(b) Only a validate command** (`dl-200`): a composer runs WingFoil on its output, as today, but without side
  effects.
- **(c) No change.**

**Recommendation: (a)**, with `dl-200`'s validate verb kept for the cross-file rules a JSON Schema cannot express
(an `executes_as` naming a declared role). One source, the Zod schemas, gives editors, composers and WingFoil the same
rules, and the format number in each file name is `dl-149`'s.

## Rationale

- **The rules are already declared; only the reader is missing.** Generating from Zod adds no second definition.
- **A composer validates before WingFoil reads**, so a pack's error is found where it is written.
- **Semantic checks stay with WingFoil**: the schema covers shape; cross-references stay in validate.
