## Description

A Memory verb takes an element's full id only. With descriptive titles the ids are long (for example
`dl-001-pick-a-storage-layout-for-exports`), and typing them by hand is the main friction a user reported. On the code
build of `release/0.3` (`0.3.1 (1ce08b5c…)`), in a project made with `wingfoil init --template kanban` holding that
decision-log: `memory history dl-001` → `error: document not found: dl-001`, exit 1; `memory submit dl-001` → the same;
`memory history dl-001-pick` (a unique prefix of the full id) → `error: document not found: dl-001-pick`, exit 1. The user
reported the same on `wingfoil@0.3.1` (`870bd440`), also with `approve` and `reject`.

Admitted into `v0.3.2` as a small feature, a semver deviation the approver accepted on 2026-10-29 (recorded in the
dev-loop plan by the supervision); it runs in a last wave `w4`, after `w3`, once the open fixes are within the
stop-the-line share.

## Acceptance Criteria

- (red-first) A reference `<type prefix>-<n>` (e.g. `dl-001`, `task-12`) resolves to the element when exactly one element
  matches it.
- (red-first) A unique prefix of an element's full id resolves to that element.
- (red-first) A reference that matches more than one element is refused with exit 1 and lists the candidates' full ids;
  nothing is written.
- (red-first) The output, the commit subject and the commit body always carry the full id, never the short reference.
- (red-first) It holds for every Memory verb that takes an element id: `history`, `submit`, `approve`, `reject`, `amend`,
  `deprecate`, `park`, and any other command where an element id is an argument.
