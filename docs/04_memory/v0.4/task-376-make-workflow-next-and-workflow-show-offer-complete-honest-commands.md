## Description

Feature **P4.4**. Five defects in what `workflow next` and `workflow show` offer: `bug-486`, a step finalizable only through a manual
binding is not marked as such; `bug-439`, `memory add` is still offered once the element exists; `bug-490`, the offered `memory add` drops
the action's other arguments; `bug-479`, `workflow show` prints a built-in binding with no element id or reason; `bug-518`, the printed
`memory approve` lists elements that have no approve edge, so the command fails as printed.

## Acceptance Criteria

1. (red-first) `workflow next` and `workflow status` mark a step that is finalizable only through a manual binding or a record, in the JSON
   contract and in the console output (`bug-486`).
2. (red-first) Once a step has created its element, `workflow next` no longer offers `memory add` for it and names what is really missing
   (`bug-439`).
3. (red-first) The offered `memory add` carries every action argument the verb accepts, and an argument the binding cannot pass is a
   `workflow list` diagnostic (`bug-490`).
4. (red-first) `workflow show` prints a built-in binding with the placeholders `workflow next` uses: `wingfoil memory submit <id>`,
   `wingfoil memory approve <id> --reason <reason>` (`bug-479`).
5. (red-first) The printed `memory approve` names only the selected elements in a state with an approve edge, the others are reported apart,
   and the command succeeds as printed (`bug-518`).

#### Design

- **`bug-486`, AC 1.** `buildStep` adds `evidence.manualOnly: boolean` to `Step`: `finalizable` and no checkable evidence

  binding carries no `argv`; the console prints `- <text> — done: <ids>`. The deduction adds
  `DeducedStep.pendingCreated` (per created element short of its exit state or path:
  `{ element, reaches, missingPaths }`), which `Step` reports only when not empty; the console prints

- **`bug-490`, AC 3.** The list-aware `tokenArguments` moves from `src/workflow/deduce.ts` to `src/workflow/bindings.ts`,

  `--tags`, the `--set` of the declared tokens, the `--set <name>=<<name>>` of the tokens not given, `--workflow`,

  `spec-009`'s ID class prints as a placeholder (`dl-090` Q3 (a), D6). `stepLines` quotes an element a POSIX shell would

Two gaps of the `spec-017` amendment, found at green. The second amendment is prepared uncommitted in this worktree.

**Gap (a), a reserved token.** A `memory.add` argument naming a token `memory add --set` refuses is left out of the offered
command with no warning, while AC 3 asks for a `workflow list` diagnostic for every argument that cannot be passed. §2 excluded
every token of the patterns. `memory add --type bug --title probe --set slug=y --dry-run` prints
`error: invalid flag value: --set cannot set "slug": memory add fills it itself or through its own option`, exit `2`
(`spec-008` §10 lists the names). **Decision:** §6.1 leaves the argument out, and §2 reports it as
`W_ACTION_ARGUMENT_NOT_PASSED` with the message
`memory.add argument '<name>' cannot be passed: memory add --set reserves the name '<name>'`. The placeholders §6.1 prints for a
token not given follow the same list, and a numeric token (`{nnn}`, `{n:3}`), which `memory add` generates, counts as reserved.

**Gap (b), a declared literal in `workflow show`.** §6.1 said "every operand a placeholder", and §7.6 wrote `--title <title> …`.
(a) a placeholder for every operand that depends on an instance or that only the user can give, a declared literal staying as
declared; (b) a placeholder for every operand, literals included. **Recommended (a):** a literal does not depend on any
instance, so hiding it would make `workflow show` less complete than the declaration it reads, against `bug-479`'s purpose. An
argument that interpolates a value prints `<<name>>` as a whole, a list included.
