## Description

Feature **P5.2.3** (US-2-11, `P5.2.3-mcp-tools.feature`), REQ-INT-03, REQ-SYS-05, REQ-SEC-05. The production server has an
empty Tools channel (`src/mcp/server.ts`). This task registers the Memory Tools, derived from `CORE_MODULES` (W1-R4). The
approver-gated verbs are exposed and always refuse, since every MCP call is an agent context (W1-R2), and a Tool's commit is an
agent's commit (W1-R3). `bug-034`: the wire error repeats the `MCP error <code>:` prefix. `bug-530`: `dev-loop.yaml` and the
`wingfoil-cli` directive still describe an agent running a reject or an amend. `bug-538`: the agent-context refusals are
covered only by spawned suites that coverage does not instrument.

## Acceptance Criteria

1. (red-first) `wingfoil mcp` serves `memory.add`, `memory.submit`, `memory.deprecate` and `memory.park`, derived from
   `CORE_MODULES`; each validates as the CLI does and writes the same single commit.
2. (red-first) `memory.approve`, `memory.reject` and `memory.amend` are listed Tools and every call refuses with
   `E_AGENT_CONTEXT`, whatever its arguments' identity (W1-R2, `dl-212` D1, `spec-018` §1.2). The design gate settles whether a
   missing argument is reported before the refusal, and the BDD scenario follows that ruling.
3. (red-first) Every Tool call runs as an agent context: its commit carries `Co-Authored-By:` and `AI-Model:`, the model read
   from `WINGFOIL_AGENT_MODEL` in the server's environment, else `not-reported` (W1-R3, `spec-018` §2). The mechanism is settled
   at the design gate.
4. (red-first) The illegal-transition and missing-argument scenarios of `P5.2.3-mcp-tools.feature` pass against a real server.
5. (red-first) A refusal is an `isError` result that keeps the operation's warnings in `structuredContent`, and `spec-008` states
   that a refused option value keeps exit `2` (`dl-199` (b)).
6. (red-first) The wire `error.message` carries the reason alone, so a client renders one prefix (`bug-034`).
7. (characterization) `dev-loop.yaml` and the `wingfoil-cli` directive say that the approver runs the verb from their own
   terminal and that an agent never does (`bug-530`), with their `version:` bumped and the change proved on the pinned build.
8. (red-first) One in-process unit test per propagation class reaches the agent-context refusal, so coverage measures it
   (`bug-538`).
9. (characterization) `spec-004` §4 and `spec-018` §1.2 state W1-R2 and W1-R3: the amendments are prepared for the design gate.
