## Description

Feature **P5.3.1**. `dl-180` invocation (c) (`ready`, `74d9c65d2`): the bootstrap names the exact invocation of the
build under test and a `PATH` shim puts that build first, so a pasted command and a plain `wingfoil` both reach it —
closing `bug-369` (medium: the launched agent ran the global `wingfoil`). `dl-168` Q1 (b) (`ready`, `841047dac`): the
assigned session id hashes a per-clone random salt kept under the git directory with the run id, so committed records
stop disclosing the absolute path; existing records stay as history. `spec-018` §1.1 (`approved`): `agent execute`
spawns the agent with `WINGFOIL_AGENT=<selected entry name>`, its own record commit carries no agent trailer, and it
takes no `--co-author`/`--ai-model`. `spec-018` Consequences rewrites the bootstrap's `{attribution_line}`: the verbs
now write the trailers (`task-334`), so the agent is told to pass `--ai-model <its model identifier>` (or the verbs write
`AI-Model: not-reported`), to write the trailers itself only on a plain `git commit`, and never to run `approve`,
`reject` or `amend`. That is how `bug-370` (the placeholder `AI-Model: <the model identifier you run as>` is not
honoured) is resolved under `spec-018` §2.4: WingFoil cannot know the model before the run, so the bootstrap stops
asking the agent to type it into an amend.

## Acceptance Criteria

1. (red-first) The bootstrap names the exact invocation of the build that launched it, and the spawned environment
   puts a `wingfoil` shim for that build first on `PATH`; inside the agent's shell `wingfoil --version` prints the
   launching build's version and sha (`spec-016` §2.4, amendment `spec-016` § 2.4 bootstrap, § 2.6 session id; `dl-180` (c); `bug-369`).
2. (red-first) The agent is spawned with `WINGFOIL_AGENT` set to the selected `team.agents` entry's name, in the spawn
   only, not in the post-run lookups; the `agent: record` commit carries no agent trailer even when `agent execute`
   runs under `CLAUDE_CODE_CHILD_SESSION`; `agent execute --co-author …` exits `2` as an unknown option (`spec-018`
   §1.1, §6 T-22; `spec-016` § 2.4 bootstrap, § 2.6 session id).
3. (red-first) The bootstrap's `{attribution_line}` carries `spec-018` Consequences' new text and no longer contains
   `<the model identifier you run as>` (`bug-370`; `spec-016` §2.4, `spec-016` § 2.4 bootstrap, § 2.6 session id); the BDD scenario of
   `p5-interaction/P5.3.1-agent-execute.feature` that says the bootstrap tells the agent to sign its commits is
   reworded before `red`.
4. (red-first) The assigned session id is a function of a per-clone salt kept under the git directory and of the run
   id, never of the absolute repository path; the salt is created once and reused (`spec-016` §2.6, `spec-016` § 2.4 bootstrap, § 2.6 session id; `dl-168`
   (b); `spec-011` § `.gitignore` policy note, `spec-011` § `.gitignore` policy).
5. (characterization) Run records committed before the change still parse and keep their session ids (`dl-168`
   ratification: "existing records are left as history").
6. (characterization) The spec amendments `spec-016` § 2.4 bootstrap, § 2.6 session id and `spec-011` § `.gitignore` policy (salt location) are approved at the design gate.
7. (red-first) When the run's model is not known before or after the launch (`bug-370` Expected, second branch;
   `spec-018` §2.4), the run record says that the `AI-Model:` value written by the agent was the agent's own claim, not
   a value WingFoil read; a test launches a fake adapter that reports no model and reads the record.
