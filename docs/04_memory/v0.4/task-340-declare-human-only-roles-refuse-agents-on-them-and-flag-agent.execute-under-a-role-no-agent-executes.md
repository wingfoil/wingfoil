## Description

Features **P2.4** (team and roles) and **P4.1** (workflow validation). `dl-202` items 1–2 (`ready`, `8b2903a1a`):
which roles agents may execute is declared per role, not inferred — the human-only roles are named (at least
`approver`; this repository also marks `product-owner` and `tech-lead`) — and the workflow validation `workflow list`
runs reports a phase whose `actions` contain `agent.execute` under a role no `team.agents` entry with an `adapter`
executes (`W_WORKFLOW_AGENT_ROLE_UNEXECUTED`). Item 3 shipped in patch-v0.3.1 (`task-292`). `bug-459`:
`check:role-directives` checks only the roles `dna.yaml` declares, so a `roles.yaml` binding under any other role is
never an error.
