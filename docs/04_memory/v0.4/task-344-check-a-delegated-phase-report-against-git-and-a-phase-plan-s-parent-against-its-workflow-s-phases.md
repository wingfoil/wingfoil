**Design.**

*The script* — `scripts/check-phase-report.cjs` with `scripts/check-phase-report.d.cts` (D1). Two subcommands, exit `0` (no
mismatch), `1` (one stdout line per mismatch, `<kind>: <detail>`, then a summary line), `2` (usage: unknown subcommand or
option, a missing `--report`/`--base`, an unreadable report, a malformed report, a `--base`/`--rev` naming no commit, not a
git worktree, `dist/` not built — "run `npm run build` first", as `check-governance.cjs` says). Usage errors go to
stderr as `check-phase-report: <message>`.

```
node scripts/check-phase-report.cjs report --report <file> --base <rev> [--since <ISO-8601>] [--worktree <dir>] [--trace <file>]
node scripts/check-phase-report.cjs plans [--rev <rev>] [--worktree <dir>]
```

`--worktree` defaults to the repository of the current directory (`git rev-parse --show-toplevel`); `--trace` defaults to
`gateTracePath(gateDir(process.env))` from `scripts/heavy-gate.cjs`; `--since` defaults to the committer date of `--base`;
`--rev` defaults to `HEAD`. It reads `dist/` of its own checkout (`join(__dirname, '..', 'dist')`) and git in `--worktree`,
so it can be run from another checkout than the one checked. It reads committed state, the worktree's status, the report
file and the trace; it writes nothing. Not in `package.json` scripts, not in `.github/workflows/`, not in
`.wingfoil/workflows/bindings.yaml` (AC 3).

*The report format* (AC 4; the module doc declares it, with one complete example a test reads). The first non-blank line is
the header; the lines right after it, up to the first blank line, are the claims; everything after that blank line is
prose the script never reads.

```
REPORT <task> <phase> head=<sha>
commit <sha> [<subject>]
file <path>
uncommitted <path>
gate <test|coverage|build|typecheck> exit=<integer>
```

- `<task>`: `task-<n>` or the full id; `<phase>`: one token `[a-z][a-z+-]*` (`design`, `red`, `green+refactor`, `review`),
  recorded, not checked; `<sha>`: 7–40 lowercase hex.
- `commit`: every commit the phase made on its branch, merges included, in any order; text after the sha is ignored.
- `file`: every path the phase's commits changed, repository-relative as `git -c core.quotePath=false` prints it.
- `uncommitted`: every path the phase leaves changed or untracked in the worktree on purpose (a pending amendment).
- `gate`: one line per heavy gate run (`npm test` with no suite filter → `test`, `test:coverage`/`test:report` →
  `coverage`, `build` → `build`, `typecheck` → `typecheck`), with its exit status. A targeted jest run is not a gate and is
  not claimed. `npm run typecheck` leaves two `typecheck` holds; one claim matches one hold.
- A claims line with any other keyword, a header that does not match, or a `gate` line without `exit=<integer>` is a
  format error (exit 2, naming the line number). Duplicate `commit`/`file`/`uncommitted` lines count once; two `gate`
  lines for the same gate claim two runs.

*The checks of `report`, in this order (the order of `MISMATCH_KINDS` and of the output).*

| Kind | Mismatch |
|---|---|
| `task` | the worktree's branch (`git branch --show-current`) is neither `task/<task>` nor starts with `task/<task>-` |
| `head` | `git rev-parse HEAD` in the worktree does not start with the claimed sha |
| `commit-unknown` | a listed sha names no commit |
| `commit-outside` | a listed commit is not in `git rev-list --first-parent <base>..HEAD` |
| `commit-unlisted` | a commit of that range is not listed, unless its body has an `Approver:` line (the approver's act: an approve, a reject, an amend, a design-gate record) |
| `trailer-missing` | a listed commit without an `Approver:` line whose final paragraph lacks `Co-Authored-By:` or a non-blank `AI-Model:` (`git-conventions` §7) |
| `trailer-identity` | its `Co-Authored-By:` names no `team.agents` entry `<name> <<email>>` of the `dna.yaml` committed at `HEAD` (§7 "Which name"; e.g. `Claude Opus 5.5`) |
| `trailer-forbidden` | a `wf(<type>): approve` or `reject` commit carrying `Co-Authored-By:` or `AI-Model:` (§7 "Which commits") |
| `trailer-paragraph` | a listed commit with a `WingFoil-*`, `Co-Authored-By:` or `AI-Model:` line outside its final paragraph (§8, `bug-391`) |
| `file-unclaimed` | a path changed by the range's first-parent commits (a non-merge: `git diff-tree -r --name-only`; a merge: its `--cc` paths, i.e. what the merge itself resolved) that no `file` line names |
| `file-unchanged` | a `file` line naming a path no such commit changed |
| `uncommitted-unclaimed` | a path of `git status --porcelain -uall` (a rename: its new path) no `uncommitted` line names |
| `uncommitted-missing` | an `uncommitted` line naming a path the status does not list |
| `gate-missing` | a `gate` claim with no hold of that gate in the worktree started at or after `--since` |
| `gate-status` | holds exist, but none unused with the claimed status (the detail names the statuses found) |
| `gate-open` | the only candidate is an `acquire` with no `release` (a gate still running, or killed and not yet taken over) |
| `plan-parent` | a changed path that is, at `HEAD`, a `plan` document whose non-empty `parent` names no workflow, or no phase of its workflow (AC 2's rule, below) |

Within a kind the lines follow the report's order, then the path order. A hold is the `acquire`/`release` pair with equal
`pid`, `worktree` and `start` (`task-349`'s definition); claims are matched in the report's order, each to the earliest
unused matching hold. The worktree is compared after `realpathSync` on both sides. A trace line that is not a JSON object
with `v: 1` is skipped (several writers append; a cut last line must not fail the check); an absent trace makes every
claim `gate-missing`, the detail naming the path.

*The `plans` subcommand* (AC 2). Every Memory document of type `plan` at `--rev` (`loadMemoryDocumentsAtRev` with the
`memory.yaml` of that rev) whose `parent` is a non-empty string: split at its first `.` into workflow and phase; a workflow
the registry at that rev (`loadWorkflowRegistryAtRev`) does not load → `plan-parent: <id> (<path>): parent "<value>" names
no workflow`; a phase that workflow does not declare → `plan-parent: <id> (<path>): parent "<value>" names no phase of
<workflow> (<its phases, in order>)`; no `.` → names no phase either. Sorted by path. `report` applies the same rule to the
plans among its changed paths only (D6), so the repository's history never fails a phase report.

*The fields of `task-349`'s trace the check uses, and whether they suffice.* `v` (1), `event` (`acquire`/`release`),
`gate`, `pid`, `worktree`, `start` (pairing and the window), `status` (the claimed exit); `end`, `waited_ms` and
`takeover` are not needed (an unreleased `acquire` is enough for `gate-open`). They suffice for AC 1 — "a heavy gate it
claims ran while holding the slot" is a released hold of that gate, in that worktree, inside the phase's window, with
the claimed status. Four limits, none blocking: the trace is per machine user and lost at a reboot (`task-349` D5), so the
check runs right after the phase; a hold names a worktree, not a commit, so it proves a gate ran in the window, not on
which tree; whether a gate ran detached is not visible in the trace; and `bug-508` (below).

*`bug-508`* — a killed `test`/`coverage` run is recorded `status: 1`, a killed `build`/`typecheck` run `null`. For AC 1 the
check compares the claimed integer with `status`: a claim `exit=0` never matches either a `1` or a `null`, so no killed
run can be passed off as a green one; only a report claiming `exit=1` for a run that was in fact killed would go
unnoticed, and both mean "not passed". AC 1 does not need it (D2).
