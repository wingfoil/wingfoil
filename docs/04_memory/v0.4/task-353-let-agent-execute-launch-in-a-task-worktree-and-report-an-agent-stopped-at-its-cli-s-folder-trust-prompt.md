## Description

Feature **P5.3.1**. `bug-499`: `agent execute` always launches the agent in the project root, so a dev-loop with one
worktree per task cannot use it; expected, the working directory comes from the step or the caller (the worktree the
run's `start` step created, a `--cwd <dir>` option confined to the repository's worktrees, or a `{worktree}`
placeholder) and the run record is still committed on the run's branch. `bug-500`: an agent launched by `agent execute`
stops at its own CLI's folder-trust prompt and the run is recorded as failed with no hint that it never started.
`bug-418`: `--next` refuses an unscoped step that `agent list --waiting` lists, so the `init` scaffold's first step
cannot be run by an agent. The launch working directory is a prerequisite of the print-mode pilot
(`release-planning-rel-v0.4-plan` R1 L8). `spec-016` §3.3 gives the agent the project root as its working directory;
no survey row covered it, so this task extends amendment `spec-016` § 3.1 grammar, § 3.2 resolution, § 3.3 pipeline, § 3.5 headless, § 3.7 refusals.

## Acceptance Criteria

1. (red-first) An option or adapter field sets the launch's working directory to a worktree of the repository
   (`git worktree list`); a directory that is not one is refused before any side effect, `VALIDATION`, exit `1`; the
   run record is committed on the run's branch (`bug-499` Expected; `spec-016` §3.3, amendment `spec-016` § 3.1 grammar, § 3.2 resolution, § 3.3 pipeline, § 3.5 headless, § 3.7 refusals extended).
2. (red-first) The built-in adapters declare how their CLI is told to trust the launch directory where the CLI allows it,
   verified with `verified_with`; when an agent exits without getting past its start-up, the record's `notes` and
   stderr name the agent CLI's folder-trust step as the likely cause (`bug-500` Expected; new `spec-016` §3.7 row).
3. (red-first) `agent execute --next` and `agent list --waiting` agree on an unscoped step of an instance with no
   bound element: either the run targets the instance's own `plan` element (`plan:<instance-id>`, its run log under
   `spec-016` §5.1), or `agent list --waiting` leaves the step out or marks it as needing `--element`, chosen at
   design (`bug-418` Expected).
4. (characterization) The spec amendment `spec-016` § 3.1 grammar, § 3.2 resolution, § 3.3 pipeline, § 3.5 headless, § 3.7 refusals (working directory; the folder-trust row), and `spec-016` § 2.2 schema, § 2.8 built-ins if an adapter field is
   added, are approved at the design gate.
