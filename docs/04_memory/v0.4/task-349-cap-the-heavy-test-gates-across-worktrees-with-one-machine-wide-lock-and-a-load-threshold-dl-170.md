## Description

Feature **P4.12** (process gates). `dl-170` (`ready`, `e9d711403`), ratified at the v0.3 retrospective with (a) and
(C): one heavy gate at a time per machine now (a configurable cap later through `WINGFOIL_GATE_SLOTS`), enforced in
the scripts and named in `dev-loop.yaml`. A heavy gate is the full test suite, the coverage run, or the production
type-check/build; it waits while the cap is reached or while the 1-minute load average is above the number of cores,
reports the wait once on stderr with the holder's worktree and pid, and takes over a lock whose pid is gone; a
detached run is not a way around the cap. `bug-446`: code under test still reads the developer's global git config in
the jest run, so a hostile global `core.excludesFile` fails 11 tests.

## Acceptance Criteria

1. (red-first) `scripts/run-tests.cjs` acquires a machine-wide lock before a heavy gate, waits while the cap (1) is
   reached or `os.loadavg()[0] > os.cpus().length`, reports the wait once on stderr with the holder's worktree and pid,
   and takes over a lock whose holder pid is gone (`dl-170` Decision 2–4, Q1 (a), Q2 (C) script half).
2. (red-first) `npm run test:coverage` and the production type-check/build (`tsc -p tsconfig.build.json`,
   `npm run build`) run through the same lock; a targeted run of named suites does not take it; a heavy gate that runs
   another inside it (the jest global setup building `dist/`) does not wait on its own lock (`dl-170` Decision 1).
3. (red-first) The lock leaves a trace a later reader can check — holder, worktree, start and end — agreed with `task-344`.
4. (red-first) `dev-loop.yaml` names the slot on the phases that run heavy gates, so `workflow show` and the reviewer
   see it (`dl-170` Q2 (C)), with one `version:` bump.
5. (red-first) The `testing` directive states: no detached heavy gate, and an agent is resumed only after checking that
   its worktree has no live gate process (`dl-170` Decision 4).
6. (red-first) Code under test in the jest run no longer reads the developer's global git config: a test with a
   hostile global `core.excludesFile` passes (`bug-446`; `testing` T2 — the check asserts the isolation invariant).
