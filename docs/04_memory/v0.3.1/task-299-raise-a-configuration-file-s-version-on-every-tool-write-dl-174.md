## Description

`dl-174` (a): every tool command that writes one of the four versioned configuration files raises its
`version:` in the same commit (`spec-006` §6 item 7, referenced by `spec-002`, `spec-011`, `spec-017` §7.7–§7.8), so a
tool-written config commit passes the governance check's `config-version` rule on a branch.

## Acceptance Criteria

- (red-first) `dna set|add|update|remove` (`--force` included), `directive assign`, `workflow create|remove` raise
  the file's `version:` by 0.1 read as a number (`1.9 → 2.0`), in the file's quoting, keeping the line's comment; no
  history entry is added; a file without `version:` gains none; a file written whole for the first time is written
  `version: 1.0`.
- (red-first) `--dry-run` shows the raised version in its diff.
- (characterization) `doc-versioning` states that a tool write is a revision of its own and the
  one-bump-per-branch rule applies to hand edits.
- (red-first) On a scratch branch with two tool writes to one versioned file, `check:governance`'s `config-version`
  rule passes (it fails before the change).
