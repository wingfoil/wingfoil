## Summary

`parseYaml` (`src/validation/yaml.ts:20-27`) calls js-yaml's `load(text)` with the default schema, which resolves an
unquoted `YYYY-MM-DD` scalar to a JavaScript `Date`. The context builder re-emits frontmatter with
`dump(value, { sortKeys: true, lineWidth: -1, noRefs: true })` (`src/core/context.ts:302-305`), which writes a
`Date` as an ISO timestamp. A frontmatter line `created: 2026-10-05` therefore reaches the `spec-012` §7 payload as
`created: 2026-10-05T00:00:00.000Z`: the value is deterministic, but the payload no longer carries what the
document says, and it gains a time of day and a zone the document never declared.

## Steps to Reproduce

On `main` at `0b297169`, after `npm run -s build`:

1. `node -e "const {parseYaml}=require('./dist/validation/yaml.js'); const {serializeExecutionContext}=require('./dist/core/context.js'); const fm=parseYaml('id: task-999\ntype: task\ncreated: 2026-10-05\ndate: \"2026-10-05\"\n','x'); console.log(serializeExecutionContext({role:'developer',stateRef:'0'.repeat(40),element:{type:'task',id:'task-999',frontmatter:fm,body:'b'},dna:{modules:[]},directives:[],memory:[]}))"`
2. The `## 1. Task` YAML block prints `created: 2026-10-05T00:00:00.000Z` and `date: '2026-10-05'`: the unquoted
   date is rewritten, the quoted one kept (with its quoting changed).

## Expected Behavior

`spec-012` §7 re-emits frontmatter "with keys sorted ascending"; a scalar's value reaches the payload as the
document declares it. A date-shaped scalar stays `2026-10-05`.

## Actual Behavior

Every unquoted date-shaped frontmatter scalar of the element and of each relevant Memory document becomes an ISO
timestamp in the payload.

## Notes

- Latent on this repository: no Memory, plan or config file has an unquoted date-shaped field
  (`grep -rnE '^[a-zA-Z_-]+: [0-9]{4}-[0-9]{2}-[0-9]{2}' docs/04_memory docs/05_plans .wingfoil | wc -l` → `0`;
  the templates quote every field). A user project whose templates or hand edits write bare dates meets it.
- §7's "no wall-clock" rule is not broken (the value is a function of the document), but the payload carries a
  timestamp the document does not.
- Fix candidates: parse with a schema that has no timestamp type (`JSON_SCHEMA`/`CORE_SCHEMA`, or a custom one),
  which changes every reader of `parseYaml` and needs a check that nothing relies on `Date` values; or re-emit
  `Date` values as `YYYY-MM-DD` only in the context builder. The payload's bytes change either way, so it is
  cheapest before `task-218`/`task-195` consume them, and it can go with the `spec-012` §7 byte-format
  decision-log filed by the same plan.
- No existing bug covers it (`grep -rlE 'js-yaml.*schema|JSON_SCHEMA|CORE_SCHEMA' docs/04_memory/bugs` → none).
