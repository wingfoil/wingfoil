## Summary

The documentation site's render guard (`htmlBlockStarts` in `test/docs/support/pages-render.ts`, `task-289`)
approximates kramdown's HTML-block rule with a line scan, and three shapes fall outside it: a paragraph line that
begins with a closing tag (`</div>`) is not reported; a list-item paragraph that starts after a blank line with
`<type>:<id>` is taken for an HTML block opened on purpose and not reported, though it is the very class the guard
exists for; and a paragraph line that begins with an inline element (`<code>`) is reported, though kramdown keeps a
span element inside the paragraph. None of the three occurs in the eleven site pages today; the guard can let the
next broken page through, or block a correct one.

## Steps to Reproduce

On `ingest/user-docs-v0.3-findings` at `main` `1c4a3a43`: transpile `test/docs/support/pages-render.ts` with
`typescript.transpileModule` (CommonJS) into a scratch file and call `htmlBlockStarts` on four pages:

1. The positive case, the known class: ``['Run `wingfoil workflow remove', '<name>` to delete it.'].join('\n')`` →
   ``[{"line":2,"text":"<name>` to delete it."}]``.
2. A closing tag continuing a paragraph: `['Some paragraph text', '</div>'].join('\n')` → `[]`.
3. A list paragraph after a blank line: ``['- item text', '', '  <type>:<id>` continues here'].join('\n')`` → `[]`.
4. An inline element continuing a paragraph: `['Run the', '<code>wingfoil paths</code> command'].join('\n')` →
   `[{"line":2,"text":"<code>wingfoil paths</code> command"}]`.

The guard's own comment names one accepted gap only (`grep -n "Accepted gap" test/docs/support/pages-render.ts` →
line 20, an indented continuation read as indented code); cases 2–4 were found and accepted by `task-289`'s
independent review (its Execution Notes, review finding 6, "Guard gaps"), without editing the guard.

## Expected Behavior

The guard reports what kramdown would read as an HTML block in the middle of a paragraph or list item and nothing
else: cases 2 and 3 reported, case 4 not. Either the line scan learns the three shapes (block-level versus span-level
tag names, closing tags, list-item context after a blank line), or the guard renders the site pages with kramdown
itself, in the test or in the Pages build (`.github/workflows/pages.yml` builds with `actions/jekyll-build-pages`),
and fails on a page whose output still carries Markdown syntax.

## Actual Behavior

Cases 2 and 3 → no finding; case 4 → one finding.
