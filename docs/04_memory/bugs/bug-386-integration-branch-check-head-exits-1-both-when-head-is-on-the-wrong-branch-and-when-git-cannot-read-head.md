## Summary

`scripts/integration-branch.cjs --check-head` (`task-288`), bound in `.wingfoil/workflows/bindings.yaml` as
`release-publishing`'s `tag` pre-check `on-integration-branch` at `severity: reject`, exits `1` for two different
outcomes: HEAD is on a branch other than the release's integration branch (a real refusal), and git cannot read HEAD
at all (not a repository, git missing). Only the stderr text tells them apart, so a caller that reads the exit code
reports an environment failure as "HEAD is on the wrong branch".

3. In an empty directory outside any repository (`GIT_CEILING_DIRECTORIES` set to its parent): the same command →
   stderr `could not read HEAD: fatal: not a git repository (or any of the parent directories): .git`, exit `1`.

## Expected Behavior

An environment failure (git cannot be run, or the directory is not a repository) exits with a code distinct from the
refusal — e.g. `2`, which the script already uses for what it cannot judge — and the header and the binding's comment
say so.

## Actual Behavior

Both exit `1`. Low: the stderr differs and the pre-check runs in the repository, where git is present.
