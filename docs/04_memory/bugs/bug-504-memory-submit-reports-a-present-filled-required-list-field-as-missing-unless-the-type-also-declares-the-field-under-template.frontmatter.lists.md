## Summary

`memory submit` refuses a document whose required field holds a non-empty list with `missing required field on
submit: <field>` when the type does not list the field under `template.frontmatter.lists`; the field is present, the
message names the wrong cause, and 0.2.2 accepted the same document. Reproduced on 0.3.2.

## Steps to Reproduce

In a throwaway repository on the pinned build (`npm run -s wingfoil --`, 0.3.2):

1. `init --template Kanban --no-interactive`.
2. In `.wingfoil/memory.yaml`, add `features` to the `task` type's `template.frontmatter.required`; commit.
3. `memory add --type task …`, set `features: [ F-1 ]` in its frontmatter; commit.
4. `memory submit task-007-listy2 --format json`.

## Expected Behavior

A required field that is present and filled is never reported as missing. Either a non-empty list satisfies a
required field whether or not `lists` declares it, or the refusal names the real cause (the field holds a list the
type does not declare under `template.frontmatter.lists`), and a configuration read reports a required field whose
template value is a list but which `lists` omits.

## Actual Behavior

`{"error":"missing required field on submit: features"}`, exit 1. Adding `lists: [ features ]` to the type's
`template.frontmatter` makes the same document submit (`draft → pending`), per the consumer's note on 0.3.1.
