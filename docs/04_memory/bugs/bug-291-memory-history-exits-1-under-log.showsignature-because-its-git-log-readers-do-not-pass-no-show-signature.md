## Summary

`wingfoil memory history` runs `git log` without `--no-show-signature` in three places: `walkGitLogFields`
(`src/memory/git-log.ts`), and the creation and path probes `CREATION_PROBE_ARGS` and `PATH_PROBE_LOG_ARGS`
(`src/memory/history.ts`). With `log.showSignature=true` in the user's git configuration, git prints the
signature verification text ("Good \"git\" signature for …", or "No signature") into the output those readers
parse as shas and fields, and `memory history` fails at exit 1 on any element whose history holds a signed
commit. `task-220` fixed the same class in `agent show` (`src/core/agent-show.ts`, `runGitRead(root, ['log',
'--no-show-signature', …])`); the Memory readers were not changed.

## Steps to Reproduce

On `main` at `c485e433` (`npm ci && npm run build`), in a scratch repository with `GIT_CONFIG_GLOBAL=/dev/null` and
`GIT_CONFIG_NOSYSTEM=1`, scaffolded by `node dist/cli.js init --template Scrum`, with an SSH signing key
(`gpg.format=ssh`, `user.signingkey`, `commit.gpgsign=true`, and `gpg.ssh.allowedSignersFile` naming the key):

1. `node dist/cli.js memory add --type bug --title "Scratch bug"` → exit 0, one signed commit
   (`git log --format='%h %G? %s' -1` → `dd51be4 G wf(bug): add bug-001-scratch-bug`).
2. `git config log.showSignature false`, then `node dist/cli.js memory history bug-001-scratch-bug` → exit 0, one
   entry, `operation: add` (the control).
3. `git config log.showSignature true`, then the same command → exit 1, `error: creation commit Good "git"
   signature for scratch@example.org with ED25519 key SHA256:… is not present in the history walk it was derived
   from`.
4. With `gpg.ssh.allowedSignersFile` unset → exit 1, `error: creation commit No signature is not present in the
   history walk it was derived from`.
5. `grep -rn 'show-signature' src` → only `src/core/agent-show.ts` (its comment and the `log` call).

## Expected Behavior

Every `git log` (and `git show` of a commit) whose output WingFoil parses passes `--no-show-signature`, so a user's
`log.showSignature` setting cannot change what a read command reports; a test pins it for `memory history` as
`task-220`'s test does for `agent show`.

## Actual Behavior

`memory history` refuses with a message built from signature text, for every element with a signed commit in its
history, whenever `log.showSignature` is on.

## Notes

- Medium: `memory history` is a shipped read command (P1.10, `minor-v0.2`), signed commits and
  `log.showSignature=true` are a common combination for developers who sign, and the failure is total for the
  element, not a degraded output. This repository is not affected unless the developer sets the option.
- The same search for other readers, `grep -rn "'log'" src --include=*.ts`, lists one more `git log` without the
