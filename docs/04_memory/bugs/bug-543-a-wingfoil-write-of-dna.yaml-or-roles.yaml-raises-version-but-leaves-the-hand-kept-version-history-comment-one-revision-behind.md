# A wingfoil write of dna.yaml or roles.yaml raises version but leaves the hand-kept version history comment one revision behind

## Summary

A `wingfoil` write of `.wingfoil/dna.yaml` or `.wingfoil/roles.yaml` raises the file's `version:` by 0.1 in its own commit
(`dl-174` (a), `spec-006` §6 item 7, `raiseConfigVersion` in `src/validation/config-version.ts`), and keeps the line's
trailing comment byte for byte. In both files that comment is a hand-kept version history, so after the write it ends
one or more revisions before the value it annotates, and stays false until someone adds the entry in a separate hand
commit. `task-341` met it twice at `02ffe01ca`'s ancestors: `dna.yaml` went 2.4 → 2.6 and `roles.yaml` 1.9 → 2.0, and
each needed a `chore(...)` commit to bring its comment level.

## Steps to Reproduce

1. The verb commits of `task-341`, as committed:
   - `git show 2749f4511:.wingfoil/dna.yaml | grep -n "^version:"` → `11:version: 2.6 … # … 2.1 -> 2.4 at task-340 (…). The
     file's FORMAT is …`: the value is 2.6 and the last history entry is `2.1 -> 2.4` (written by `wf(dna): update
     team.agents.Claude`, after `f1b14913b` `wf(dna): add team.roles coordinator` raised 2.4 → 2.5).
   - `git show 3e950f601:.wingfoil/roles.yaml | grep -n "^version:"` → `41:version: 2.0 # 1.9 approver: [code-review,
     standing-approvals] (task-343) (prev 1.8 …)`: the value is 2.0 and the comment's newest entry is 1.9 (written by
     `wf(directive): assign coordinator to coordinator`).
   - The hand commits that repaired them: `f5503b573` `chore(dna): task-341 — the version history comment …` and
     `5b67fb416` `chore(roles): task-341 — … the 2.0 version note`. At `02ffe01ca`, `.wingfoil/dna.yaml:11` ends
     `2.4 -> 2.6 at task-341 (…)` and `.wingfoil/roles.yaml:45` reads `version: 2.0 # 2.0 coordinator: [coordinator]
     (task-341) (prev 1.9 …)`.
2. Still so at `02ffe01ca`, in a scratch clone of it, code build, agent session:
   `node <worktree>/dist/cli.js dna update team.agents.Claude --entry-executes_as developer,reviewer,qa,architect,facilitator`
   → exit 0, `wf(dna): update team.agents.Claude`; `grep -n "^version: [0-9.]*" -o .wingfoil/dna.yaml` → `11:version: 2.7`,
   while the same line's comment still ends at `2.4 -> 2.6 at task-341 (…)`.

## Expected Behavior

After any commit, the `version:` line of a versioned configuration file says nothing false about the value it carries:
either the comment holds no per-revision history that a tool write can leave behind, or the history is complete.

## Actual Behavior

Each tool write leaves the comment one revision behind, and correcting it costs a hand commit per branch. The
writer's own TSDoc says it is deliberate on the writer's side ("no history entry is added: the `wf()` commit is the
record", `raiseConfigVersion`, `02ffe01ca`), so the stale text is in the hand-kept comment, not in the raise.
