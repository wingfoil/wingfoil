## Summary

`scripts/check-governance.cjs` accepts an `approve` or `reject` commit that carries `Co-Authored-By:` and
`AI-Model:` trailers, although `git-conventions` §7 says those commits record the approver's decision and
carry no AI co-author, even when an agent typed them.

## Steps to Reproduce

1. On `main`, list the `approve`/`reject` commits since the directive introduced the rule (`39885b87`,
   task-178) and keep those with a `Co-Authored-By` trailer:
   `git log 39885b87..main -E --grep '^wf\([a-z-]+\): (approve|reject) ' --format='%h %(trailers:key=Co-Authored-By,valueonly,separator=;)' | awk 'NF>1' | wc -l`
   printed `63` (of `171` such commits, same command without the `awk` filter), on 2026-10-09.
2. Run `node scripts/check-governance.cjs --base 1ce84a54` over the W3 B3 range, which contains such commits.

## Expected Behavior

The governance check reports each `approve`/`reject` commit that carries an AI co-author trailer as a
finding, so the rule `git-conventions` §7 states is enforced rather than remembered.

## Actual Behavior

`governance check: 81 wf() commits … gated: 0 findings on 0 commits` (W3 B3 gate, 2026-10-09): nothing is
reported.

## Notes

- The violating commits since `39885b87` were written by the coordinator's helper scripts in the v0.3
  dev-loop (`--amend --trailer` after `memory approve`); the scripts were corrected on 2026-10-09. The pushed
  commits cannot be rewritten (`git-conventions` §2 and §8 forbid rewriting approve/reject records), so the
  check needs a cut-off: only commits after the one that introduces the check, as the governance check
  already does with its introduction commit.
