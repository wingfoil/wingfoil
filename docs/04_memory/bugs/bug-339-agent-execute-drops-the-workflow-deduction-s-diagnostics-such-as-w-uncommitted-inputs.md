## Summary

`agent execute --next|--workflow|--step` deduces its step with `workflow next`'s deduction
(`readNextAtHead`), whose result carries `diagnostics`, but never reports them, so the user is not told, for example,
that the step was deduced from `HEAD` while the working tree differs (`W_UNCOMMITTED_INPUTS`).

## Steps to Reproduce

On `main` at `29b8406a`:

1. `sed -n 496,526p src/agent/execute.ts`: `deduced = readNextAtHead(…)`; only `deduced.value.baseline.commit`,
   `deduced.value.instance` and `selectFrontierStep(deduced.value, …)` are read.
2. `grep -n "diagnostics" src/agent/execute.ts` → no match on the deduction; the positive case, `grep -n
   "reportWarning" src/agent/execute.ts`, matches the adapter-tree diagnostics it does report (line 512).
3. `node dist/cli.js workflow next` on this branch reports `85 diagnostic(s): --format json lists them`, which an
   `agent execute --next` on the same state does not mention.

## Expected Behavior

`agent execute` reports the deduction's warning diagnostics on stderr (or a count with a pointer, as `workflow
next` does) before launching the agent.

## Actual Behavior

As in steps 1–2.
