## Summary

`publish.yml`'s `mcp-registry` job pins `mcp-publisher` by version and archive SHA-256, but nothing proposes a pin
update (no Dependabot configuration exists), and the signature bundle published with the release's checksums file
is not verified.

## Steps to Reproduce

On `main` at `0da232cb`:

1. `sed -n 318,319p .github/workflows/publish.yml` → `MCP_PUBLISHER_VERSION: '1.8.1'` and `MCP_PUBLISHER_SHA256`.
2. `sed -n 331,333p .github/workflows/publish.yml` → the archive is downloaded and checked with `sha256sum --check
   --strict` against the pinned hash; no signature is checked.
3. `ls .github` → `ISSUE_TEMPLATE`, `PULL_REQUEST_TEMPLATE.md`, `workflows`: no `dependabot.yml`, so neither the
   action pins nor this pin get an update proposal.

## Expected Behavior

A documented update path for the pin (and the action pins), and the checksums file's signature bundle verified
before the hash is trusted.

## Actual Behavior

As in steps 1–3. The SHA pin itself is sound: a changed archive fails the job.
