## Summary

`checkTranscript` (`scripts/publish-staging.cjs`, the `--check-transcript` gate that `task-282` made strict for
`bug-311`) checks only lines that carry the `[publish:staging] ` prefix as version-check lines. A line without the
prefix that names another version or another sha is not examined, so a transcript can hold an unprefixed version line
naming a foreign sha and still pass.

## Steps to Reproduce

On `main` at `327a7b01`:

1. `grep -n "const VERSION_LINE_RE\|const VERSION_CHECK_RE\|const LOG_PREFIX" scripts/publish-staging.cjs` → both
   version patterns are anchored on `^\[publish:staging\] `.
2. `grep -n "function checkTranscript" -A30 scripts/publish-staging.cjs` → only lines matching `VERSION_LINE_RE` are
   checked for the version and the sha; the closing line and the failure scan are the other checks. A line such as
   `ok wingfoil --version = 0.0.1 (<another full sha>) — match` without the prefix matches none of them.
3. With `node -e` on `require('./scripts/publish-staging.cjs')`: a transcript of one prefixed line `ok wingfoil
   --version = 0.2.2 (<sha a>) — match`, one unprefixed line `ok wingfoil --version = 0.0.1 (<sha b>) — match` and the
   prefixed `stagingPassedLine('wingfoil', '0.2.2')` → `checkTranscript(…, { name: 'wingfoil', version: '0.2.2' })`
   returns `{ ok: true, commit: <sha a> }`.

## Expected Behavior

Any non-empty transcript line that does not start with `LOG_PREFIX` is refused, so the transcript proves exactly the
run the script wrote.

## Actual Behavior

Unprefixed lines are ignored. Low: the transcript is the script's own output, and the shapes `bug-311` named are
refused.
