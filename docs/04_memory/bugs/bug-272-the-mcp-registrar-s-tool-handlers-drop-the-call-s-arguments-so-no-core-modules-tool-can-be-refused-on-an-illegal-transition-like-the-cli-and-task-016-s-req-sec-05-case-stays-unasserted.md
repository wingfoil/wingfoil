## Summary

`task-016`'s REQ-SEC-05 acceptance case, "an MCP Tool call attempting an illegal state-machine transition is rejected
identically to the equivalent CLI path", is still unasserted: every `callTool` test drives a synthetic op or a stub,
and the production server registers no Tool. It also cannot be asserted as things stand, which the follow-up list
did not say: `registerCoreModules` (`src/mcp/registrar.ts`) registers each mutating op as a Tool with no input schema
and a handler that takes no arguments, and calls the op with `buildParams({moduleName, operationName, root})` only. A Tool call therefore
never names an element, and a real `memory.approve` Tool answers "missing required argument: <id>", whatever it is
sent.

## Steps to Reproduce

On `main` at `f15096a2`, code build (`npm ci && npm run build`):

1. `grep -n 'server.registerTool' src/mcp/registrar.ts` → line 112: the Tool is registered with a description and
   no `inputSchema`, and its handler is `async () => { const outcome = await callCore(); ... }`, so the SDK hands it
   no arguments and `callCore` builds the op's params from `buildParams` alone.
2. `grep -rn 'callTool' test/mcp/*.ts` → `registrar.test.ts` and `error-details.test.ts` call `memory.approve` with
   `arguments: {}` over fixture modules whose ops return canned results ("illegal transition: draft to approved");
   `read-only-agent-channel.test.ts` calls a synthetic `x.write`; `server.test.ts` gets "Tool dna.set not found"
   from the production server, which answers `tools/list` with `[]` (`src/mcp/server.ts`, `bug-151`).
3. Scratch repository (`git init`, `node dist/cli.js init --template Scrum`, `node dist/cli.js memory add --type bug
   --title probe` → `bug-001-probe`, `draft`). A Node script wires `registerCoreModules(server, CORE_MODULES,
   {resolveRoot, buildParams: (c) => ({root: c.root})})` (from `dist/mcp/registrar.js` and `dist/core/index.js`,
   the same wiring as `connectCoreModuleSurface` in `test/mcp/helpers/channel-enumeration.ts`) over the SDK's
   in-memory transport:
   - `listTools()` → 14 Tools, `directive.assign` ... `memory.submit`, `memory.approve` among them;
   - `callTool({name: 'memory.approve', arguments: {id: 'bug-001-probe', reason: 'x'}})` → `isError: true`, text
     `missing required argument: <id>`.
4. The CLI on the same element: `node dist/cli.js memory approve bug-001-probe --reason x` → exit 1, `error:
   illegal transition draft -> (none) for type 'bug'`, plus the detail line naming the document and "illegal
   `approve` from "draft": not a `gates` state".

## Expected Behavior

A Tool call's arguments reach the operation (mapped to the same params the CLI registrar builds), and a test drives
a real `CORE_MODULES` mutating Tool into an illegal transition and asserts the refusal text and details equal the
CLI's, and that nothing is persisted (shared snapshot), as `task-016`'s AC and REQ-SEC-05 state.

## Actual Behavior

The Tool path refuses every real call for a missing argument before any state-machine check, so the REQ-SEC-05
parity of illegal-transition refusals is neither met nor tested on the Tool channel.
