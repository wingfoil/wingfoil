## Summary

The P4.17 / REQ-SEC-10 integrity check of a built-in workflow template, `isValidWorkflowSource`
(`src/core/builtin-integrity.ts`), runs the `Workflow` schema and the loader's per-file diagnostics
(`workflowFileDiagnostics`) but not the core checks `task-194` added (`workflowCoreDiagnostics`,
`src/core/workflow-core-checks.ts`: `E_PHASE_ROLE_UNKNOWN`, `E_PHASE_APPROVER_UNKNOWN`,
`E_WORKFLOW_ELEMENT_TYPE_UNKNOWN`, `E_WORKFLOW_COLLECTION_UNRESOLVED`, `E_PHASE_CADENCE_EVENT_UNKNOWN`), which the
workflow registry runs against `dna.yaml` and `memory.yaml` at `HEAD`. A built-in template naming a role or a Memory
type the scaffolded configuration does not declare passes the integrity check and is then refused by every
workflow command that loads the registry. This is the class of `bug-183`, which `task-196` closed for the
per-file rules only.

## Steps to Reproduce

On `main` at `0962f85f`:

1. `grep -n workflowFileDiagnostics src/core/builtin-integrity.ts` → the import and the call in
   `isValidWorkflowSource` (`return !workflowFileDiagnostics(loaded, index, 0).some(…)`).
2. `grep -n workflowCoreDiagnostics src/core/builtin-integrity.ts` → nothing (exit 1); the same pattern over `src`
   finds the registry's call, `src/core/workflow-registry.ts` (`const core = workflowCoreDiagnostics(`), so the
   pattern matches where the checks do run.
3. The core checks refuse what the integrity check lets through: in a scratch repository (`node dist/cli.js init
   --template Scrum`), a committed workflow phase with `role: nonexistent-role` makes `node dist/cli.js workflow list`
   exit 1 with `error: E_PHASE_ROLE_UNKNOWN phases[0].role (workflows/custom/bug-ingest.yaml): unknown role
   'nonexistent-role' (not defined in dna.yaml)`, a rule `isValidWorkflowSource` never applies.

## Expected Behavior

A built-in workflow template that passes its integrity check also loads in the project it is installed into: the
check applies the core rows too, against the configuration the template is installed with (for `init`, the
scaffolded `dna.yaml` and `memory.yaml`), and refuses with the P4.17 message before anything is written.

## Actual Behavior

Only the schema and the per-file rows are applied; a template that fails a core row is installed and then refused
by the registry.

## Notes

- Low and latent: no built-in workflow template ships today. The scaffold writes only
  `.wingfoil/workflows/built-in/.gitkeep` (`grep -n BUILTIN_WORKFLOWS_DIR src/storage/templates.ts` → the
  `.gitkeep` entry and the directory classifier), so nothing reaches this path until one does.
- The fix has to choose what the template is judged against: the core rows read a project's roles and types, and a
  built-in template is shipped for every project. Judging it against the scaffold `init` writes is the natural
  reading; a template installed into an existing project with other roles is a separate question.
