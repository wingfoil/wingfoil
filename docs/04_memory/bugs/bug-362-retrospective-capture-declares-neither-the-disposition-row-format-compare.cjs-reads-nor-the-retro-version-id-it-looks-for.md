## Summary

`compare.cjs` reads the dispositions of the previous release's health proposals from a table in a decision-log with
id `retro-<version>`, but `retrospective.yaml`'s `capture` phase states neither that table's format nor that id: its
action `memory.add(type: decision-log, title: "Retrospective {release.version}")` allocates a `dl-<n>-<slug>` id, while
its `produces:` names `retro-{release.version}.md`.

## Steps to Reproduce

On `main` at `bd55f70e`:

1. `sed -n 103,116p .wingfoil/workflows/custom/retrospective.yaml` → `capture`'s description says the `## Release
   health` section holds "the disposition of every RH proposal" with no format; its action is `memory.add(type:
   decision-log, title: "Retrospective {release.version}")`; its `produces:` is
   `docs/04_memory/design/dls/retro-{release.version}.md`.
2. `grep -n id_pattern .wingfoil/memory.yaml` → the `decision-log` type's `id_pattern` is `dl-{n}-{slug}`, so the
   action allocates `dl-<n>-retrospective-v0-3`, not `retro-v0.3`.
3. `sed -n 726,729p scripts/release-health/compare.cjs` → `retroPath` is the decision-log path pattern with `{id}`
   replaced by `retro-${previous.release.version}`; `dispositions()` (line 466) reads the rows.
4. `sed -n 83,99p docs/08_health/report-layout.md` → the row format (`| Proposal | Outcome | Element |`, the RH id,
   the outcome, the linked element) is declared only there.

## Expected Behavior

`capture` declares the disposition table's format (or points at `report-layout.md`) and produces the document under
the id `compare.cjs` reads, through an `id_pattern` or a declared id, so that a retrospective written by following the
workflow is read back by the next release's comparison.

## Actual Behavior

A retrospective written by following `capture` is a `dl-<n>-…` document whose table format is undeclared there;
`compare.cjs` then finds no retrospective and settles every proposal as "no disposition recorded".
