## Summary

For a selection phase whose action is `memory.approve`, `workflow next` prints one `wingfoil memory approve` command
naming every element the selection matches, including elements whose current state has no approve edge in their
type's machine. Running the printed command fails with `illegal transition <state> -> (none)`, so a phase that selects
such elements can never be completed with the command the engine offers.

## Steps to Reproduce

1. In a scratch clone of `main` at `4028a1df1`, record `release-planning.advance-pinned-build@release:minor-v1.0` with
   `workflow finalize` so that `reconcile-governance@release:minor-v1.0` reaches the frontier.
2. `workflow next sw-life-cycle-1-plan` prints `wingfoil memory approve` with 13 decision-logs, 10 of them `ready`
   (same on the pinned 0.3.2 and the code build).
3. `memory approve dl-125-… --dry-run` on one of the `ready` ones → `illegal transition ready -> (none)`, exit 1.
4. The same holds for `triage-bugs` with a `where` that matches `triaged` bugs: the printed approve fails on each.

## Expected Behavior

The command `workflow next` prints for a `memory.approve` action names only the selected elements in a state that has
an approve edge (a gate in their type's `gates`); the others are reported apart (or the phase's evidence says why they
need no approve), so the printed command succeeds as printed.

## Actual Behavior

Every matched element is listed, and the command fails on the first one already past its gate.
