## Summary

Since `task-312` (`bug-316`), `wingfoil paths <category>` answers a category declared by hand in `dna.yaml` `paths:`
as a list of paths, besides the seven the schema names. The command's help still describes `<category>` as only
"sources, tests, docs, config, governance, runs or health", so a reader of `--help` cannot learn that an extra
category is accepted. `docs/cli-reference.md` `wingfoil paths` was aligned in v0.3.2's `user-docs` phase; the help
text, generated from `src/core/index.ts`, was not.

## Steps to Reproduce

With the code build of `main` at `1db90b57f` (`npm run build`):

1. `node dist/cli.js paths --help` → `category    sources, tests, docs, config, governance, runs or health (omit it
   for the whole map)`.
2. `grep -n "governance, runs or health" src/core/index.ts` → line 2970, the `positional` description.
3. In a throwaway project (`git init`, `wingfoil init --template Scrum`), add `extras: [ "notes/" ]` under
   `paths:` in `.wingfoil/dna.yaml`, then `node <repo>/dist/cli.js paths extras` → `{"category": "extras",
   "paths": ["notes/"]}`, exit 0.
4. `sed -n 447,451p docs/cli-reference.md` → "New in 0.3.2: a category of your own, declared by hand in `dna.yaml`
   `paths:` as a list of paths and committed, is answered too".

## Expected Behavior

The `category` description in `paths --help` names the seven categories and says that a category declared in
`dna.yaml` `paths:` is answered too, matching `docs/cli-reference.md`.

## Actual Behavior

The help lists only the seven categories.
