## Summary

After `npm stage approve` on `wingfoil@0.3.1`, `npm view` reported the version about 4 minutes before the registry
served its tarball. `npm install` failed with `E404` on the tarball URL in that window. Every post-publish wait reads
`npm view`:
- the plan's install check (`release-publishing-rel-v0.3.1-plan` S7);
- `scripts/wait-npm-version.cjs`, which `publish.yml`'s `release` and `mcp-registry` jobs and `pages.yml` run before
  they announce the version.

So the GitHub Release, the MCP Registry listing and the Pages deploy went out for a version a user could not yet
install. That is the case the script says it exists to prevent.

## Expected Behavior

- A post-publish wait succeeds only when the version can be installed: when `npm view wingfoil@<v> dist.tarball`
  names a URL that answers 200, not only when `npm view` reports the version.
- The S7 install check of `release-publishing` waits for the same condition before `npm install`.

## Actual Behavior

The install check failed once and passed on retry, by hand. The CI jobs created the Release, the MCP Registry listing
and the Pages deploy during the window. `release-publishing.yaml`'s `publish` post-check is prose ("live on the npm
registry", `grep -n "live on the npm registry" .wingfoil/workflows/custom/release-publishing.yaml` → line 124) and
does not say which signal means "live".

## Notes

- Proposal from the phase's retrospective (`grep -n "tarball URL" docs/05_plans/rl-v1/rel-v0.3.1/*.md`): the S7
  install check waits for the tarball URL (`curl` 200), not for `npm view`. The CI wait is the same class.
  `wait-npm-version.cjs` can read `dist.tarball` from the same `npm view` call and probe it, so one change covers the
  three jobs.
- The runbook in `publish.yml`'s header (`grep -n "stage approve" .github/workflows/publish.yml` → lines 120, 130)
  and the `publish` phase text (`release-publishing.yaml` lines 91–114) describe the approval. Neither mentions the
  propagation delay.
- One observation (one publish). The delay is npm's and may vary. The fix bounds the wait; it does not assume the
  delay's length.
- Related: `bug-174` (the runbook and npm's automated review before approve), `dl-130` (steps 1–2: the Release and
  Registry jobs poll npm), `adr-011` (staged publish).
