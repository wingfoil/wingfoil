## Summary

`Produces` and the phase `approval` in `src/workflow/schema.ts` are zod unions of `.strict()` object branches, and
neither has an `error:` option. An unknown key in either therefore reports zod's built-in message. With zod 4.4.3,
which the lock held until `task-304` (850e9ea2), the message was `Invalid input`. With zod 4.6.x, the version now
installed, it is `Unrecognized key: "x"`. The path is the same in both. No spec, test or document pins either text,
so a zod minor update silently changes a user-facing `E_VALIDATION` message. This is the same class as the
`cadence` message that `task-304` made independent of zod (`bug-415`).

## Expected Behavior

The two messages are WingFoil's own, like the `cadence` message (`cadenceShapeMessage`) and the `kind` message: an
`error:` option on each union that names the unknown key and the accepted shapes. A test pins them, so a zod update
cannot change them.

## Actual Behavior

The text is whatever the installed zod minor produces. It changed with `task-304`'s lock refresh, and the change was
caught only because a reviewer read the output.
