## Summary

When any workflow file fails to load, `workflow list` (and `workflow status`) exits 1 without listing the workflows
that do load; the refusals are reported, but the valid workflows disappear with them. Reproduced on 0.3.2.

## Steps to Reproduce

In a throwaway repository on the pinned build (`npm run -s wingfoil --`, 0.3.2):

1. `init --template Kanban --no-interactive`.
2. In the scaffold's main workflow, write a phase `include:` as a file path (as 0.2.x's `init` wrote it); commit.
3. `workflow list` → exit 1, the message names the workflow and the upgrade section (`bug-394`).
4. Also give another workflow (`bug-ingest`) a prose `produces` entry; commit; `workflow list` → both refusals are
   reported, and no workflow is listed.

## Expected Behavior

`workflow list` lists every workflow that loads, and reports each refused one as a diagnostic of that workflow
(file, key, fix), exiting non-zero only to signal the diagnostics; `workflow status` keeps showing the open runs of
the workflows that load.

## Actual Behavior

Exit 1 with the refusals and an empty listing; on a project made by 0.2.x this hides every workflow until the
configuration is hand-edited (svc-019 F-029: `workflow list` and `workflow status` fail while `dna show`, `memory
search` and `directives list` succeed).
