## Summary

A phase plan's `parent` is `"<workflow>.<phase>"` (spec-017 §3.1, the plan template's comment), but nothing checks
that the named phase exists in that workflow: the engine only tests whether `parent` is empty (an instance) or not.
The value is written by hand on every phase plan opened with `memory add --type plan`, and four plans have drifted:
v0.3's and v0.3.1's `release-submit` and `release-publishing` plans declare `parent: "release-cycle.release-submit"`
and `"release-cycle.release-publishing"`, while `release-cycle.yaml` names those phases `submit` and `publishing`.
v0.3.2's plans use the right names, so the error is invisible until a reader or a tool resolves the value.

## Steps to Reproduce

From the repository root on `main` (`1db90b57f`):

1. `grep -H "^parent:" docs/05_plans/rl-v1/rel-v0.3/release-{submit,publishing}-rel-v0.3-plan.md
   docs/05_plans/rl-v1/rel-v0.3.1/release-{submit,publishing}-rel-v0.3.1-plan.md` →
   `"release-cycle.release-submit"` twice and `"release-cycle.release-publishing"` twice.
2. `grep -n '  - name:' .wingfoil/workflows/custom/release-cycle.yaml` → `planning`, `implementation`, `user-docs`,
   `e2e-smoke`, `submit`, `publishing`, `release-health`, `retrospective`: no `release-submit`, no
   `release-publishing`.
3. `grep -H "^parent:" docs/05_plans/rl-v1/rel-v0.3.2/release-{submit,publishing}-rel-v0.3.2-plan.md` →
   `"release-cycle.submit"`, `"release-cycle.publishing"`.
4. `grep -rn "parent" src/workflow/deduce.ts src/core/workflow-start-end.ts` → only the emptiness test that tells an
   instance from a phase plan.

## Expected Behavior

`memory submit` of a plan (or a validation the plan type declares) refuses a non-empty `parent` that does not name a
phase of the named workflow, with the workflow's phase names in the message, exit 1 and nothing written. The four plans
are corrected by the approver's `memory amend` of their `parent` field.

## Actual Behavior

Any string is accepted, and four `done` plans name phases that do not exist.
