## Summary

`.github/workflows/pages.yml` pins `actions/jekyll-build-pages` to a full commit SHA, as `dl-057`'s pinning rule asks,
but that action is a docker action whose `action.yml` runs `docker://ghcr.io/actions/jekyll-build-pages:v1.0.13`, a
mutable image tag: the SHA pin does not pin the code that builds the site.

## Steps to Reproduce

On `main` at `bd55f70e`:

1. `sed -n 72p .github/workflows/pages.yml` → `uses:
   actions/jekyll-build-pages@44a6e6beabd48582f863aeeb6cb2151cc1716697 # v1.0.13`; line 28 states the rule "Every
   `uses:` names a full commit SHA, with the release tag it came from in a trailing comment (dl-057)".
2. `gh api 'repos/actions/jekyll-build-pages/contents/action.yml?ref=44a6e6beabd48582f863aeeb6cb2151cc1716697' --jq
   .content | base64 -d` → `using: 'docker'`, `image: 'docker://ghcr.io/actions/jekyll-build-pages:v1.0.13'`.
3. `dl-057` option (a) 1 (`grep -n "Pin every action" docs/04_memory/design/dls/dl-057-*.md` → line 78) pins actions
   to commits and says nothing of the images a docker action pulls.

## Expected Behavior

The pinning rule covers what a pinned action executes: a docker action's image is pinned by digest (for example a
step that runs the image `@sha256:<digest>` itself, or an action whose `action.yml` names a digest), or the exception
is recorded in `pages.yml` and in `dl-057`.

## Actual Behavior

Whoever can move the `v1.0.13` tag on the registry changes what builds the published site, with no change in this
repository.
