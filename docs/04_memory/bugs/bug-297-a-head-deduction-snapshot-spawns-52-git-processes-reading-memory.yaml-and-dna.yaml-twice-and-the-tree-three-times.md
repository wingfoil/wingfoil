## Summary

`readDeductionSnapshotAtHead` (`src/core`, `task-198`) builds one snapshot of `HEAD` for workflow deduction, and in
doing so spawns 52 git processes on this repository. Most of them repeat work: the workflow registry load
(`loadWorkflowRegistryAtRev`, `task-194`) issues one `git cat-file --batch` per configuration file, 26 in all, where
one batch could answer every path; `.wingfoil/memory.yaml` and `.wingfoil/dna.yaml` are each read twice with `git
show` (once by the registry's core checks, once by the snapshot); the tree is listed three times with `git ls-tree
-r`; and the revision is resolved with `git rev-parse --verify` eight times. Each spawn costs a process start, and
REQ-PERF-03 gives `workflow next`, which will read this snapshot, 1,000 ms p95.

## Steps to Reproduce

On `main` at `c485e433` (`npm ci && npm run build`), from the repository root:

1. `GIT_TRACE=<file> node -e "require('./dist/core').readDeductionSnapshotAtHead(process.cwd())"`, then counting the
   `trace: built-in: git <cmd>` lines → 52: `cat-file --batch` 27, `show` 11, `rev-parse --verify` 8, `ls-tree -r` 3,
   `log` 2, `status --porcelain` 1.
2. The `show` lines name `.wingfoil/memory.yaml` and `.wingfoil/dna.yaml` twice each, and the seven Memory templates
   once; the `ls-tree` lines are `-- docs/04_memory`, `-- docs/05_plans` and the whole tree.
3. The same trace around `loadWorkflowRegistryAtRev(root, <HEAD sha>)` alone → 40: `cat-file` 26, `show` 9,
   `rev-parse` 5.
4. Three runs of the snapshot, timed in-process with `process.hrtime.bigint()` → 2994, 3068 and 2271 ms, at load
   average 18 (`uptime`); `task-198`'s review measured 2.4–6.7 s under load and 47 spawns before `task-264` and
   `task-220` merged.

## Expected Behavior

One snapshot reads each object once: a single `cat-file --batch` for the registry's files (as `readPathsAtRev`
already does for a list of paths), `memory.yaml` and `dna.yaml` read once and passed to the core checks, one tree
listing filtered in memory, and the revision resolved once. `task-216`'s REQ-PERF-03 timing test then has margin
on an ordinary machine.

## Actual Behavior

52 spawns per snapshot, more than half of them avoidable, and a snapshot time of seconds on a loaded machine.
