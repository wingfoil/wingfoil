## Summary

Loading the compiled `core/agent-execute` module before the `core` barrel leaves `agentExecute` and `agentList` without their `fn` in `CORE_MODULES`, because the module graph closes a cycle back into `core/index` while that barrel is still initialising.

## Steps to Reproduce

1. On `release/0.3` at `6ba2169eb`, `npm ci` and `npm run build`.
2. `node -e 'require("./dist/core/agent-execute"); const c=require("./dist/core"); const m=c.CORE_MODULES.find(x=>x.name==="agent"); console.log(Object.values(m.operations).map(o=>o.name+":"+typeof o.fn).join(" "))'`
   prints `agentExecute:undefined agentList:undefined agentShow:function`.
3. The same with the two `require` calls swapped prints `agentExecute:function agentList:function agentShow:function`.

## Expected Behavior

Every operation in `CORE_MODULES` has its `fn` whichever module of `src/core` is loaded first: the result of step 2 equals the result of step 3.

## Actual Behavior

With `core/agent-execute` loaded first, `CORE_MODULES.agent`'s `agentExecute` and `agentList` operations have no `fn` (step 2). The require chain, traced by the reviewer of task-332: `core/agent-execute → agent/execute → core/agent-list → agent/run-log → core/write-guard → memory/index → memory/audit → core/index` — `src/memory/audit.ts` l.32 imports `isConfiguredIdentity` from `../core` (the barrel), which is still loading.

## Notes

Found by task-332's red (qa): `test/core/element-short-reference.test.ts` must import `src/core` before `src/core/agent-execute`, otherwise its `agent list` case fails with `operation.fn is not a function`. Its reviewer confirmed the cycle is pre-existing on `release/0.3` (task-332's new `src/memory/reference.ts` adds no runtime edge) and that no production entry is affected: `src/cli.ts`, `package.json` `main` (`dist/core/index.js`) and the MCP server all load the barrel first. So the defect is a test-ordering hazard. Suspected fix: `src/memory/audit.ts` imports `isConfiguredIdentity` from `core/git-identity` rather than from the barrel; a test that loads `core/agent-execute` first and checks every operation's `fn` pins it.
