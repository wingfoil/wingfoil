## Summary

The pinned build `wingfoil-released` 0.3.0 (`dl-095`) requires `run` on every check binding of
`.wingfoil/workflows/bindings.yaml`, so it refuses the `{ manual: true }` check binding `dl-172` (a) adds (`task-298`
binds `demo.rendered` that way). From `task-298`'s merge on, the pinned build cannot load this repository's
workflows: `workflow list`, `show`, `next`, `status` and the MCP Resources `wingfoil://workflows`, `-/next` and
`-/status` fail on `release/0.3` until `advance-pinned-build` moves the pin to a build that reads the form (0.3.1).
The same forward-compatibility case as `bug-292` for 0.2.2 and the `{ type, path }` produces entry (`dl-104` D3).

## Steps to Reproduce

On `task/task-298-let-a-workflow-check-be-bound-manual-dl-172` at `b8aab79c` (the binding committed in
`342ba597`), 2026-10-25:

1. `npm run -s wingfoil -- --version` → `0.3.0 (cc31d7a8…)`, the version `package.json` pins for
   `wingfoil-released`.
2. `npm run -s wingfoil -- workflow list` → exit 1, `error: E_VALIDATION checks.demo.rendered.run
   (workflows/bindings.yaml): Invalid input: expected array, received undefined`.
3. `node dist/cli.js workflow list` (the code build, `0.3.0 (b8aab79c…)`) → exit 0.
4. `npm run -s check:mcp` → exit 0 with three `known failure` lines, one per Resource
   (`wingfoil://workflows`, `-/next`, `-/status`), declared in `scripts/check-mcp-registration.cjs`
   `KNOWN_READ_FAILURES` for version 0.3.0.

## Expected Behavior

The pinned build reads every configuration form the repository uses, or a read it cannot run is recorded by a
`pinned-build` bug the `wingfoil-cli` directive §2/§3 and `advance-pinned-build` can find. This bug is that record:
it closes when the pin reaches a build that loads a `{ manual: true }` check binding, at which point the three
`KNOWN_READ_FAILURES` entries and the directive's exception are removed (`check:mcp` fails until they are).

## Actual Behavior

The pinned 0.3.0 refuses the binding with `E_VALIDATION`, so the workflow reads and the three MCP Resources fail on
the pinned build; the reads run on the code build in the meantime (`wingfoil-cli` 1.3 §1, AGENTS.md §3).
