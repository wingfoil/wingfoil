## Summary

A `.jsonl` committed as a symbolic link in the run-log directory is read by `agent list`'s readers as a run log
whose text is the link's target path, and is refused as "not JSON" instead of being reported as a link.

## Steps to Reproduce

On `main` at `0da232cb`:

1. `sed -n 369,388p src/agent/run-log.ts` (`readRunLogsAt`) → the directory is listed with `listPathsAtCommit`
   and each path read with `readPathAtRev`; `sed -n 326,336p src/agent/run-log.ts` (`readRunLogAt`) reads the same
   way. Neither knows a blob's kind.
2. `sed -n 101,114p src/core/revision.ts` → `listBlobEntriesAtCommit` returns each blob with its kind, "so that a
   symbolic link is known as one rather than read as a document whose text is the link's target" (`task-171`,
   `bug-189`), and the Memory scan already uses it (`grep -n listBlobEntriesAtCommit src/memory/query.ts`).

## Expected Behavior

The run-log readers list with `listBlobEntriesAtCommit` and refuse (or skip, with a diagnostic) a symbolic link by
name, as the Memory scan does.

## Actual Behavior

A committed `<runs>/<id>.jsonl` symlink fails strict parsing with a "not JSON" message about its target's path.
