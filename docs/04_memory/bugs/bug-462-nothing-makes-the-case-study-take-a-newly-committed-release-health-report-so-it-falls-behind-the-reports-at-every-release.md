## Summary
The case study (`docs/case-study.md`) shows the figures of the committed release-health reports, and `presentation.current`
(`test/docs/presentation.test.ts`, bound in `.wingfoil/workflows/bindings.yaml`) checks it against them. But no phase or check makes
the case study take a report that is committed after it: `release-health` commits `docs/08_health/release-health-<version>.json`
after `user-docs` has run in the same release cycle, and `release-health.yaml` names no hand-off to the case study
(`grep -n "case-study" .wingfoil/workflows/custom/release-health.yaml` → nothing). So the case study falls one report behind at every
release, which is how `bug-432` arose (the v0.3 report committed, the page showing v0.1 and v0.2 only).

## Steps to Reproduce
1. On `release/0.3` at `ab691d35`: `ls docs/08_health/release-health-v*.json` lists the v0.1, v0.2, v0.3 and v0.3.1 reports;
   `docs/case-study.md` shows v0.1 and v0.2 only (`bug-432`).
2. `grep -n "case-study" .wingfoil/workflows/custom/release-health.yaml` → no line; `grep -n "case-study"
   .wingfoil/workflows/custom/user-docs.yaml` → the case study is an output of `align-user-docs` only (line 57), checked by
   `presentation.current` (line 61).
3. `task-322` (w2 of `patch-v0.3.2`) makes `presentation.test` read an explicit list of the four reports (approver ruling D2 (a) at its
   design gate), so a fifth report committed by a later `release-health` leaves the test green and the page behind.

## Expected Behavior
A declared hand-off: a newly committed release-health report is taken into the case study by the next `align-user-docs` (or by
`release-health` itself), with a check that fails while a committed report is missing from the page — for example a check in
`align-user-docs` that every `docs/08_health/release-health-v*.json` reached from the integration branch is shown, or a
`release-health` step that updates the case study and its report list.

## Actual Behavior
Nothing names the hand-off; the case study and `presentation.test`'s report list are updated only when a task is filed for them.
