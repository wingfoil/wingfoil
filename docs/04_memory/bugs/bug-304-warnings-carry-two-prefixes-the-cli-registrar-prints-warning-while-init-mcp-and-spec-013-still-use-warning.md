## Summary

Since `task-218` (W3 B3, `bug-202`), a warning raised inside a CLI operation goes through the registrar's warning
sink and prints `warning: <text>` (console), beside `error: `. A warning raised outside that sink still prints the
old `Warning: <text>` (`reportWarning`'s fallback, `src/validation/warning.ts`): `wingfoil init` and `wingfoil
mcp` are wired outside the registrar, so the same loader warning reads `warning:` on `dna show` and `Warning:` on
`mcp`. `spec-013` § "`version`" still documents the directive loader's warnings as "`Warning: <file>: …`".

## Steps to Reproduce

1. In a scratch project (`GIT_CONFIG_GLOBAL=/dev/null`, `node dist/cli.js init --template Scrum`) built from
   `main` at `02121a96`, append `probe_unknown_key: 1` to `.wingfoil/dna.yaml` and commit.
2. `node dist/cli.js dna show 2>&1 >/dev/null` → `warning: .wingfoil/dna.yaml: unknown field(s) ignored:
   probe_unknown_key`.
3. `timeout 10 node dist/cli.js mcp </dev/null 2>&1 >/dev/null` → `Warning: .wingfoil/dna.yaml: unknown field(s)
   ignored: probe_unknown_key` (exit 0).
4. `grep -n 'Warning: <file>' docs/04_memory/design/specs/spec-013-directive-frontmatter-schema.md` → the
   `version` section: "These warnings are spec-009 §2 stderr warnings (`Warning: <file>: …`)".
5. `grep -n "withWarningSink" -r src` → installed only by `src/cli/registrar.ts`.

## Expected Behavior

One console prefix for a warning on every command, `warning: ` (`spec-008` §6 as amended by `task-218`), and
`spec-013` saying so; or a declared exception for the commands outside the registrar, stated in `spec-008` §6.

## Actual Behavior

Two prefixes, chosen by whether the command runs under the registrar (steps 2–3), and `spec-013` documents the
one that operations no longer print.
