## Summary

`wingfoil agent execute` runs an `interactive` agent with `stdio: 'inherit'` and no process group of its own
(`src/agent/launch.ts`, `spawnOptions`), so the agent shares `agent execute`'s foreground process group. On
`--timeout` and on a forwarded `SIGTERM`, `takeOverSignals`' `send` calls `child.kill(signal)`, which reaches the
agent's pid only. A child the interactive agent started (a shell, a tool server) is not signalled and can outlive the
run, as `bug-516` describes for headless runs. The group cannot be signalled instead, because it holds
`agent execute` itself.

## Steps to Reproduce

1. `grep -n "kind === 'interactive'" src/agent/launch.ts` → `{ cwd: root, stdio: 'inherit', env: process.env }`, no
   `detached`.
2. `grep -n "child.kill(signal)" src/agent/launch.ts` → the only delivery path of a forwarded signal or a timeout.
3. Launch an interactive adapter whose agent spawns a long-lived child, with a short `--timeout`: after the run ends
   the child is still listed by `ps -eo pid,ppid,args`.

## Expected Behavior

Either spec-016 states it as a known limit of an interactive run (the user guide says so too), or the interactive
agent gets a process group of its own while keeping the terminal (foreground group handed over and taken back), so
a timeout or a forwarded signal reaches the agent's whole group.

## Actual Behavior

Only the agent's pid receives the signal; its children are left running, and nothing in spec-016 or the user guide
says so.
