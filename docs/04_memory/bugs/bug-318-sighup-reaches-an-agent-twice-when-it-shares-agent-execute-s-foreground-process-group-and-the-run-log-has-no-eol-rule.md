## Summary

When the terminal hangs up, an interactive agent launched by `agent execute` receives `SIGHUP` twice: once from the
kernel, because it shares `agent execute`'s foreground process group, and once forwarded by `agent execute`, which
`spec-016-agent-execution` §3.3 step 15 assumes does not happen; and the committed run log
(`*.jsonl`) has no `.gitattributes` rule fixing its line endings.

## Steps to Reproduce

1. `spec-016` §3.3 step 15 ("**Signals.** Interactive launch: … **forwards** only `SIGTERM` and `SIGHUP`, which do not
   come from the keyboard"): it treats `SIGHUP` like `SIGTERM`, an external signal reaching `agent execute` alone.
2. `task-228`'s independent review (2026-10-10) drove the fake agent (`test/fixtures/agents/fake-agent.cjs`) under a
   real process group and recorded two `SIGHUP` deliveries in one run (`rec-b-double.jsonl` in the review scratch):
   a hang-up is delivered by the kernel to the whole foreground process group, which includes the agent.
3. `ls .gitattributes` at `main` `02800955` → no such file; the run log under `dna.yaml` `paths.runs` is committed
   JSON Lines.

## Expected Behavior

`agent execute` does not forward a `SIGHUP` the agent already received from the kernel (or `spec-016` states that the
agent may receive it twice and the fake agent pins it), and `.gitattributes` declares `*.jsonl text eol=lf`, so a
checkout on a CRLF platform does not rewrite committed run records.

## Actual Behavior

Two `SIGHUP`s; no eol rule.
