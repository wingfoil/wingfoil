## Summary

`spec-016`'s "Revision triggers" says "A new manifest field bumps `format`", and the comment on
`ADAPTER_MANIFEST_FORMAT` in `src/agent/schema.ts` says the same. `dl-149` (`ready`) rules the opposite: "Additive,
optional fields do not bump it." The repository follows `dl-149`: `task-335` added `launch.headless` and `task-356`
added `mcp.conflict_args` and `output: jsonl` without a bump (`task-356` ruling D7).

## Steps to Reproduce

1. `grep -n "bumps \`format\`" docs/04_memory/design/specs/spec-016-agent-execution.md` → the "Revision triggers"
   bullet (line 1116 at `task-356`'s head).
2. `grep -n "A new manifest field bumps it" src/agent/schema.ts` → the comment above `ADAPTER_MANIFEST_FORMAT`.
3. `grep -n "Additive, optional fields" docs/04_memory/design/dls/dl-149-*.md` → line 54.

## Expected Behavior

Both texts state `dl-149`'s rule: the manifest `format` is bumped only on a backward-incompatible change; an additive,
optional field does not bump it.

## Actual Behavior

The spec and the code comment state a rule the project does not follow, so a reader of either would bump `format` on
the next additive field and break every older build's read of the manifests.

## Notes

Pre-existing; found by the review of `task-356` (finding 4). A `spec-016` amendment plus a one-line comment change.
