## Summary

Since `task-256`, a `dna.yaml` `team.agents` entry's `name` and `email` are the identity `git-conventions` §7
writes as `Co-Authored-By: <name> <<email>>`. `AgentEntry` (`src/dna/schema.ts`) refuses angle brackets and
line breaks in the name, a malformed address and a bare GitHub noreply login, but it accepts an empty or
blank name and an address on a reserved top-level domain (`.test`, `.example`, `.invalid`, `.localhost`). The
audit predicate for the same kind of identity, `isValidAttribution` (`src/memory/audit.ts`, `task-132`,
`bug-153`), rejects both as "not a deliberately-configured identity".

## Steps to Reproduce

On `main` at `b0c3e472`, after `npm run build`:

```
node -e 'const {AgentEntry}=require("./dist/dna/schema.js"); const {isValidAttribution}=require("./dist/memory/audit.js");
for (const [n,e] of [["","noreply@anthropic.com"],["Claude","bot@agents.test"],["Claude","bot@example.invalid"],["  ","a@b.example"],["Claude","noreply@anthropic.com"]])
  console.log(JSON.stringify(n), e, AgentEntry.safeParse({name:n,email:e,executes_as:["developer"]}).success, isValidAttribution(n,e));'
```

prints `true false` for the first four pairs (accepted by the schema, rejected by the audit) and `true true` for
the last.

## Expected Behavior

A `team.agents` entry is refused, with a message naming the field, when its `name` is empty or blank or its
`email` is on a reserved top-level domain: the same rules `isValidAttribution` applies, shared rather than
restated, so the identity §7 writes into a trailer is one the audit would accept.

## Actual Behavior

`dna.yaml` can declare an agent identity that every trailer would carry and that the audit's own rule calls a
placeholder.
