## Summary

A workflow action `memory.add(type: task, tags: [demo])` is accepted with no diagnostic and printed with its `tags`,
but the command `workflow start` and `workflow next` offer for it is `wingfoil memory add --type task --title <title>
--workflow … --step …`, with no `--tags demo`; the element created with it has no tags. A pack's facilitator must add
the arguments by hand. Reproduced on 0.3.2.

## Steps to Reproduce

In a scratch repository (`git init`, `wingfoil init --template Kanban --no-interactive`), on 0.3.2:

1. Add and commit a custom main workflow, included in `workflows.yaml`, with one phase whose action is
   `memory.add(type: task, tags: [demo])`.
2. `wingfoil workflow list --format json` → `diagnostics []`.
3. `wingfoil workflow start <it>`, then `wingfoil workflow next` → the offered command has `--type task` and no
   `--tags`.

## Expected Behavior

The offered command carries every argument of the action that `memory add` accepts (here `--tags demo`); an argument
the binding cannot pass is reported by `workflow list` as a diagnostic.

## Actual Behavior

The argument is dropped from the command with no diagnostic.

## Notes

- `dl-090` Q3 (ready) decides how token arguments reach a bound command; this is the built-in `memory.add` binding not
  following it. A search of `docs/04_memory` for arguments or tags on bindings finds no bug on the built-in binding.
- Distinct from `dl-197` (in-discussion, v0.4: `memory add --set` fills only `id_pattern` tokens): here the argument
  never reaches the command.
