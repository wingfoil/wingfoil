## Summary

`scripts/publish-staging.cjs` — run as `npm run publish:staging` locally and by the `stage` job of
`.github/workflows/publish.yml` — is the job that decides whether a tarball may be promoted, yet it does not stage
from exactly what the `gate` job tested:
1. it installs the staging registry at run time from `VERDACCIO_PACKAGE = 'verdaccio@6'`, a major-version range with no
   lockfile or integrity check, so the registry and its transitive dependencies are resolved afresh on every run;
2. its generated Verdaccio configuration gives the package under test no uplink but proxies every other package to
   `https://registry.npmjs.org/` (`proxy: npmjs`), so the smoke install resolves the dependency tree from the public
   registry at that moment, not from the lockfile the gate tested, and the job needs network access to npmjs (the
   script's header says so);
3. it listens on the fixed `STAGING_REGISTRY = 'http://localhost:4873/'`, so two staging runs on one machine collide.
The UI consumer reported it while building its own publish pipeline on WingFoil's model (read on `main` at 0.3.1).

## Steps to Reproduce

From the repository root:

1. `grep -nE "VERDACCIO_PACKAGE =|STAGING_REGISTRY =|proxy:|registry.npmjs.org" scripts/publish-staging.cjs` →
   `verdaccio@6`, `http://localhost:4873/`, the `npmjs` uplink and `proxy: npmjs`.
2. `grep -n "publish:staging" package.json .github/workflows/publish.yml` → the npm script and the `stage` job step
   that runs it.
3. `sed -n 20,26p scripts/publish-staging.cjs` → the header: network access to npmjs, to install Verdaccio and to
   proxy the package's dependencies.

## Expected Behavior

- Verdaccio pinned exactly: a devDependency locked by `package-lock.json`, or an exact version installed with its
  integrity checked.
- The staging registry seeded with the lockfile's resolved tarballs and run with no uplink, so the smoke proves the
  package installs from exactly the tree the gate tested, with no access to npmjs during the install.
- A free loopback port (listen on port `0` and read the bound address) instead of `4873`.

## Actual Behavior

A range-pinned registry, a live npmjs proxy for every dependency, and a fixed port, as above.
