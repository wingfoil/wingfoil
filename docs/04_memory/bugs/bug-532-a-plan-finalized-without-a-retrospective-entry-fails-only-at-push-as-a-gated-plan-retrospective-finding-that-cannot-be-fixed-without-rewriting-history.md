# A plan finalized without a Retrospective entry fails only at push, as a gated plan-retrospective finding that cannot be fixed without rewriting history

## Summary

`task-358` (`bug-320`, design-gate ruling D2 (a) (i)) adds the governance check `plan-retrospective`. It applies to every
`wf(plan): finalize … [active → done]` after the check's introduction, and requires the plan's `### Retrospective` to
hold at least one line outside HTML comments. The check runs at push and in CI. `workflow end`, the command that writes
that finalize, does not check the entry. A plan created from `.wingfoil/memory/templates/plan.md`, whose
`### Retrospective` holds only the template comment, can therefore be ended without warning. It then fails at push as a
gated finding. A `wf()` commit may not be rewritten once it is pushed or has other commits on top
(`git-conventions` §2), so by then the finding cannot be fixed cleanly.

## Steps to Reproduce

1. Once `task-358` is merged: `workflow start` a plan and write no `### Retrospective` entry.
2. `node dist/cli.js workflow end <plan>`: it succeeds.
3. `node scripts/check-governance.cjs --base origin/main`: a gated `plan-retrospective` finding on that finalize.

## Expected Behavior

The missing entry is reported before the finalize is written. Either `workflow end` warns or refuses (a `spec-017` §7.2
amendment), or the orchestrator's procedure checks it before every `workflow end` with
`node scripts/check-retrospective.cjs <plan file>`.

## Actual Behavior

The missing entry is reported only after the finalize is committed, when it can no longer be fixed without rewriting.

## Notes

Found by `task-358`'s review (finding 3, introduced by that task's D2 (a) (i), which the review judged sound but
late-failing). The design weighed a `workflow end` refusal (option (ii)) and set it aside because it is visible to every
adopter. Severity low: a procedure step avoids it.
