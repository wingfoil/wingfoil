## Summary

`wingfoil directive create` accepts only `--name` (and `--dry-run`): it derives the directive's `title` from the name
and writes a placeholder body, so a directive cannot be created in one committed step. Its real title, its tags and its
body have to be written by hand afterwards, in a second commit that no WingFoil verb records. The Benchmark consumer
met it on a 0.2 pre-release build; the feedback read of `minor-v0.4`'s release-planning reproduced it on 0.3.2.

## Steps to Reproduce

1. In a scratch repository: `git init`, then `wingfoil init --template Kanban --no-interactive` (pinned build 0.3.2,
   `wingfoil --version` → `0.3.2 (6de2e13c…)`).
2. `wingfoil directive create --help` → the options are `--dry-run` and `--name` only.
3. `wingfoil directive create --name my-rule` → a `wf(directive): create my-rule` commit whose file carries a
   `title` derived from the name and a placeholder body under its heading.

## Expected Behavior

`directive create` takes the directive's content at creation: at least `--title` and `--tags`, and a way to give the
body (an option, or reading the directive from a file), so that one `wf(directive): create` commit holds the whole
directive.

## Actual Behavior

Only the name is accepted; the title is derived from it, the body is a placeholder, and the rest is a separate hand
edit committed outside the `wf(directive)` scope.
