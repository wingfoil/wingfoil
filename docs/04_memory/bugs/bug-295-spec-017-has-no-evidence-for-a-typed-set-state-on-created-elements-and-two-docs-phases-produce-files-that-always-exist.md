## Summary

`spec-017` §4.3 lists the kinds of evidence that complete a phase. Two phase shapes in this repository's workflows
get no evidence that says anything:

1. **A typed `<T>.set_state` on elements an earlier step created.** §4.2 gives `<T>.set_state(…)` "the elements of
   type `T` created by an earlier step of the same workflow pass" as a target, but no §4.3 kind observes them:
   `state` is the bound element's, `created` is the phase's own `memory.add`, `selection` needs a `where`.
   `retrospective.approve` (`decision-log.set_state(ready)` on the decision-log `capture` created) is therefore a
   checkpoint, completed only by a `workflow finalize` record, although the transition it performs is a fact in
   Memory (§12: "which none of §4.3's kinds observes").
2. **`produces` entries naming files that always exist.** `user-docs.align-user-docs` produces `README.md`,
   `docs/user-guide.md`, `docs/cli-reference.md`, `docs/examples/` and `CHANGELOG.md`; `agent-docs.align-agent-docs`
   produces `CLAUDE.md`, `.wingfoil/README.md` and `.wingfoil/WORKFLOW.md`. §4.3's `produces` kind is satisfied when
   each "matches at least one path in `HEAD`'s tree", and every one of those paths has been committed since v0.2 or
   earlier, so both phases count as evidenced from the moment the instance starts, before anything is aligned. §4.3
   already refuses this for an implicit owner ("one that exists from the start (the release-line's own file)"), but
   not for a literal path.
