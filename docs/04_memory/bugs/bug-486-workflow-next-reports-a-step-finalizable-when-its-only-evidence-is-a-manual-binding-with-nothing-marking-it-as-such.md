## Summary

A step whose action is bound `kind: manual` is reported by `workflow next` with `evidence {"kinds":["record"],
"finalizable":true}`, exactly like a step whose work has been checked by other means. Nothing in the output says the
step is finalizable only because its binding is manual. A driver that finalizes whatever the engine calls finalizable
(the process driver of `dl-203`, or any script) would record as complete work nobody has done. Source: input given
privately to the approver, 2026-11-05.

## Steps to Reproduce

On this repository, with the pinned build (`npm run -s wingfoil -- --version` → `0.3.2`):

1. `npm run -s wingfoil -- workflow next sw-life-cycle-1-plan --format json`.
2. Read the step `release-planning.advance-pinned-build@release:minor-v1.0` (under `more`): `evidence {"kinds":
   ["record"], "missing": ["record"], "finalizable": true}`, and its action's binding `kind: manual`.
3. Compare `release-planning.reconcile-governance@release:minor-v0.4` (the `next` step): `finalizable: false`, binding
   `kind: wingfoil`. Nothing else in the output separates the two cases.

The input names the same case, in a throwaway clone after the state adoption of `dl-186` S4, for `advance-pinned-build`
of `minor-v0.4`, `record-adrs` and `identify-specs` of `minor-v1.0`, and the four `initial-design` seed steps.

## Expected Behavior

`workflow next` (and `status`, and any deduction preview) marks a step that is finalizable only because nothing but a
manual binding or a record can complete it, for example `finalizable: "manual"` or a separate `manualOnly: true`
flag, and the human output says so; a driver can then route such a step to a person instead of finalizing it.

## Actual Behavior

`finalizable: true` with no distinction; the manual nature of the step is visible only by reading the binding kind of
each action and inferring it.
