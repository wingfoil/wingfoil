## Summary

`workflow finalize` records an `approval:` phase that no element carries, but only on the frontier of an open
instance, that is, a plan with an empty `parent`. A sub workflow such as `release-submit` or `release-publishing` is
run on this repository by a phase plan opened by hand (`parent: "release-cycle.release-submit"`), because no
`sw-life-cycle` instance exists. Neither that plan nor the sub workflow can be addressed by any verb, and the
sub workflow cannot be started on its own. So its approval is recorded as a hand-written
`wf(plan): finalize … [active → done]` commit carrying `Approver:` and `Reason:`. The engine cannot read that commit as
the phase record. Its authority is checked only afterwards, by the governance check, and not before the commit as
`workflow finalize` checks it. This happened at v0.3 (bab1e0f4), v0.3.1's release-submit
(db6e8b44) and v0.3.1's release-publishing (e99f0a05, which records the publish approval and the plan's close in one
commit).

## Steps to Reproduce

From the repository root, with the code build (`npm run build`, then `node dist/cli.js`), every command `--dry-run`:

1. `grep -m4 "^status:\|^parent:\|^workflow:\|^phase:" docs/05_plans/rl-v1/rel-v0.3.1/release-submit-rel-v0.3.1-plan.md`
   → `status: done`, `workflow: "release-submit"`, `phase: "rel-v0.3.1"`, `parent: "release-cycle.release-submit"`.
2. `node dist/cli.js workflow end release-submit-rel-v0.3.1-plan --dry-run` → `error: unknown workflow:
   release-submit-rel-v0.3.1-plan`, exit 1.
3. `node dist/cli.js workflow finalize release-submit-rel-v0.3.1-plan --step release-submit.approve-release --reason x
   --dry-run` → `error: unknown workflow: release-submit-rel-v0.3.1-plan`, exit 1.
4. `node dist/cli.js workflow finalize release-submit --reason x --dry-run` → `error: workflow is not open:
   release-submit`, exit 1.
5. `node dist/cli.js workflow start release-submit --dry-run` → `error: cannot start a sub workflow directly:
   release-submit`, exit 1. `node dist/cli.js workflow start release-cycle --element release:patch-v0.3.1 --dry-run` →
   `error: cannot start a sub workflow directly: release-cycle`, exit 1.
6. `node dist/cli.js memory approve release-submit-rel-v0.3.1-plan --reason x --dry-run` → `error: illegal transition
   done -> (none) for type 'plan'`, exit 1. The `plan` machine has no gate at all
   (`grep -n "^  plan:" -A14 .wingfoil/memory.yaml`: `sequence: [ draft, active, done ]`, `waiting: [ active ]`), so
   `approve` is illegal from any state of a plan. Steps 2–5 gave the same results while the plan was still `active`,
   before db6e8b44, as recorded in the plan's Retrospective

7. `git log -1 --format='%h %s%n%b' db6e8b44` (and `bab1e0f4`, `e99f0a05`) shows the hand records:
   `wf(plan): finalize <plan> [active → done]` with `Approver: Roberto Pompermaier <robypomper@gmail.com> (approver)`
   and a `Reason:` that approves the release step.
8. `grep -n "approval:" .wingfoil/workflows/custom/release-submit.yaml .wingfoil/workflows/custom/release-publishing.yaml`

## Expected Behavior

An approver can record a sub workflow's `approval:` step with a verb, with the authority check
(`requireApprovalAuthority`) and the `WingFoil-Phase` record that `workflow finalize` writes, also when the phase is
run by a hand-opened phase plan. Two candidates, to settle with `dl-203` (the engine drives a run):

- `workflow finalize` (and `workflow end`) accept a phase plan, meaning a plan with `parent:` set, as `<ref>`;
- a phase of a main can be run as a startable unit that has its own instance.

## Actual Behavior

Every route a verb could take is refused (steps 2–6). The approval is recorded by a hand-written
`wf(plan): finalize` commit. The workflow deduction does not read that commit as the phase record of
`release-submit.approve-release` or `release-publishing.publish`: it carries no `WingFoil-Phase` trailer
(`git log -1 --format='%(trailers)' db6e8b44` shows only `Co-Authored-By` and `AI-Model`). Its `Approver:` line is
checked against `dna.yaml` only after the fact, by `scripts/check-governance.cjs`'s authority rule ("any other verb
carrying an `Approver:` line", `sed -n 25,28p scripts/check-governance.cjs`), not before the commit.
