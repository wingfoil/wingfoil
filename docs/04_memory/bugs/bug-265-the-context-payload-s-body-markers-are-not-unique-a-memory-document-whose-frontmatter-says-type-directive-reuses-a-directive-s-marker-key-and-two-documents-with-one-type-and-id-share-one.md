## Summary

`spec-012` §7 format 1 (`task-255`, `dl-150` (B)) delimits each body by `<!-- begin:{key} -->` /
`<!-- end:{key} -->`, with key `directive:{id}` for a directive and `{type}:{id}` for the element and each
Memory document. The Memory key is built from the document's **frontmatter** `type` and `id`
(`payloadCandidates`, `src/core/context.ts`), which the tolerant scan reads without checking them against the
type the path declares. So a Memory document whose frontmatter says `type: directive` carries the same key and
the same `### directive:<id>` heading as a directive of that id, and two documents with the same `type` and
`id` (a copied file, or an id collision `dl-101` renumbers later) carry two identical marker pairs. `memory.yaml`
itself cannot declare a type named `directive` (`RESERVED_TYPE_NAMES`, `bug-177`): the collision comes only
from a document's own frontmatter.

## Steps to Reproduce

On `main` at `b0c3e472`, after `npm run build`, in a scratch repository (`node dist/cli.js init --template
Scrum`):

1. Element `task-001-older-probe` (status `draft`) with `depends_on: ["testing", "task-006-dup"]`.
2. Three hand-written documents under `docs/memory/task/`, all `status: backlog`: `task-005-a.md` with
   `id: testing`, `type: directive`; `task-006-dup.md` and `task-006-dup-copy.md`, both `id: task-006-dup`,
   `type: task`. Commit.
3. `assembleExecutionContext(root, {role: 'developer', element: {type: 'task', id: 'task-001-older-probe'},
   stateRef: 'HEAD'})` from `dist/core/index.js`, then the payload's heading and marker lines: section 3 holds
   `<!-- begin:directive:testing -->` for the `testing` directive; section 4 ("3 documents") holds
   `### directive:testing` with a second `<!-- begin:directive:testing -->` pair, and `### task:task-006-dup`
   twice, each with a `<!-- begin:task:task-006-dup -->` pair.
4. Not reproduced, so not part of this bug: two directives with one id (`resolveRoleDirectives` deduplicates
   by id, `custom/` winning, `dl-037` A.1), and a frontmatter key or value shaped like a marker (the fenced YAML
   dump never yields a line equal to a marker: a probe with the key and a multi-line value
   `<!-- end:task:task-001-x -->` gave `'...': v`, `k: ...` and an indented line, only the real marker exact).

## Expected Behavior

Every marker key in a payload is unique, so a consumer can address a body by its key: a Memory document whose
frontmatter `type` is not the type its path declares, or whose `type:id` repeats one already carried, is left
out and reported (as the unnameable ones are), or the key is made unique by construction.

## Actual Behavior

The splitting rule still parses the payload (it is sequential), but the same key names two bodies, and a
section-4 heading reads as a directive.
