## Summary
The workflow configuration of this repository (`.wingfoil/workflows/custom/*.yaml`) names prose `checks:` and `actions:` tokens that
`.wingfoil/workflows/bindings.yaml` neither binds to a command (kind `run`) nor declares `manual: true`, so every workflow deduction on this
repository carries 65 `W_WORKFLOW_UNBOUND_TOKEN` diagnostics. Since `task-330` (`bug-339`), `agent execute` prints the deduction's diagnostics
as warnings before any refusal, so every run on this repository prints those 65 lines, and a run diagnostic such as `W_UNCOMMITTED_INPUTS`
(the one `bug-339` is about) is buried among them. A fresh project carries none.

## Steps to Reproduce
1. On `release/0.3` at `148194875`, with the code build: `node dist/cli.js workflow next --format json` → `diagnostics` holds 65 entries, all
   `W_WORKFLOW_UNBOUND_TOKEN` (counted by code over the JSON).
2. In a scratch repository: `git init`, `wingfoil init --template Scrum`, `wingfoil workflow start bug-ingest`, then
   `wingfoil workflow next --format json` (same code build) → `diagnostics` is empty.
3. After `task-330`'s merge, `wingfoil agent execute --next --dry-run` on this repository prints the warnings before its answer.

## Expected Behavior
Each prose token of this repository's workflows is either bound in `.wingfoil/workflows/bindings.yaml` (kind `run`, when a command decides it)
or declared `manual: true` (when a human confirms it), in view of the checks runner (P4.10/P4.12, v1.0), so that a deduction on this
repository carries no `W_WORKFLOW_UNBOUND_TOKEN` and the warnings `agent execute` prints are the run's own. The tool's behaviour does not
change: the approver ruled out splitting the warnings into run and configuration classes.

## Actual Behavior
65 unbound tokens on every deduction.
