## Summary

`spec-012` §7 makes `test/fixtures/context/golden-payload.md` the normative example of payload format 1, and
`test/core/context-payload-format.test.ts` compares the serializer's output with it byte for byte. The golden
context is built by hand (`created`, `scope`, `status`, `type`, `id`), and every other context test writes its
element and documents by hand too. No test builds a context from an element `memory add` writes from a shipped
template (`memoryTemplateMd` in `src/storage/templates.ts`: `id`, `type`, `title`, `status`, `format`), so a
template change, or a template field the dump renders differently, never reaches the byte pin.

## Steps to Reproduce

On `main` at `b0c3e472`:

1. `sed -n 1,12p test/fixtures/context/golden-payload.md` → the element frontmatter `created`, `id`, `scope`,
   `status`, `type`: no `format`, no `title`.
2. `grep -n 'function memoryTemplateMd' -A10 src/storage/templates.ts` → the shipped scaffold, with
   `format: ${MEMORY_TEMPLATE_FORMAT}` and quoted empty `id`/`title`.
3. `grep -rln 'assembleExecutionContext\|serializeExecutionContext' test` → four suites
   (`context-builder`, `context-payload-format`, `context`, `builtin-directive-templates`);
   `grep -rn 'memoryAdd\|memory add'` over those four files finds nothing: each writes its element with a literal
   frontmatter (for example `'---\nid: task-1-none\ntype: task\nstatus: backlog\n---\n'` in
   `builtin-directive-templates.test.ts`).
4. In a scratch repository, an element from `memory add --type task` renders in the payload with `format: 1`
   and its other template fields; nothing compares that rendering with an expected text.

## Expected Behavior

One test builds the payload of an element created by `memory add` from each shipped template (or the golden
fixture's element is derived from a template), so a change to a template or to the dump's handling of a
template field shows up as a golden diff to review, as `dl-150` (B) intends for every envelope change.

## Actual Behavior

The byte format is pinned only on hand-written frontmatter that matches no template.

## Notes

- Low: a test gap; the serializer is the same for any frontmatter, but a template is the frontmatter users
  actually have.
- The elements of this repository use its own hand-authored templates (`.wingfoil/memory/templates/`, with
  `tmpl_version`), not the shipped ones; the shipped templates are what an `init` project gets.
