## Summary

`spec-003` ("Where each check runs") says a core check "is not decided when its input is missing": without
`dna.yaml` no role, member or `dna:` collection is checked, without `memory.yaml` no type, event, token, exit state
or fallback. `workflowCoreDiagnostics` (`src/core/workflow-core-checks.ts`) does exactly that, and silently: with
`dna.yaml` or `memory.yaml` absent at the baseline, `workflow list` returns `"diagnostics": []` and exit 0 for a
registry the same checks would refuse, and nothing in the output says that a whole group of checks did not run. The
check fails open with no trace, so a reader cannot tell "checked and clean" from "not checked".

## Steps to Reproduce

On `main` at `0962f85f` (`npm ci && npm run build`), in a scratch repository (`git init`, a local identity,
`node dist/cli.js init --template Scrum`):

1. Add `role: nonexistent-role` to the `capture` phase of `.wingfoil/workflows/custom/bug-ingest.yaml` and commit.
   `node dist/cli.js workflow list` → exit 1, `error: E_PHASE_ROLE_UNKNOWN phases[0].role
   (workflows/custom/bug-ingest.yaml): unknown role 'nonexistent-role' (not defined in dna.yaml)`.
2. `git rm .wingfoil/dna.yaml` and commit. `node dist/cli.js workflow list` → exit 0, nothing on stderr, and the JSON
   holds `"diagnostics": []` while its `workflows[1].phases[0].role` is still `nonexistent-role`.

## Expected Behavior

The output says which core checks were not decided and why — for example one warning per missing input
(`dna.yaml absent at HEAD: role, approver and dna: collection checks not run`) in `diagnostics` — so the empty
list means "checked and clean". The skip itself stays as `spec-003` defines it; `spec-003` gains the warning row.

## Actual Behavior

An empty `diagnostics` array and exit 0, identical to a fully checked clean registry.
