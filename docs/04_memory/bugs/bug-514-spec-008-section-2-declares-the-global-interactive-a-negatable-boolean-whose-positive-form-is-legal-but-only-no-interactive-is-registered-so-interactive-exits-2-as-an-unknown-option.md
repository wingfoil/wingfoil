## Summary

`spec-008-cli-grammar` §2 declares the global `--interactive` a negatable boolean, default `true`: "Pass
`--no-interactive` to force immediate failure instead". It is listed with `--color` as a negatable boolean whose
positive form is accepted. The program registers only `--no-interactive` (§3's Commander pattern), so the positive form
is refused as an unknown option, and the spec and the program disagree.

## Steps to Reproduce

1. On `main` at `013640ed8`, outside a repository: `node dist/cli.js --interactive agent list` prints
   `error: unknown option '--interactive'` and `hint: did you mean "--no-interactive"?`, exit `2`.
2. `grep -n "interactive" docs/04_memory/design/specs/spec-008-cli-grammar.md` → l.108, the §2 row
   `--interactive` (negatable); l.115, "`--color`/`--interactive` are **negatable booleans**"; l.344,
   `.option('--no-interactive', …)`.

## Expected Behavior

The spec and the program agree. Either the positive form `--interactive` is registered as well, or §2 declares only
`--no-interactive`.

## Actual Behavior

The positive global form exits `2` as an unknown option.

## Notes

- Found by `task-335`'s architect at design (2026-11-07) and reproduced by the orchestrator with the command above.
- `task-335` adds a *command* flag `--interactive` to `agent execute` (`dl-183`), read from the command's own
  options. Commander keeps it apart from the global `--no-interactive`. The fix must keep that distinction.
