## Summary

Codex limits the output of each MCP tool call (`tools.<tool>.output_token_limit`), while the session Resource
`wingfoil://session/{role}/{element}/{state}` that the bootstrap tells the agent to read was 436,204 bytes on this
repository; on a real repository Codex's model would likely get a truncated context.

## Steps to Reproduce

1. `task-236`'s by-hand pass (2026-10-14, its Execution Notes): the session Resource read by the launched agent on
   this repository was 436,204 bytes (`wc -c` on the saved tool result).
2. `task-237`'s design read of Codex's documentation (2026-10-14): `tools.<tool>.output_token_limit` exists, so a
   large context may be truncated; `task-237`'s by-hand pass therefore ran in a small scratch project, where the read
   was complete.

## Expected Behavior

The context has a size budget the agent can always read whole, or the session Resource is paged (with the bootstrap
or the Resource saying how to read the rest), and `agent execute` warns when the assembled context exceeds what the
adapter declares its agent can take.

## Actual Behavior

Nothing bounds the session Resource's size or tells the agent it was cut.
