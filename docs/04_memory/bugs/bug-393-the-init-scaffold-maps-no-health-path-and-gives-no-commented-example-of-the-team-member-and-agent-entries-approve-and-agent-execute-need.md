## Summary

A project scaffolded by `wingfoil init` (code build at `1c4a3a43`) cannot run three commands the v0.3 documentation
walks a new user through until `dna.yaml` is edited by hand, and the scaffold shows nothing of the edit: `paths
health` is refused because `paths:` has no `health` key, `memory approve` is refused because `team.members` is empty,
and `agent execute` is refused because `team` has no `agents` key. The README Quick Start and `docs/user-guide.md`
§9.4 document the `dna add` commands that fix the last two; the scaffold itself carries no commented example of
either entry, as it does for the per-type machine it shows on `bug`.

## Steps to Reproduce

In a scratch repository outside this one (`git init`, a local `user.name` / `user.email`), with this branch's code
build (`node dist/cli.js --version` → `0.2.2 (1c4a3a431486e61213f6b2bfcdb8f14e54956f64)`, called `wingfoil` below):

1. `wingfoil init --template Scrum --no-interactive` → exit `0`, one commit `chore(wingfoil): initialize
   .wingfoil/ with the Scrum template (P5.1.1)`.
2. `wingfoil paths health` → `error: no paths mapped for category 'health'`, exit `1`; `grep -n health
   .wingfoil/dna.yaml` → no match (exit `1`), while `wingfoil paths --help` lists the category (`category
   sources, tests, docs, config, governance, runs or health`). The positive case of the command: `wingfoil paths
   runs` → `{"category": "runs", "paths": ["docs/runs/"]}`, exit `0`.
3. `wingfoil memory add --type task --title "Scratch task"`, `wingfoil memory submit task-001-scratch-task` (both
   exit `0`, `status: pending`), then `wingfoil memory approve task-001-scratch-task --reason "Accept the scratch
   task."` → `error: user not authorized to approve type 'task'`, exit `1`. The pinned build gives the same answer
   (`node node_modules/wingfoil-released/dist/cli.js --version` → `0.2.2`; its `memory approve` → the same error
   after two `unknown field(s) ignored` warnings), so this is not a regression. `wingfoil dna show team` →
   `"members": []` and no `agents` key.
4. `wingfoil agent execute --role developer --element task:task-001-scratch-task --dry-run` → `error: no agent in
   dna.yaml with an adapter executes as role 'developer'`, exit `1`.
5. The positive case of steps 3 and 4: `wingfoil dna add team.members --value "Scratch User" --entry-email <the
   local git email> --entry-roles approver,developer` (README.md:164's command) and `wingfoil dna add team.agents
   --value claude --entry-adapter claude-code --entry-email noreply@anthropic.com --entry-executes_as
   developer,reviewer` (docs/user-guide.md:588's), both exit `0`; then `memory approve` → exit `0`, `wf(task):
   approve task-001-scratch-task [pending → approved]`, and the dry run under a pseudo-terminal (`script -qec "…"
   /dev/null`) → exit `0`, a plan with `"subject": "agent: record task-001-scratch-task/adhoc/1"`.
6. The scaffold's source: `sed -n 294,315p src/storage/templates.ts` → `team:` / `members: []` / `roles:` (seven
   names), `paths:` with `sources`, `tests`, `docs`, `config`, `governance`, `runs` and no comment on `team.members`,
   `team.agents` or `health`.

## Expected Behavior

A new user meets the three edits in the file `init` wrote: the scaffold's `dna.yaml` carries commented examples of a
`team.members` entry holding the `approver` role, a `team.agents` entry with an `adapter` and an `email`, and a
`paths.health` directory, each with the command that adds it; or the three refusals name that command. A commented
`health:` line keeps `spec-002`'s rule that `init` does not map the category (see Notes).

## Actual Behavior

The three commands exit `1` on a fresh project with messages that say what is missing but not where or how to add it;
only the README Quick Start and the user guide say it.
