## Summary

`test/docs/name-resolvability.test.ts` (`task-151`, `dl-116` Q1 (B)) classifies each backticked name in the
specs, ADRs and SARD by shape. Its element pattern (`ELEMENT_ID` in `test/docs/support/name-resolvability.ts`)
allows `[a-z0-9]` slug segments only, but `memory add` keeps dots from the title in the slug (`team.agents`,
`dna.yaml`, `p1.11`). A full id with such a slug fails the element pattern and falls through: when the text
after the dot starts with a letter it matches the `config` pattern and is reported as an unresolved
configuration key; when it starts with a digit it matches no class and is silently skipped.

## Expected Behavior

A name that is a Memory element id, slug dots included, is classified `element` and resolves when the element
file exists (the slug accepts `.`, as the id character class `a-z0-9-.` of `src/validation/id.ts` does), and
an unknown id of that shape is a finding.

## Actual Behavior

The full id of an element whose title holds a dotted name is either a false finding (it must be reworded out
of the document, as in `task-256`) or invisible to the check.
