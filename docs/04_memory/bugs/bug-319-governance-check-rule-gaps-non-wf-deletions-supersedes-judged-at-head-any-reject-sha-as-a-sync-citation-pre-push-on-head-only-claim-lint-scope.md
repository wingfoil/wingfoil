## Summary

Five gaps in `scripts/check-governance.cjs`, its hook and its lint (`task-208`), each found by `task-208`'s
independent review: a Memory document deleted outside a `wf()` operation is not flagged; the `supersedes-pair` rule
is judged at `HEAD`, so a later `deprecate` of the superseded element re-flags an approve that was right when made;
a `sync` citation accepts any `reject` commit's sha; `.githooks/pre-push` checks only a pushed ref whose tip is
`HEAD`; and the claim lint (`scripts/lint-claims.cjs`) reads whole Memory documents where most of its warnings are
normative prose.

## Steps to Reproduce

1. **Deletion.** `task-208`'s green notes: the `dl-139` rule "follows renames (`-M`), counts a document only when its
   `type:` is a type of that file, flags a creation, never a deletion". `dl-139` (option (a), ratified 2026-10-02)
   fails a non-`wf()` commit that changes a Memory document's `status`; removing the document changes it too.
2. **supersedes-pair at `HEAD`.** `git-conventions` §9 (1.4): the check flags "an approve whose `supersedes:` target
   is not `superseded` at `HEAD` (`bug-218`)". `memory deprecate` is legal from any state, so a later deprecate of the
   target turns an approve that was correct at its commit into a finding.
3. **sync citation.** `task-208`'s green notes: "a hop that is a reject edge and no forward edge under any other
   verb needs a body token resolving to a `wf(…): reject` commit" — any reject commit, not one of the same element
   whose transition it mirrors.
4. **pre-push.** `.githooks/pre-push` at `main` `02800955`: `head=$(git rev-parse HEAD)`, then `[ "$local_sha" =
   "$head" ] || continue` for each pushed ref, so `git push origin task/x` from another branch's worktree, or a push
   of several refs, checks at most the one equal to `HEAD`.
5. **claim lint scope.** `node scripts/lint-claims.cjs --base 1ce84a54` (the W3 B3 range) → `claim lint: 17
   warnings in 11 files (warn-only), 59 files read`, "most are normative spec prose ('unchanged' in
   `spec-005`/`spec-006`)" (`task-208`'s refactor notes); the reviewer counted about 4 of the 17 as real.

## Expected Behavior

1. A non-`wf()` commit that deletes a Memory document of a declared type is a gated finding, like a status change
   (`dl-139`).
2. `supersedes-pair` judges the target's state at the approve commit (or at its merge), not at `HEAD`.
3. A `sync` citation resolves to a `reject` of the element the sync mirrors (the task whose reject the bug follows).
4. The hook checks every pushed ref (`<remote_sha>..<local_sha>` per line of its input), whatever `HEAD` is.
5. The claim lint reads only the Execution Notes sections (and Triage & Execution Notes) of the Memory documents the
   range changed, where `claim-evidence` asks for pasted commands.
