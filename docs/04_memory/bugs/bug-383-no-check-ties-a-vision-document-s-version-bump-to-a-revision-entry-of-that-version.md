## Summary

No check verifies that a vision document whose `version:` is bumped carries a matching revision entry. That is how
`docs/01_vision/X_cli-cmds.md` 1.5's entry went missing, found only when `task-245` wrote 1.7.

## Steps to Reproduce

On `main` at `327a7b01`:

1. `grep -ln "^## Revision history" docs/01_vision/*.md` → `00_index.md` and `X_cli-cmds.md`.
2. `grep -n "the header is at version 1.7 or later" -A18 test/docs/x-cli-cmds.test.ts` → the one test that reads
   `X_cli-cmds.md`'s history pins the entries `task-245` named by hand (the header at 1.7 or later, entries 1.7 and
   1.5 present, in descending order); it does not tie the header's `version:` to an entry of that version, so a 1.8
   bump without an entry passes. No test reads `00_index.md`'s history (`grep -rln "Revision history" test/` →
   `test/docs/x-cli-cmds.test.ts` and `test/docs/vision-default-machine-text.test.ts`, the latter only to exclude it).
3. `scripts/check-governance.cjs` checks the version bump of the four versioned config files over a range
   (`git-conventions` §9, `bug-249`), not the vision documents' revision entries.

## Expected Behavior

A check (a docs test, or the governance check over a range) refuses a vision document whose `version:` has no
revision entry of that version, wherever the document keeps a revision history.

## Actual Behavior

A bump without an entry passes every gate; the history loses the record of what changed.
