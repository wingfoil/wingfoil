## Summary

`.githooks/pre-push` ignores the remote git passes it (`$1`) and always reads the tracking refs under
`refs/remotes/origin/`, so a push to another remote, or a clone whose remote is not called `origin`, gets the wrong
base or none; and the hook's guard against a local branch that looks like a tracking ref is tested for
`origin/release/0.3` but not for `origin/main`.

## Steps to Reproduce

1. `grep -n 'origin' .githooks/pre-push` → line 34 `pushed="refs/remotes/origin/${remote_ref#refs/heads/}"` and line 36
   `git for-each-ref --format='%(refname)' refs/remotes/origin/main 'refs/remotes/origin/release/*'`: the remote name
   is a literal.
2. `grep -n '\$1\|\$2' .githooks/pre-push` → nothing: the hook never reads the remote name or URL git gives it as its
   arguments (git `githooks(5)`, pre-push).
3. In a clone whose only remote is named `upstream` (`git remote rename origin upstream`), with `git config
   core.hooksPath .githooks` and `dist/` built, push a new branch: `git push upstream HEAD:refs/heads/scratch`. The
   `for-each-ref` of step 1 returns nothing, `base` stays empty (lines 49–58), and the hook runs `node
   scripts/check-governance.cjs --root <top>` without `--base` (line 61) — the whole history, not the commits being pushed (read from the hook's code, `sed -n 31,63p .githooks/pre-push`).
4. `grep -n "branch', '--quiet', 'origin/" test/cli/git-hooks.test.ts` → one line, the local branch
   `origin/release/0.3` of the look-alike case at line 302; no case creates a local branch named `origin/main`.

## Expected Behavior

The hook reads the tracking refs of the remote it is pushing to — `refs/remotes/$1/…` — and skips the tracking ref of
the pushed ref under that remote; a remote with no tracking refs gives no base, as today. A test pins that a local
branch `refs/heads/origin/main` does not hide or replace `refs/remotes/origin/main`, alongside the existing
`origin/release/0.3` case.

## Actual Behavior

The candidates are always `origin`'s. Pushing a new branch to a remote other than `origin` takes its base from
`origin`'s lines (or from none), and a clone without an `origin` remote checks the whole history on every
branch-creating push. The `origin/main` look-alike is handled by the code — the candidates are matched by full refname
since `f9fd7447` — but only by hand verification at `task-291`'s re-review, not by a test.
