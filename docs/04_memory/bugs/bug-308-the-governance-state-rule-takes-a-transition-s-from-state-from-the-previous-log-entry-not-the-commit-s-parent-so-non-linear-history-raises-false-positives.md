## Summary

`reconstructMemoryTransitions` (`src/memory/audit.ts`, at `main` `02800955`) takes each commit's `fromState` from the
previous entry of the path's `git log --follow` walk, not from the commit's parent, so on non-linear history it
derives a transition the commit never made, and `scripts/check-governance.cjs`'s state rule reports it as a gated
finding: an amend on `main` made while the task is started on its branch reads as `in-progress → backlog`.

1. Build `main` at `02800955` (`npm ci && npm run build`).

   §5), commit `docs/task-1.md` with `status: backlog` on `main` (`wf(task): add task-1`, 10:00).

   (11:00).

## Expected Behavior

A commit's `fromState` is the document's `status` in that commit's (first) parent, read at the path the parent
used; the amend in step 5 derives `backlog -> backlog` and `d818c0dd` raises no finding. A merge commit that
changes `status` relative to its first parent is judged against that parent.

## Actual Behavior

`fromState` is the `toState` of the walk's previous entry (`previousState` in `reconstructMemoryTransitions`), which
on interleaved branches is another branch's commit: step 5 derives `in-progress -> backlog`, and the governance
check fails `d818c0dd`.
