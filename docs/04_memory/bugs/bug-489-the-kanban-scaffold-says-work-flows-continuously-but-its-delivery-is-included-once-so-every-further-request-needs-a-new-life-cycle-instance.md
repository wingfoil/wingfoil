## Summary

`wingfoil init --template Kanban` scaffolds a `kanban-delivery` workflow whose header describes continuous flow with no
timeboxed iterations, but `sw-life-cycle` includes it once, with no `iterate_over` and no recurring `cadence`. After one
plan → build → review → deliver, `workflow next` reaches `sw-life-cycle.sunset`; a second request needs a second
instance, with its own inception and specification to finalize. Reproduced by reading the 0.3.2 scaffold.

## Steps to Reproduce

1. In a scratch repository, `wingfoil init --template Kanban --no-interactive` (0.3.2).
2. `grep -n "include" .wingfoil/workflows/*/sw-life-cycle.yaml` → one `include: kanban-delivery`.
3. `grep -n "iterate\|cadence" .wingfoil/workflows/*/kanban-delivery.yaml` → no match; its header says work flows
   continuously.
4. Optionally, step 1 of the bug filed from svc-020 F-043: after one delivery, `wingfoil workflow next` →
   `sw-life-cycle.sunset`.

## Expected Behavior

The Kanban scaffold's delivery repeats inside one instance (an `iterate_over: task` include, or a recurring cadence),
or its documentation says plainly that each request is an instance of its own.

## Actual Behavior

One delivery per instance, while the scaffold describes a continuous flow.
