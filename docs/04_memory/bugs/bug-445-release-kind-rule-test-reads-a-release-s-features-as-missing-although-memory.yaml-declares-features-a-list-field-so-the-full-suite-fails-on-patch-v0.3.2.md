## Summary

`test/workflow/release-kind-rule.test.ts` "every release document carries every field the check requires of it"
counts an empty list as a missing field, so it reports `patch-v0.3.2: features` although `memory.yaml` declares
`features` among the release type's `lists` (an empty list is filled, "none") and `memory submit` accepted the
document; the full suite fails on `release/0.3` since `patch-v0.3.2` was submitted with `features: []`.

## Steps to Reproduce

1. Check out `release/0.3` at `7ce9d88d` (or any commit from `b7604e8b`, `wf(release): submit patch-v0.3.2`, on),
   `npm ci`.
2. `npx jest test/workflow/release-kind-rule.test.ts`.
3. The test "every release document carries every field the check requires of it" fails, received
   `["patch-v0.3.2: features"]`.

## Expected Behavior

The test reads a required field the way the engine does (`missingRequiredFields` in `src/memory/submit.ts`): a field
listed in the type's `template.frontmatter.lists` (`release`: `[ features ]`, bug-147, task-168) is filled by `[]`,
so `patch-v0.3.2`, which ships no feature, passes, and the full suite is green on `release/0.3`.

## Actual Behavior

The test's own `missingFields` treats `[]` as missing for every field, ignoring `lists`
(`Array.isArray(value) && value.length === 0`), and is the only failure of the full suite:
`Test Suites: 1 failed, 506 passed, 507 total`, `Tests: 1 failed, 8953 passed, 8954 total`, twice in a row under
`--maxWorkers=2` (`task-308` refactor, 2026-10-28; that branch changes nothing under `docs/04_memory/planning`,
`.wingfoil` or `test/workflow`: `git diff --stat release/0.3...task/task-308-… -- docs/04_memory/planning .wingfoil
test/workflow` prints nothing).
