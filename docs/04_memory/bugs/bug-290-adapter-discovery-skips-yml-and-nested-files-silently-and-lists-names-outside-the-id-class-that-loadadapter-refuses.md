## Summary

`listAdaptersAtRev` (`src/agent/discovery.ts`) recognises an adapter only by `ENTRY_RE`, a `.yaml` file directly inside
`.wingfoil/agents/built-in/` or `.wingfoil/agents/custom/`. It passes over a `.yml` file and a nested
`custom/<dir>/<name>.yaml` without a word, and it lists `custom/Bad Name.yaml` as an adapter named `Bad Name`, which
`loadAdapter` then refuses as "not an adapter name". `bug-234` asked for such files and names to be "reported where
adapters are enumerated"; that part was not done when `bug-234` closed, and no v0.3 command enumerates adapters
(`wingfoil agent` has `show` only), so nothing reports them.

## Steps to Reproduce

On `main` at `c485e433` (`npm ci && npm run build`), in a scratch git repository committing
`.wingfoil/agents/custom/{a.yml, Bad Name.yaml, nested/b.yaml, ok.yaml}` (each `format: 1`):

1. `node -e "…require('<build>/dist/agent').listAdaptersAtRev(process.cwd(),'HEAD').map(e=>e.name)…"` →
   `["Bad Name","ok"]`: `a.yml` and `nested/b.yaml` are absent, and no warning or diagnostic is returned.
2. `loadAdapter(root, 'a')` → `NOT_FOUND adapter 'a': no .wingfoil/agents/built-in/a.yaml or
   .wingfoil/agents/custom/a.yaml at HEAD`; `loadAdapter(root, 'b')` → the same `NOT_FOUND` for `b`.
3. `loadAdapter(root, 'Bad Name')` → `VALIDATION adapter 'Bad Name': not an adapter name: an adapter name is an id,
   characters [a-z0-9-.] only (spec-009 §1)`: a name the listing offered is one the loader refuses.
4. `node dist/cli.js agent --help` → the commands are `show <run-id>` and `help`; `grep -rn 'listAdaptersAtRev' src`
   finds only its definition and the re-export in `src/agent/index.ts`.

## Expected Behavior

Wherever adapters are enumerated, every entry under `.wingfoil/agents/` that is not an adapter (another extension, a
nested file) and every basename outside the id class is reported as a diagnostic naming its path, and an entry the
listing offers is one `loadAdapter` can select (or the listing marks it unloadable). `spec-016` §2.1 says which
code, severity and surface carry it (`wingfoil init`'s install, `agent execute`'s selection, a future command that
lists adapters).

## Actual Behavior

Unrecognised files vanish silently, and a name the loader always refuses is listed as an adapter. A user who
writes `claude.yml` gets `NOT_FOUND` from `agent execute` with no hint that the file exists under the wrong
extension.
