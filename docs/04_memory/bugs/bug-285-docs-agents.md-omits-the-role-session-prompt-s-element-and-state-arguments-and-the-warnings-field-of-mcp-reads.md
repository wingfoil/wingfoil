## Summary

`task-195` gave the MCP read surface two things an agent using WingFoil needs to know, and `docs/agents.md` (the
guide for agents working in a project that uses WingFoil) describes neither:

- the `<role>-session` Prompt takes two optional arguments, `element` (`<type>:<id>`) and `state` (a commit), given
  together; with them the Prompt carries the `spec-012` §7 execution context for that element at that commit,
  instead of the role header and directive blocks (`ROLE_PROMPT_ARGUMENTS`, `src/mcp/prompt.ts`; `spec-004` §3.1);
- a Resource read, and a Prompt, that left something out returns a top-level `warnings` array beside `contents` or
  `messages` (`withWarnings`, `src/mcp/read-only.ts`; `spec-004` §2.2, §3.2), the MCP twin of the warnings the CLI
  prints on stderr.

The guide's MCP table lists the Prompt as "role instructions with its directives embedded", and an agent reading it
neither asks for its execution context nor looks for the warnings.
