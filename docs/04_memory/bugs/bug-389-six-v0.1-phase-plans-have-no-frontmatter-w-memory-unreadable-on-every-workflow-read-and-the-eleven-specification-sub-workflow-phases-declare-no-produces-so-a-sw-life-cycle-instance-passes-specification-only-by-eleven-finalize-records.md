## Summary

Two parts of this repository's configuration and Memory cannot be deduced by the v0.3 engine: six
v0.1 phase plans have no frontmatter, so every workflow read reports `W_MEMORY_UNREADABLE` six times,
and the eleven phases of the specification sub-workflows declare no `produces`, so a `sw-life-cycle`
instance passes `specification` only by eleven `workflow finalize` records, although their artefacts
exist.

## Steps to Reproduce

1. At `89c43d36`, build the CLI and run `node dist/cli.js workflow status --format json`: among the
   diagnostics, `W_MEMORY_UNREADABLE` for `docs/05_plans/rl-v1/initial-design-rl-v1-plan.md` and five
   plans under `docs/05_plans/rl-v1/rel-v0.1/` (`dev-loop-`, `release-implementation-`,
   `release-planning-`, `release-submit-rel-v0.1-plan.md`, `retrospective-and-config-bootstrap-plan.md`):
   "no frontmatter".
2. In a scratch clone, run `workflow start sw-life-cycle`, then `workflow next` repeatedly: the steps
   `user-story-mapping.backbone|vertical-explosion|mvp-cut`,
   `specification-by-examples.isolate-mvp|write-scenarios`,
   `volere-requirements.extract-requirements|apply-volere-shell|group-by-macro-area` and
   `backlog-export.generate-records|map-dependencies|validate` each report
   `evidence missing: record (finalizable)`.

## Expected Behavior

- A plan the engine reads has the frontmatter the `plan` type declares, or is excluded the way
  `dl-019` grandfathers the `X_*` plans.
- A phase whose artefact is a file declares it in `produces`, so the deduction sees it: the user story
  map under `docs/02_requirements/01_user_story_map/`, the `.feature` files under
  `docs/02_requirements/02_bdd/features/`, the SARD under `docs/02_requirements/03_sard/`, the backlog
  under `docs/03_backlog/04_backlog/`.

## Actual Behavior

The six plans are unreadable to the engine and reported on every read; the eleven phases are
checkpoints (`spec-017` §12 lists them), each completed only by an explicit `finalize`.
