## Summary

`assembleExecutionContext` (`src/core/context.ts`) finds its subject element in the tolerant scan
`loadMemoryDocumentsAtRev`. Since `task-257`, that scan leaves a newer-format element out and reports it as
`W_MEMORY_UNREADABLE`, so a subject written in a newer format is "not found": the builder answers `NOT_FOUND`,
`element '<type>:<id>' not found at <sha>`, with the format refusal only in `details.unreadable`. Every verb
that names the same element refuses it as `VALIDATION`, `E_INVALID_FORMAT ... upgrade WingFoil`.

## Steps to Reproduce

On `main` at `b0c3e472`, after `npm run build`, in a scratch repository (`git init`, an identity passed through
`GIT_AUTHOR_*`/`GIT_COMMITTER_*`, `node dist/cli.js init --template Scrum`):

1. `node dist/cli.js memory add --type task --title "Newer probe"`; by hand set `format: 2` in
   `docs/memory/task/task-002-newer-probe.md` (the id the scaffold allocated) and commit.
2. `node -e` calling `require('<worktree>/dist/core/index.js').assembleExecutionContext(process.cwd(),
   {role: 'developer', element: {type: 'task', id: 'task-002-newer-probe'}, stateRef: 'HEAD'})` →
   `{"ok":false,"error":{"code":"NOT_FOUND","message":"element 'task:task-002-newer-probe' not found at <sha>",
   "details":{"unreadable":["W_MEMORY_UNREADABLE (docs/memory/task/task-002-newer-probe.md): unreadable
   frontmatter in docs/memory/task/task-002-newer-probe.md: E_INVALID_FORMAT: this file is written in format 2;
   this WingFoil reads up to format 1: upgrade WingFoil"]}}}`.
3. For comparison: `node dist/cli.js memory history task-002-newer-probe` → exit 1, `its document is written
   in a newer format: E_INVALID_FORMAT ...`; the MCP Resource `wingfoil://memory/task/task-002-newer-probe` →
   error `-32603` with the `E_INVALID_FORMAT` text.

## Expected Behavior

A subject element found at `stateRef` but written in a newer format is refused for its format, `VALIDATION`
with the `dl-149` `E_INVALID_FORMAT` text, as the transition verbs and `memory history` refuse it; `NOT_FOUND`
stays for an element that is absent.

## Actual Behavior

The context says the element does not exist. `task-195`'s `{role}-session` Prompt is specified to answer an
unknown element at `state` with `InvalidParams`, so an agent would be told the element is unknown rather than
that it needs a newer WingFoil.
