## Summary

`dna set` detects a no-op by comparing the file's text before and after the edit, so a value that is unchanged but
re-quoted (`""` → `''`) counts as a change: on the `wingfoil init` scaffold, `dna set project.name --value ''` writes a
`wf(dna): set project.name` commit, and since `task-299` that commit also raises `dna.yaml`'s `version:` (`1` → `1.1`).

## Steps to Reproduce

On the code build (`node <repo>/dist/cli.js --version` → `0.3.1`), in a scratch repository:

1. `git init -q -b main scratch && cd scratch && git config user.name T && git config user.email t@e.x`
2. `node <repo>/dist/cli.js init --template Scrum` → exit 0; `sed -n 9p .wingfoil/dna.yaml` →
   `  name: ""                        # your project name`.
3. `node <repo>/dist/cli.js dna set project.name --value '' --dry-run; echo $?` → exit 0, a dry-run commit with subject
   `wf(dna): set project.name` and the diff `-version: 1` / `+version: 1.1` and
   `-  name: ""  …` / `+  name: ''  …`.
4. For contrast, `node <repo>/dist/cli.js dna set project.methodology --value Scrum --dry-run; echo $?` → exit 0 and only
   `{"key": "project.methodology", "value": "Scrum"}`: an unchanged plain scalar is detected as a no-op and nothing is
   planned.

## Expected Behavior

A `dna set` whose value YAML reads the same as the current one (`""` and `''` are both the empty string) is a no-op:
nothing is written, no commit is made, and `version:` is not raised — the same outcome as step 4.

## Actual Behavior

The edit re-spells the scalar in single quotes, the text comparison sees a difference, and the command commits a
rewrite of `dna.yaml` with its `version:` raised, although no value changed.

## Notes

- Where: `sed -n 628,644p src/core/index.ts` — `const serialized = current === produced ? produced :
  raiseConfigVersion(produced);` and `if (current === serialized) return coreOk(outcome);` compare text only; the
  in-place edit (`applyDnaEditInText`, `src/dna/edit.ts`) re-spells the empty value as `''` (step 3).
- Possible fixes: compare the YAML-read value at the path before and after (or the whole parsed document) to decide
  the no-op, or keep the existing scalar's quote style when the value is unchanged. Either way the version raise
  follows the no-op decision, as `task-299` intended ("a write that changes nothing stays no write").
- Reachable on every project initialised from the shipped templates, which scaffold `name: ""`; harmless in content,
  but it adds a commit and a version revision `doc-versioning` does not expect.
