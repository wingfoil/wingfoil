## Summary

With both an invalid `--format` and a surplus operand, the two bootstrap commands and the derived commands
report different errors first. `init` and `mcp` refuse the surplus operand; a derived command (`paths`) reports
the invalid `--format` value. Both exit `2`, so the contract holds, but the message a user sees depends on which
kind of command they typed.

## Steps to Reproduce

In an empty `git init` folder, with `node <repo>/dist/cli.js` built from `main` at `ccccc227`:

1. `wingfoil --format bogus init extra` → `error: wingfoil init takes no positional (got 1 positional)`, exit 2.
2. `wingfoil --format bogus mcp extra` → `error: wingfoil mcp takes no positional (got 1 positional)`, exit 2.
3. `wingfoil --format bogus paths a b` → `error: invalid --format value "bogus", expected one of: console, json, yaml`, exit 2.
4. `wingfoil --format bogus init` → `error: invalid --format value "bogus", …`, exit 2 (so `init` does check the
   flag, after the operand count).

## Expected Behavior

One order of usage checks for every command, as `spec-005`/`spec-008` declare the refusal shape: either the
global `--format` value first everywhere (it decides how every later error is rendered), or the operand count
first everywhere.

## Actual Behavior

Bootstrap commands check the operand count first (`task-165`/`bug-179` gave them the shared surplus refusal);
derived commands check `--format` first.
