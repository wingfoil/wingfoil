## Summary

Some read verbs (`workflow list`, `workflow status`, `workflow next`, `agent list`) run git in a way that writes
to the repository and executes programs the repository can choose: `git status` with optional locks refreshes and
rewrites a stale `.git/index`; a configured `core.fsmonitor` command runs; on a partial clone a read lazy-fetches
from the promisor remote; and git is started by name, so the first `git` on `PATH` runs, including one inside the
project when `PATH` has a relative entry. Three of the four parts reproduced on 0.3.2.

## Steps to Reproduce

In a throw-away repository on the pinned 0.3.2 build (`git init`, `wingfoil init --template Kanban
--no-interactive`):

1. **Index write.** Touch `.wingfoil/dna.yaml` with a future mtime, `sha1sum .git/index`, run
   `wingfoil workflow list --format json`, `sha1sum .git/index` again → changed. `wingfoil dna show` leaves it
   unchanged.
2. **fsmonitor.** `git config core.fsmonitor <a script that logs a line and exits 1>`, a stale index entry,
   `wingfoil workflow list` → the script ran 4 times.
3. **git from PATH.** A logging executable named `git` at the repository root, `PATH=".:$PATH" wingfoil workflow
   list` → it ran 17 times.
4. **Lazy fetch** (not attempted on 0.3.2: it needs a filtered remote). The consumer reports on 0.3.1 that on a
   `--filter=blob:none` clone `workflow list` fetched missing objects, and failed with
   `E_GIT_READ_FAILED` under `GIT_NO_LAZY_FETCH=1`.

## Expected Behavior

A read verb never writes to the repository, never runs a program named by the repository's configuration and never
contacts a remote: WingFoil's git reads run with `--no-optional-locks` (or `GIT_OPTIONAL_LOCKS=0`),
`-c core.fsmonitor=false`, `GIT_NO_LAZY_FETCH=1` and no transport allowed (a read on a partial clone fails with a
message naming the fix); git is started by an absolute path resolved once from absolute `PATH` entries, never from
inside the project. Writes keep the locks they need.

## Actual Behavior

As in the steps: the index is rewritten, the fsmonitor command and a project-local `git` run, under verbs documented
as reads (`command-baseline`).
