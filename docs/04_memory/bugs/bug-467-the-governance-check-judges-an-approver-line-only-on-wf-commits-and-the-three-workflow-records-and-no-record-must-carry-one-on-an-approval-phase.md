## Summary
`bug-444`'s Expected Behavior asks that "any commit carrying an `Approver:` line" be held to the Approver grammar and the authority rule.
`task-328` (w2 of `patch-v0.3.2`) does so for `wf(...)` commits (as before) and the three `workflow: finalize|adopt|rekey` records, and,
by release-planning ruling R8, only when a record carries the line. Two parts stay open: (1) other commits that carry an `Approver:` line
(for example an `agent: record` commit, or a plain commit with a hand-written `Approver:` line) are not judged; (2) whether a record on an
`approval:` phase must carry an `Approver:` line was left to v0.4 by R8, but no element holds that question.

## Steps to Reproduce
1. After `task-328`'s merge, commit an `agent: record …` (or a `docs:`) commit whose body starts with `Approver: Mallory <m@x> (approver)`,
   by an author who does not hold `approver`.
2. `node scripts/check-governance.cjs --base <parent>` → no finding.
3. A `workflow: finalize` on an `approval:` phase with no `Approver:` line → no finding.

## Expected Behavior
Every commit that carries an `Approver:` line is held to the grammar and the authority rule, and a record of an `approval:` phase without
one is a finding (or the rule states why not), each under a gated check with its own introduced-at.

## Actual Behavior
Only `wf(...)` commits and the three record subjects are judged, and only when the line is present.
