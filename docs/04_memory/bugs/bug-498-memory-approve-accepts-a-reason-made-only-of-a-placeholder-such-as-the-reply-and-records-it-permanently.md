## Summary

`--reason` is mandatory on `approve` and `reject` (P1.7) and a blank reason is refused at exit 2 (`dl-067`,
`spec-008` §2), but a reason that is only an angle-bracketed placeholder is accepted and committed as the recorded
reason. The record cannot be corrected without rewriting history. Reproduced on 0.3.2.

## Steps to Reproduce

1. Throw-away repository on the pinned 0.3.2 build: `git init`, an identity, `wingfoil init --template Kanban
   --no-interactive`, a member holding `approver`; a task added and submitted.
2. `wingfoil memory approve <id> --reason "<the reply>"` → exit 0.
3. `git log -1 --format=%B` → `Reason: <the reply>`.

## Expected Behavior

`approve` and `reject` (and the other verbs that record a `Reason:`) refuse at exit 2 a reason that is only a
placeholder token (the whole text a single `<…>`) or contains no word, as they refuse a blank one.

## Actual Behavior

The placeholder is recorded as the approval's reason, exit 0.

- The rule would extend `dl-067`'s declared reason contract and `spec-008` §2's "unrecordable value" row; triage
  decides whether that needs a `dl-067` amendment or only a test-backed rule in the shared reason check.
- Typical source: a command template copied with its placeholder left in, by a person or an agent.
