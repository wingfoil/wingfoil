## Summary

`scripts/e2e-smoke.cjs`, the release gate's end-to-end run on a fresh project, drives `workflow list` and
no other workflow command, so the four v0.3 workflow commands that write or deduce state are never run end to end
against the packed candidate.

## Steps to Reproduce

On `main` at `29b8406a`:

1. `grep -oE "args: \['[a-z-]+', *'?[a-z-]*" scripts/e2e-smoke.cjs | sort | uniq -c` → `directives list`, `dna
   add/set/show`, `init`, `memory add/approve/history/search/submit`, `paths config` and `workflow list` — no
   `workflow start`, `end`, `finalize`, `status` or `next`.
2. `node dist/cli.js workflow --help` → `end`, `finalize`, `list`, `next`, `show`, `start` and `status` ship.

## Expected Behavior

The smoke's fresh-project run starts a workflow, reads `workflow next` and `workflow status`, records a
step with `workflow finalize` where the scaffold has one that needs it, and ends the instance with `workflow end`,
each checked for its exit code and its `wf()` commit.

## Actual Behavior

As in step 1.
