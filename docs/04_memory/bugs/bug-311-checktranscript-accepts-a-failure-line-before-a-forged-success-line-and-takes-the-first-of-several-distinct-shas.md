## Summary

`checkTranscript` (`scripts/publish-staging.cjs`), the check bound as `staging-rehearsal-passed`, accepts a transcript
that records a failure before a success line appended after it, and a transcript whose smoke checked several
distinct commits, returning the first one as the commit to tag.

## Steps to Reproduce

1. Build `main` at `02800955`.
2. `node -e` with `const {checkTranscript} = require("./scripts/publish-staging.cjs")` and `pkg = {name: "wingfoil",
   version: "0.3.0"}`:
   - transcript = `[publish:staging] FAIL wingfoil init --template Scrum exited 1`, `[publish:staging] staging smoke
     FAILED`, `[publish:staging]   ok   wingfoil --version = 0.3.0 (<40×a>) — match`, `[publish:staging] staged
     wingfoil@0.3.0 and smoke passed` → `{"ok":true,"commit":"aaaa…"}`;
   - transcript = two `ok wingfoil --version = 0.3.0 (<sha>) — match` lines with shas `<40×a>` and `<40×b>`, then the
     closing line → `{"ok":true,"commit":"aaaa…"}`.
3. The script itself writes `staging smoke FAILED — the build must not be promoted` and `staging FAILED: <message>`
   (`runStaging`'s `effects.log` calls), and the e2e smoke writes `FAIL <label> — <detail>` lines; `checkTranscript`
   reads only the last line and the first `VERSION_CHECK_RE` match.

## Expected Behavior

A transcript passes only when no line records a failure (`FAIL`, `FAILED`), the closing line is the success line,
and every version-check line names the same full sha, which is the commit returned; any other shape exits 1 with the
reason.

## Actual Behavior

Both transcripts of step 2 pass; the first sha wins.
