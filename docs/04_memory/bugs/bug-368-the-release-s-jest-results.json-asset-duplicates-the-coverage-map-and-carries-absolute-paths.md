## Summary

The test-results files `publish.yml` attaches to the public GitHub Release are larger and noisier than they need to
be: `jest-results.json` (about 6.2 MB) carries the whole `coverageMap`, which duplicates `lcov.info`, and absolute
paths of the runner's checkout with stack traces; the committed `coverage-summary.json` is keyed by absolute paths
too. Nothing sensitive is in them.

1. `sed -n 351p .github/workflows/publish.yml` (`main` at `bd55f70e`) → `gh release create` attaches
   `jest-results.json`, `coverage-summary.json`, `lcov.info` and `test-results.md` to the Release; line 118 says the
   summary is also committed under `docs/07_gates/`.
2. `task-244`'s review read, on a full `npm run test:report`: `jest-results.json` 6.16 MB, about 1.95 MB of it the
   `coverageMap`, 424 absolute `/home/runner/…`-style paths with stack traces; `coverage-summary.json` keyed by
   absolute paths.
3. Re-read on the local `npm run test:report` output of `task-244`'s worktree (2026-10-14): `jest-results.json`
   6,163,869 bytes, its `coverageMap` 2,255,172 bytes serialized, 656 absolute paths; `coverage-summary.json`'s keys
   after `total` are absolute paths of the checkout.

attached files and in the committed summary.
