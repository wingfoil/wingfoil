## Summary

A project initialised by `wingfoil init --template Scrum|Kanban` (0.3.0) gets five workflows whose phases declare no
`role:`, no `actions:` and no `produces:`, and a `dna.yaml` with no `team.agents`, so the 0.3 workflow engine has
nothing to guide on a fresh project: a started `sw-life-cycle` completes with seven `workflow finalize` records and no
work, no step waits for an agent, and `agent execute --next` cannot run.

## Steps to Reproduce

On the published `wingfoil@0.3.0` (isolated `npm install -g --prefix <tmp> wingfoil@0.3.0`; `wingfoil --version` →
`0.3.0 (cc31d7a8ca3940c6ec96dca4e0ef77f32f52dfb1)`), 2026-10-19:

1. In an empty git repository with an identity: `wingfoil init --template Scrum` → exit 0 (the same with `Kanban`).
2. `grep -lE '^\s+(role|actions|produces):' .wingfoil/workflows/custom/*.yaml | wc -l` → `0` of 5 files
   (`sw-life-cycle`, `scrum-delivery` / `kanban-delivery`, `bug-ingest`, `adr-ingest`, `decision-log-ingest`), for both
   templates; `grep -cE '^\s+agents:' .wingfoil/dna.yaml` → `0`.
3. `wingfoil workflow start sw-life-cycle` → `next step: sw-life-cycle.inception`, `role: (none)`, `directives: (none)`,
   `evidence missing: record (finalizable)`.
4. Repeat `wingfoil workflow finalize sw-life-cycle-1-plan` while `workflow next` prints a step → 7 records
   (`git log --format=%s | grep -c "^workflow: finalize"` → `7`); then `workflow next` → `no next step: workflow
   'sw-life-cycle' is complete`, and `workflow status` → `phases: inception complete, specification complete, delivery
   complete, sunset complete`, with no Memory element created.
5. `wingfoil agent list --waiting` → `no waiting steps`; `wingfoil agent execute --next` → `error: step
   'sw-life-cycle.inception' has no element: give --element <type>:<id>`.

The same was observed on the code build `a4c080cb` on 2026-10-18 (engine-adoption work), held by the approver until
after the v0.3.0 tag.

## Expected Behavior

The scaffold `init` writes is a configuration the shipped engine can drive: each phase of the delivery workflow names
the role that performs it, and the phases that produce Memory declare it (`actions:` / `produces:`, e.g. the delivery
loop on `task` elements, `bug-ingest.capture` adding a `bug`), so `workflow next` names who acts, the deduction reads
evidence instead of only `finalize` records, and a project with an agent in `team.agents` can see a step in
`agent list --waiting`. If the scaffold is meant to stay a bare skeleton until P4.18–P4.20, `init` and the user guide
say so.

## Actual Behavior

Every phase is a name with at most a description (`src/storage/templates.ts` `mainWorkflowYaml` /
`deliveryWorkflowYaml`: `plan`, `build`, `review`, `deliver`; `sw-life-cycle`: `inception`, `specification`,
`delivery` (include), `sunset`; each ingest main: one `capture` phase). The engine reports nothing wrong — `init` prints
0 diagnostics — and the only way through a workflow is to finalize every step by hand.
