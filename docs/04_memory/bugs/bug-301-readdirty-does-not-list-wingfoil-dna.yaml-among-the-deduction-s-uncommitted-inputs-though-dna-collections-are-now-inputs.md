## Summary

`readDirty` (`src/core/workflow-deduction.ts`), which feeds `W_UNCOMMITTED_INPUTS` (`spec-017` §1.2), lists the
working-tree changes under the Memory scan roots, `.wingfoil/workflows.yaml`, `.wingfoil/workflows/`, the static
part of every `produces` pattern and `dna.yaml` `paths.runs`, but not `.wingfoil/dna.yaml` itself. Since `task-202`
(W3 B3), a phase may `iterate_over` a `dna:<path>` collection (`dl-104` D2 (b); `COLLECTION_REF_RE` in
`src/workflow/deduce.ts`), whose entries are read from `dna.yaml` at `HEAD`. An uncommitted edit of those entries
changes nothing in the answer, correctly, but is not reported either, so the operator is not told why the
iterations they just edited do not appear.

1. In a scratch project (`GIT_CONFIG_GLOBAL=/dev/null`, `node dist/cli.js init --template Scrum`, first commit),

3. Control: `git checkout .wingfoil/dna.yaml`, `echo "# probe" >> .wingfoil/workflows.yaml`, the same command →
   one `W_UNCOMMITTED_INPUTS` diagnostic, `"file":".wingfoil/workflows.yaml"`, message "uncommitted change to a
   deduction input, not read (the answer is computed from HEAD): .wingfoil/workflows.yaml".

## Expected Behavior

Every file the deduction reads at `HEAD` is a deduction input for §1.2: a change to `.wingfoil/dna.yaml` is
reported by `W_UNCOMMITTED_INPUTS` like one to `workflows.yaml`. `spec-017` §1.2's list of paths gains
`dna.yaml`.

## Actual Behavior

No diagnostic for an uncommitted `dna.yaml` (step 2).
