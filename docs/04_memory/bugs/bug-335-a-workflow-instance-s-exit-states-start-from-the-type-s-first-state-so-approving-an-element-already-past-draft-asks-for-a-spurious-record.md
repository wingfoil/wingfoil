## Summary

`spec-017` §4.4 computes a phase's exit state statically, and for an instance's first phase starts from the
type's first state; a startable workflow whose first phase approves an element already past `draft` therefore gets
an undetermined exit state (`W_PHASE_EXIT_STATE_UNDETERMINED`) and asks for a `workflow finalize` record that the
approval itself should satisfy.

   `W_PHASE_EXIT_STATE_UNDETERMINED` is raised at load and the phase's `state` evidence is unsatisfied".

   (`e94c2728`)."
3. `git show e94c2728 --stat` → the fixture change that made the CLI test submit before it approves, to step around
   it.

## Expected Behavior

An instance bound to an element seeds its first phase's start state from the element's status at the
instance's `HEAD` (or at its start commit), so an approval from that state is determined and needs no record.

As in steps 1–2.
