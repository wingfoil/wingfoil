## Summary

The jest `globalSetup` removes `dist/` and rebuilds it with `npm run build`; a run interrupted between the
removal and the end of the build leaves no `dist/`, and the next CLI command fails with "Cannot find module
…/dist/cli.js".

## Steps to Reproduce

On `main` at `29b8406a`:

1. `sed -n 1,20p test/global-setup.cjs`: "Deterministic by construction: a clean removal + a single `npm run build`",
   under the `.jest-dist.lock` of `test/dist-lock.cjs`.
2. `sed -n 172,176p test/dist-lock.cjs`: `prepareDist` runs `rmSync(join(repoRoot, 'dist'), …)` and then `build()`.
3. Reproduced on this branch: start `setsid npx jest test/core/workflow-next.test.ts --maxWorkers=2`, wait until
   `dist/` is gone, send `SIGINT` to its process group (what Ctrl-C does), then `node dist/cli.js --version` →
   `Error: Cannot find module '/home/…/dist/cli.js'`; `ls -d dist` → `No such file or directory`. The positive
   case: the same `SIGINT` sent to the jest process alone lets the build child finish, and `dist/cli.js` exists.
   `task-235`'s session met it after a restart (W3 B5).

## Expected Behavior

The build writes to a temporary directory and swaps it in with a rename, or the setup restores the previous
`dist/` when interrupted, so `dist/` is never absent; at least, a CLI run with no `dist/` prints a hint to run
`npm run build`.

## Actual Behavior

As in step 3.
