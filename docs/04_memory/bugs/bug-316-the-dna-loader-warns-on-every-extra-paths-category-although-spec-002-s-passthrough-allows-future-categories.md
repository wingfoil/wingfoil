## Summary

`spec-002-dna-yaml-schema` (Categories) says that "`.passthrough()` allows a future category to be added without
invalidating existing files", but loading a `dna.yaml` whose `paths:` holds a category outside the seven declared
ones prints a warning on every command, and calls the field ignored, so a project-specific category cannot be used
silently.

## Steps to Reproduce

1. Build `main` at `02800955`. In a scratch copy of this repository's `.wingfoil/dna.yaml`, add `extras: [ "notes/" ]`
   under `paths:`.
2. `node dist/cli.js dna show paths` → stderr `warning: .wingfoil/dna.yaml: unknown field(s) ignored: paths.extras`;
   `node -e "require('./dist/core').loadWorkflowRegistry('.')"` → `Warning: .wingfoil/dna.yaml: unknown field(s)
   ignored: paths.extras` (the file restored with `git checkout` after).
3. `grep -n -i "without invalidating" docs/04_memory/design/specs/spec-002*.md` → "`.passthrough()` allows a future
   category to be added without invalidating existing files" (Categories, at `02800955`).

## Expected Behavior

As the approved spec says: an extra `paths` category is preserved and loads with no warning (it is not "ignored"),
while unknown keys elsewhere keep whatever diagnostic their own rule gives. The test that pins the warning for
`paths` is updated.

## Actual Behavior

Step 2: a warning on every load, with the word "ignored" for a key `.passthrough()` keeps.
