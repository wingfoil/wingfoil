# The pinned build 0.3.2 refuses a run log holding a 19-key line so agent list, agent show and agent execute fail on any element the code build has run on

## Summary

Since `task-337`, the code build writes run records with key 19, `agent_version_after` (`spec-016` §4.2). The pinned
build `wingfoil@0.3.2` (`wingfoil-released`, the devDependency `main` pins for read commands, `AGENTS.md` §3) knows only the
18-key form, and its readers refuse a line with an unknown key (`spec-016` §4.5, as it stood in 0.3.2). So once a
run log holds one 19-key line, 0.3.2's `agent list --past` and `agent show` exit `1` on it, and its `agent execute`
refuses that element too, because the next run id (`nextRunId`) and the record's duplicate check (`recordRun`) parse the
same log (`parseRunLog`). The code build at `02ffe01ca` reads the same line.

The refusal of a newer form is the subject of `dl-240-run-log-readers-refuse-a-whole-run-log-on-one-line-written-in-a-newer-form`
(`in-discussion`); whatever it rules, it cannot change the already-published 0.3.2.

## Steps to Reproduce

Two scratch projects outside the worktree, `git init`, local identity, an agent session (`CLAUDE_CODE_CHILD_SESSION`
set). `P=node <worktree>/node_modules/wingfoil-released/dist/cli.js` (`$P --version` → `0.3.2 (6de2e13c0…)`),
`C=node <worktree>/dist/cli.js` (`0.3.2 (02ffe01ca…)`, the code build).

1. `$P init --template Scrum`; `$P dna add team.agents --value Claude --entry-email noreply@anthropic.com
   --entry-adapter claude-code --entry-executes_as developer`; `$P memory add --type task --title "Scratch task"` →
   `task-001-scratch-task`; `$P paths runs --format json` → `docs/runs/`.
2. Commit `docs/runs/task-001-scratch-task.jsonl` holding one 19-key line: the 18 keys in §4.2 order (as in
   `docs/06_runs/task-236-*.jsonl` of this repository) with `"agent_version_after":"2.1.322 (Claude Code)"` appended.
3. `$C agent list --past` → `past runs: 1`, `task-001-scratch-task/adhoc/1  developer  Claude  0  1.0s  not-reported`,
   exit 0 (the line is valid for the code build); `$C agent show task-001-scratch-task/adhoc/1` → exit 0.
4. `$P agent list --past` → `error: run log docs/runs/task-001-scratch-task.jsonl: line 1 is not a valid run record:
   unexpected key 'agent_version_after'`, exit 1; `$P agent show task-001-scratch-task/adhoc/1` → the same line, exit 1.
5. `$P agent execute --element task:task-001-scratch-task --role developer --dry-run` → the same line, exit 1. (Before
   step 2, with no log, the same command stops later, at `error: interactive launch needs a terminal on stdin and
   stdout`, so the run log is what refuses it.)

In this repository at `02ffe01ca` no committed log holds a 19-key line yet (`grep -l agent_version_after docs/06_runs/*`
prints nothing; the same grep on the scratch log above prints its path), so the refusal appears with the first
`agent execute` the code build records here.

## Expected Behavior

The pinned build reads the run logs the code build writes in the same repository. With 0.3.2 that cannot be fixed in
place; the expected end is that `release-planning`'s `advance-pinned-build` moves the pin to a
build that reads 19-key lines (0.4.0 or later), which closes this bug.

## Actual Behavior

0.3.2 refuses the whole log on the first 19-key line: no listing, no `show`, and no launch on that element.

  agent list --past`).

  which build runs `agent list`/`agent show` here is not stated; the refusal bites whoever runs them on the pin, as
  `npm run -s wingfoil -- agent list` does.
- Severity medium: two read commands and the launch of an element stop working on the pinned build, with a
  workaround.
