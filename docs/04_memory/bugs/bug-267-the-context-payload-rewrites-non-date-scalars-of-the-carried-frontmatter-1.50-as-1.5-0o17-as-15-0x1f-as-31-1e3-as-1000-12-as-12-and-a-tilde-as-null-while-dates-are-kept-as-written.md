## Summary

`task-255` (`bug-232`) made the payload carry every frontmatter timestamp exactly as the document wrote it: the
carried frontmatter is re-read with `PAYLOAD_YAML_SCHEMA` (`src/core/context.ts`), whose timestamp type keeps
the text in a `WrittenTimestamp`. Every other implicit scalar type of that schema still constructs a value and
dumps it in js-yaml's canonical spelling, so a number or a null the document wrote one way reaches the agent
another way: `1.50` → `1.5`, `0o17` → `15`, `0x1F` → `31`, `1e3` → `1000`, `+12` → `12`, `~` → `null`.

## Steps to Reproduce

On `main` at `b0c3e472`, after `npm run build`, in a scratch repository (`node dist/cli.js init --template
Scrum`, an element `task-001-older-probe`):

1. Add to its frontmatter, by hand, `version: 1.50`, `mode: 0o17`, `hex: 0x1F`, `exp: 1e3`, `plus: +12`,
   `nothing: ~` and `created: 2026-10-05`, and commit.
2. `assembleExecutionContext(root, {role: 'developer', element: {type: 'task', id: 'task-001-older-probe'},
   stateRef: 'HEAD'})` from `dist/core/index.js`; section 1's YAML block reads `created: 2026-10-05`,
   `exp: 1000`, `hex: 31`, `mode: 15`, `nothing: null`, `plus: 12`, `version: 1.5`.

## Expected Behavior

Either every scalar is carried as written, the way timestamps are (the same mechanism, applied to the int,
float and null types), or `spec-012` §7 states that only timestamps are kept and every other scalar is
re-emitted canonically, and a test pins that choice.

## Actual Behavior

The payload is still deterministic (the same document gives the same bytes), but it differs from the document
the agent may also read, for values whose spelling can matter: a version `1.50` read as `1.5`, a file mode
read in decimal.
