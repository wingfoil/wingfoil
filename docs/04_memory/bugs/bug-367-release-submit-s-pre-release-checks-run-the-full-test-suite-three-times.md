## Summary

`release-submit`'s `pre-release-checks` phase runs the full test suite three times on the release candidate: once as
the action `npm run test:report` (coverage and JSON results), once for the check `tests.passing` (`npm test`) and once
for `tests.coverage(min: 80)` (`npm run test:coverage`), plus the no-identity run, a distinct check.

## Steps to Reproduce

On `main` at `bd55f70e`:

1. `sed -n 27,38p .wingfoil/workflows/custom/release-submit.yaml` → the action `cli.run(command: "npm run
   test:report")`; the checks `tests.passing`, `tests.coverage(min: 80)` and `tests.no-identity`.
2. `grep -n "tests.passing\|tests.coverage" .wingfoil/workflows/bindings.yaml` → line 24 `tests.passing: { run: [npm,
   test] }`, line 28 `tests.coverage: { run: [npm, run, "test:coverage"] }`.
3. `grep -n '"test' package.json` → `test` (`node scripts/run-tests.cjs`), `test:coverage` (`jest --coverage`),
   `test:report` (`jest --coverage --json --outputFile=coverage/jest-results.json`): each runs the whole suite, the
   last two with coverage.

## Expected Behavior

One full run with coverage serves the action and both checks: `tests.coverage` (and `tests.passing`, if its
`run-tests.cjs` behaviour allows) read the results `test:report` wrote, for example by rebinding `tests.coverage` to
`test:report`'s output in `bindings.yaml`.

## Actual Behavior

About three times the suite's run time on every `release-submit` (a coverage run takes minutes, `dl-089`'s cost
note), under `dl-170`'s one-heavy-gate-at-a-time rule.
