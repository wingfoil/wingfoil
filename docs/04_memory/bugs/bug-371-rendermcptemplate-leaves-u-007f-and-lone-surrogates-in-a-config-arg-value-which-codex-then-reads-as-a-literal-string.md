## Summary

`renderMcpTemplate` renders `{mcp_command}` and `{mcp_args}` with `JSON.stringify`, which leaves U+007F unescaped
(invalid in a TOML basic string) and writes an unpaired surrogate as a `\uD8xx` escape (not a TOML scalar). Under
`mcp.via: config-arg` the result is passed to Codex as a `-c` value, and Codex does not refuse a value it cannot parse
as TOML: it uses the raw text as a literal string, so the registration silently breaks.

## Steps to Reproduce

1. `sed -n 177,183p src/agent/execute.ts` (`main` at `bd55f70e`) → `JSON.stringify(server.command).slice(1, -1)` and
   `JSON.stringify(server.args)`, with no TOML-specific escaping.
2. `node -e 'console.log(JSON.stringify("a\u007fb").length, JSON.stringify("\ud800"))'` → `5 "\ud800"`: U+007F is
   kept as a raw character, the lone surrogate becomes `\ud800`.
3. `spec-016`'s revision of 2026-10-14 (`task-237`): the rendered values "are valid TOML for any value without U+007F
   or an unpaired surrogate … Codex does not refuse a `-c` value it cannot parse as TOML: it uses the raw text as a
   literal string".

## Expected Behavior

For `config-arg`, the renderer escapes U+007F as `\u007f` and refuses a lone surrogate with a clear error, so every
rendered value is valid TOML.

## Actual Behavior

A path or argument holding either character yields a value Codex reads as a plain string, with no error.
