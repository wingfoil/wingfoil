## Summary

An agent CLI launched by `wingfoil agent execute` in a folder it has not seen before stopped at its own folder-trust
prompt; the run was recorded as failed, with nothing saying that the agent never started its work. **Not reproduced**:
the read of 2026-11-05 did not attempt it (it needs a real agent CLI in a fresh folder), and the version it was seen on
is not stated.

## Steps to Reproduce

To be run in a by-hand adapter pass (as `retro-v0.3` planned):

1. A fresh clone of a WingFoil project in a folder the agent CLI has never opened, on the pinned build.
2. `wingfoil agent execute --element <type:id> --role developer` with a built-in adapter (Claude Code, Codex CLI),
   headless and interactive.
3. Observe whether the agent CLI shows a folder-trust prompt, and what `wingfoil agent show <run-id>` records
   (`exit_status`, `notes`).

## Expected Behavior

Either the adapter declares how its CLI is told to trust the folder for the launch (an argv fragment or a setting,
verified with the adapter's `verified_with`), or `agent execute` detects that the agent never got past its start-up and
says so in the run record and on stderr, naming the agent CLI's trust step as the likely cause.

## Actual Behavior

As reported: the agent waits at the prompt (interactive) or exits (headless), and the record shows a failed run with no
cause.
