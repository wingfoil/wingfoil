# The git-log-readers lint takes any quoted log token in src/ for a git log reader so it flags the agent execute --log option name

## Summary

`test/lint/git-log-readers.test.ts` enumerates `git log` readers textually: every `'log'`, `"log"` or `` `log` `` token in
a `src/` source (pattern `LOG_ARG`) is taken for a git argument and must be followed by `'--no-show-signature'`. It has
an exemption for `'show'` used as a WingFoil command noun (`WINGFOIL_NOUN_BEFORE`) but none for `log`, so any quoted
`log` that is not a git argument fails it. `task-336` met it on the `agent execute --log` option's `name: 'log'`, and
worked around it by spelling the name `'--log'.slice('--'.length)` (`AGENT_EXECUTE_LOG_OPTION`,
`src/core/agent-execute.ts`), with a comment asking that the workaround be removed with the lint's fix.

## Steps to Reproduce

1. The rule, at `02ffe01ca`: `grep -n "LOG_ARG\|WINGFOIL_NOUN_BEFORE" test/lint/git-log-readers.test.ts` →
   ```
   56:const LOG_ARG = /(['"`])log\1/g;
   62:const WINGFOIL_NOUN_BEFORE = /'(dna|agent|workflow|memory|directive|directives)',\s*$/;
   77:    for (const match of line.matchAll(LOG_ARG)) {
   84:      if (WINGFOIL_NOUN_BEFORE.test(line.slice(0, match.index))) continue;
   ```
   l.84 is in the `'show'` loop, not in the `'log'` one: l.77–81 push a finding for every `log` match not followed by
   the flag.
2. The line it flagged: `task-336`'s refactor notes record `src/core/index.ts:2728`, `'log' not followed by
   '--no-show-signature'`. At `02ffe01ca` that line is `name: AGENT_EXECUTE_LOG_OPTION,`
   (`sed -n 2725,2730p src/core/index.ts`, the `--log` option of `agent execute`).
3. The rule matches the spelling the option would naturally have: a `node -e` applying `LOG_ARG` to the line
   `            name: 'log',` prints `1` match, and the text after it does not start with `, '--no-show-signature'`,
   so the gate reports it.
4. The workaround: `sed -n 57,62p src/core/agent-execute.ts` → the TSDoc "A workaround: `test/lint/git-log-readers.test.ts`
   has no exemption … remove it with that fix" and `export const AGENT_EXECUTE_LOG_OPTION = '--log'.slice('--'.length);`
   (added in `f84f870a4`, `git log --format='%h %s' -S"AGENT_EXECUTE_LOG_OPTION = '--log'" -- src/core/agent-execute.ts`).

## Expected Behavior

The gate flags git `log` arguments only: a `log` token that is a CLI option name or a WingFoil noun is not a reader,
and `src/` can spell `name: 'log'` plainly. After the fix, `AGENT_EXECUTE_LOG_OPTION` goes back to a literal (or is
dropped) and its workaround comment with it.

## Actual Behavior

Any quoted `log` in `src/` fails the gate, and the only way past it is to hide the token from the textual scan, which
the gate's own header warns against for real readers ("a reader written that way escapes the gate and must be avoided").
