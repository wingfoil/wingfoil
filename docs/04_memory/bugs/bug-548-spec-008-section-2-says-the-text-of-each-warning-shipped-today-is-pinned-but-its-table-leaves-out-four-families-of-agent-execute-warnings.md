# spec-008 section 6 says the text of each warning shipped today is pinned but its table leaves out four families of agent execute warnings

## Summary

`spec-008-cli-grammar` §6's paragraph **Warnings on a successful command** (the paragraph §2's `--dry-run` row cites)
ends "The text of each warning shipped today is pinned:" and gives a table. For `agent execute`'s post-run reads the table's row
"per post-run lookup that fails or reports a value of the wrong type, and per `version_args` read before the launch"
pins the lookup and `version_args` texts only. Four families of warnings that `agent execute` ships at `02ffe01ca` are in
no row:

1. the transcript source's warnings, all prefixed `usage.transcript: ` (`postRunFields` and `transcriptSource`,
   `src/agent/launch.ts`), e.g. `adapter '<name>': usage.transcript: the session id is not-reported: the transcript is
   not read`;
2. the headless output's usage warnings: `adapter '<name>': the headless output is not one JSON document: model and
   tokens not read from it` (and its over-size variant), and `adapter '<name>': the headless output's <key> is not a
   non-negative integer: not read from it` (`model`: `is not a non-empty string`; `documentUsage`, `src/agent/usage.ts`);
3. the headless session warnings, `adapter '<name>': the headless output carries no session id: session recorded as
   not-reported` (`NO_SESSION_ID`, from `task-356`) and the same ending after the output-document reasons;
4. `task-337`'s `adapter '<name>': the agent CLI changed during the run: version_args printed '<before>' before the
   launch and '<after>' after it`.

So the sentence claims more than the table holds. Either the table gains the rows, or the sentence is narrowed to the
warnings it lists (with the rest left to `spec-016` §2.6, which describes them in prose).
