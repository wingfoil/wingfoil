# On a file system that refuses hard links every agent execute run of an adapter that assigns its session id is refused

## Summary

`sessionSalt` (`src/agent/session-salt.ts`, `task-338`) creates the per-clone salt only by a hard link from a temporary
file (`linkSync`). Where the common git directory sits on a file system that refuses hard links (FAT, exFAT, some network
or FUSE mounts: `EPERM` or `ENOTSUP`), the salt is never created. `launchAgent` (`src/agent/launch.ts`) refuses the run
before the banner, so no run of an adapter declaring `session.id: assign` can start in that clone.

## Steps to Reproduce

1. Put a clone whose `git rev-parse --git-common-dir` lies on a file system without hard links, with no
   `wingfoil/session-salt` in it yet.
2. Run `wingfoil agent execute` for an adapter whose manifest declares `session.id: assign`.
3. The pinned unit test shows the same path without such a mount: `test/agent/session-salt-errors.test.ts` (`EPERM from
   link: IO naming the link syscall, no absolute path, the temporary file removed, no salt`).

## Expected Behavior

The salt is still created exactly once per clone, atomically and owner-only. For example, an exclusive create
(`O_CREAT|O_EXCL`, `flag: 'wx'`) of the salt's own name is the fallback when `link` fails with `EPERM` or `ENOTSUP`, and a
reader that finds a partial file retries before calling it malformed. Alternatively, `spec-016` §2.6 states that such a
file system is unsupported and the refusal says so.

## Actual Behavior

`IO`: `cannot create or read the session salt in the git directory (wingfoil/session-salt): EPERM: operation not
permitted (link)`. Nothing is launched and nothing is recorded. The refusal repeats at every launch, since no salt is
ever written.

## Notes

Found at `task-338`'s review: finding F2 pinned the refusal, and its follow-up candidate was this missing fallback. The
approver accepted it as a follow-up at `task-338`'s approve. Severity low: the common git directory of a developer
clone is rarely on such a file system, and an adapter that reads its session id from the output (`session.id:
output`) does not need the salt.
