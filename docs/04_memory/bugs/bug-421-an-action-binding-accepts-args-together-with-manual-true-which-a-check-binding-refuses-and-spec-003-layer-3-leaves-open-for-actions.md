## Summary

`ActionBinding` (`src/workflow/bindings.ts`) accepts a binding that declares both `manual: true` and `args`, although
`args` only constrains the placeholders interpolated into `run` and so means nothing on a binding with no command;
`CheckBinding` refuses the same pair since `task-298`, and spec-003 Layer 3 says so for checks only.

## Steps to Reproduce

On the code build (`node dist/cli.js --version` → `0.3.1 (a8a2e93a…)`), from the repository root:

1. `node -e 'const b=require("./dist/workflow/bindings.js"); console.log(JSON.stringify(b.ActionBinding.safeParse({manual:true,args:{x:"^a$"}})))'`
   → `{"success":true,"data":{"manual":true,"args":{"x":"^a$"}}}`.
2. `node -e 'const b=require("./dist/workflow/bindings.js"); console.log(b.CheckBinding.safeParse({manual:true,args:{x:"^a$"}}).success)'`
   → `false` (issue `args does not apply to a manual check binding`).
3. `sed -n 44,82p src/workflow/bindings.ts` — `CheckBinding`'s `superRefine` adds an issue for `args` (and `severity`)
   when `manual === true`; `ActionBinding`'s `superRefine` checks only "exactly one of run or manual".
4. `grep -n "ActionBinding.manual\|CheckBinding.manual\|\*.args" docs/04_memory/design/specs/spec-003-workflows-yaml-schema.md`
   — the `CheckBinding.manual` row says "`severity` and `args` do not apply to it"; the `ActionBinding.manual` row says
   only "Exactly one of `run` / `manual`", and `*.args` is declared for both kinds.

## Expected Behavior

One rule for both binding kinds: a `manual: true` binding has no command, so `args` does not apply to it and the
loader refuses it with the same message shape as for checks (`args does not apply to a manual action binding`), and
spec-003 Layer 3's `ActionBinding.manual` row says so.

## Actual Behavior

An action binding `{ manual: true, args: {…} }` loads without a diagnostic, and the `args` it declares are silently
ignored, while the same shape on a check is refused.
