## Summary

Two traceability gaps around the release smoke gate that `task-207` (W3 B3) rebuilt. (1) `task-207`'s Implementation
Notes trace it to "**Features:** X1.2 (smoke gate)", but X1.2 is *Notification Routing*; no feature of
`docs/01_vision/06_features.md` names the smoke, and no BDD scenario covers it, so the chain feature → BDD → task
breaks for the gate `dl-023` and `dl-099` §3 define. (2) The gate's evidence is a report path written twice in
`e2e-smoke.yaml`'s `gate` phase — once under `produces:`, once as the `report:` argument of the
`e2e-smoke-passed(report: …)` check — and nothing checks that the two agree: a phase whose check writes its report
elsewhere is deduced complete from the `produces:` file alone, or never.
