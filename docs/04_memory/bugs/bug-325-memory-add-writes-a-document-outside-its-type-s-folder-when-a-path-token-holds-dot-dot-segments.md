## Summary

`memory add --set <token>=<value>` substitutes the value into the type's `path` pattern unchecked, so a value
with `..` segments moves the new document out of the type's folder to anywhere inside the project root, including
`.wingfoil/`; only an escape from the root itself is refused.

## Steps to Reproduce

On `main` at `29b8406a`, with `npm run build` done:

1. `node dist/cli.js memory add --type plan --title x --set scope=../../etc --set workflow=w --set phase=p --dry-run`
   → exit 0, `"paths": ["etc/w-p-plan.md"]` (the `plan` type's path is `docs/05_plans/{scope}/{id}.md`).
2. The same with `--set scope=../../.wingfoil` → exit 0, `"paths": [".wingfoil/w-p-plan.md"]`: a Memory document
   written into the configuration directory.
3. The positive case of the existing guard: `--set scope=../../../../tmp` → `error: E_PATH_ESCAPES_ROOT: Memory
   entries must reside within the project root: 'docs/05_plans/../../../../tmp/w-p-plan.md' resolves to …, outside
   the project root.`
4. `workflow start` fills the same tokens (`--set`), so it inherits the behaviour (`task-217`'s review found it
   through `workflow start --set scope=../../etc`).

## Expected Behavior

A path token's value is refused (exit 2, naming the token) when it holds a `..` segment, an absolute path or
an empty segment, or more generally when the resolved document does not lie under the static prefix of its type's
`path` pattern (`docs/05_plans/` here); the check runs before anything is written, for `memory add` and
`workflow start` alike.

## Actual Behavior

As in steps 1–2: the document lands wherever the token points, as long as it stays inside the root.

## Notes

- Relates to REQ-SEC-06 (storage confinement), whose boundary is the project root, so this is not a breach of
  that requirement as written; it is the narrower confinement a type's `path` declares, which nothing enforces. The
  root-level guard is `resolveConfinedMemoryPath` (`task-017`).
- Medium: an agent filling tokens from untrusted input (an element title, a consumer note) can overwrite or plant a
  file under `.wingfoil/`, which the next command loads as configuration.
- Source: `task-217`'s independent review (W3 B5), follow-up "path traversal within root, pre-existing in `memory
  add` path tokens"; not introduced by `task-217`, which only reuses the token filler.
