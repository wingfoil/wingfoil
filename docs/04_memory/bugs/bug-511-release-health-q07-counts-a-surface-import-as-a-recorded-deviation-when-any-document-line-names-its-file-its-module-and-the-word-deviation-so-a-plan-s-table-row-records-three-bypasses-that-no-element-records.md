## Summary

Release-health Q07 (`scripts/release-health/measure.cjs`, function `q07`) counts a surface import that bypasses
`src/core` as "recorded" when any line of any document contains the importing file, the module it reaches and the word
"deviation"; a table row of a plan that happens to hold those words makes three bypasses count as recorded deviations
although no Memory element records them.

## Steps to Reproduce

1. On `main` at `da1f1016c`: `grep -n "deviation" scripts/release-health/measure.cjs` → lines 1871–1873
   (`deviationLines` = every document line matching /deviation/i; `recorded` = a line that includes the path and the
   module).
2. `node scripts/release-health/measure.cjs --release v0.4 --at da1f1016c --no-toolchain --offline --out <file>`
   (about 16 minutes) → Q07 `raw`: `cycles: 2`, `bypasses: 3`, `recorded_deviations: 3`.
3. The three "recorded" bypasses match one line, `docs/05_plans/rl-v1/rel-v0.1/release-implementation-rel-v0.1-plan.md`
   l.197, a wave table row that mentions the file names, the module names and "deviation" in passing.

## Expected Behavior

A bypass counts as a recorded deviation only when a Memory element states it as one — for instance an element
(decision-log, ADR, tech-spec) whose line names the importing file and the module as a deviation, or a declared list
the check reads — and plans' prose and tables never record one. At `da1f1016c` Q07 reports the six bypasses
`task-354`'s design found and `recorded_deviations: 0`.

## Actual Behavior

`recorded_deviations: 3` with no element recording any deviation; Q07 under-reports the bypasses by three.
