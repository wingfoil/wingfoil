## Summary

`memory add` sets `status: draft` as a literal (`src/memory/add.ts:244`,
`setFrontmatterEntry(document, 'status', 'draft')`), not the head of the type's machine. `spec-001` makes the
first state of `sequence` the initial state, and `spec-010`'s `status` row states it as the declared rule since
`task-153`. On a type whose machine does not start at `draft`, the new document is in a state its own machine
does not have, and the next verb refuses it.

## Steps to Reproduce

On a scratch repository:

1. `git init && node <repo>/dist/cli.js init --template Kanban`.
2. In `.wingfoil/memory.yaml`, give `bug` its own machine: `states: { sequence: [ new, done ] }`; commit.
3. `node <repo>/dist/cli.js memory add --type bug --title "First bug"` → exit 0, `bug-001-first-bug`.
4. `grep '^status:' docs/memory/bug/bug-001-first-bug.md` → `status: draft`.
5. `node <repo>/dist/cli.js memory submit bug-001-first-bug` → exit 1,
   `error: invalid state 'draft' for type 'bug'`.

## Expected Behavior

`memory add` writes `status: new`, the head of the type's `sequence` (or of `defaults.states.sequence` for a type
with no machine of its own), and `submit` then moves it to `done`.

## Actual Behavior

`status: draft`, a state the type does not declare; the document is stuck until edited by hand. Every type in
this repository starts at `draft`, so it does not fire here.
