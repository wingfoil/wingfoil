## Summary

`workflow adopt <ref> --plan` lists only the steps an adoption alone completes (`spec-017` §7.11 rule 6), so two cases
that the single form handles stay invisible: (a) a step with no candidate is listed (`candidates: []`) when `created`
is its only declared evidence, but not when it also declares a string `produces` naming the created element
(`docs/memory/bug/{id}.md`), so whether a zero-candidate step shows depends on its `produces` shape; (b) on the
`bug-ingest` workflow of the shipped templates, a bug added without `--workflow` gets `nothing to adopt` (exit 0), while
`workflow adopt <ref> --element bug:<id> --reason …` adopts it. Both are within the documented scope, but the plan gives
no hint that a candidate or a blocked step exists.

## Steps to Reproduce

On the code build (`node <repo>/dist/cli.js --version` → `0.3.1`), in a scratch repository:

1. `git init -q -b main scratch && cd scratch && git config user.name T && git config user.email t@e.x`
2. `node <repo>/dist/cli.js init --template Scrum`; `node <repo>/dist/cli.js workflow start bug-ingest` (its `capture`
   phase: `memory.add(type: bug)`, `memory.submit`, `produces: docs/memory/bug/{id}.md` —
   `cat .wingfoil/workflows/custom/bug-ingest.yaml`).
3. Case (a): `node <repo>/dist/cli.js workflow adopt bug-ingest-1-plan --plan --format json` → `"steps":[]`,
   `"orphans":[]`, exit 0 — `bug-ingest.capture` is blocked on a creation and has no candidate, but is not listed. For
   contrast, a step whose only evidence is `created` is listed with `candidates: []`
   (`sed -n 40,43p test/workflow/adopt-plan.test.ts`: "a step with no candidate is listed and stops its branch",
   `{ step: 'life.seed', type: 'release-line', candidates: [], recorded: false }`).
4. Case (b): `node <repo>/dist/cli.js memory add --type bug --title "a stray bug"` (no `--workflow`) → `bug-001-a-stray-bug`.
5. `node <repo>/dist/cli.js workflow adopt bug-ingest-1-plan --plan; echo $?` → `nothing to adopt`, exit 0.
6. `node <repo>/dist/cli.js workflow adopt bug-ingest-1-plan --element bug:bug-001-a-stray-bug --reason "added without
   --workflow." --dry-run` → a dry-run record `workflow: adopt bug-ingest-1-plan bug-ingest.capture
   bug:bug-001-a-stray-bug`, exit 0 (written without `--dry-run`, it succeeds; `workflow next` then shows the step with
   `evidence missing: created` until the bug is submitted).

## Expected Behavior

`--plan` tells the user every frontier step blocked on a creation and every candidate it knows of, even when an
adoption alone would not complete the step: (a) a zero-candidate step is listed whatever its `produces` shape, a
string `produces` naming the created element being treated as met by the creation, as the rule already does for a
step with candidates; (b) a step with a candidate that adoption would not complete on its own (here: the bug still
needs its `memory submit`) is listed with that candidate and a note, or the output names the single-form command,
instead of a bare `nothing to adopt`.

## Actual Behavior

Case (a) prints no step; case (b) prints `nothing to adopt` (`grep -n "nothing to adopt" src/core/workflow-adopt.ts`,
line 290: printed when `steps`, `orphans` and `applied` are all empty), although an adoptable element exists.
