## Summary

When an in-place DNA write rewrites a key line that carries an inline comment, `rewriteKeyLine`
(`src/dna/edit.ts`) keeps the comment at the column it had, counting every character before it as one column,
and fills the gap with spaces. A tab between the value and the `#` is therefore replaced by spaces: one space
when the new value is as long as the old, more when it is shorter. The rest of the file is kept byte for byte,
so the edit is not minimal on exactly the line it touches.

## Steps to Reproduce

With the code build on `main` at `29d2aea2` (`node dist/cli.js --version` → `0.2.2 (29d2aea2...)`), in a scratch
git repository scaffolded by `node dist/cli.js init --template Scrum`:

1. Replace the `project.name` line of `.wingfoil/dna.yaml` with `  name: ab`, a tab, then `# your project
   name`, and commit. `sed -n 9p .wingfoil/dna.yaml | od -c` → `... n a m e : a b \t # ...`.
2. `node dist/cli.js dna set project.name --value cd` → exit 0, commit `wf(dna): set project.name`.
3. `sed -n 9p .wingfoil/dna.yaml | od -c` → `... n a m e : c d   # ...`: the tab is now a single space.

## Expected Behavior

The whitespace between the value and the inline comment is kept as written when it can be (a tab stays a tab),
or the rule for re-aligning it is stated and applies to tabs as a tab, not as one column.

## Actual Behavior

A tab before an inline comment becomes one or more spaces on every in-place rewrite of that line.

## Notes

- Low, and pre-existing: `rewriteKeyLine` dates from `task-093` (`git log -L` on it → `a1615a94`, v0.2), and
  `dna set` already reached it through `applyDnaEditInText` before `task-193` (`git show 8441ade7^1:src/core/index.ts
  | grep -n applyDnaEditInText` → the import and the call). `task-193` made the in-place path the only one without `--force`, so
  the behaviour now applies to every unforced DNA write. A shorter value pads to the old column: `--value c` on the same line
  → two spaces before `#`.
- Tabs are legal YAML whitespace after a value (not as indentation), and a hand-edited `dna.yaml` may carry
  them; `task-193`'s goal was that a DNA write keeps the file as written except for the edited value.
