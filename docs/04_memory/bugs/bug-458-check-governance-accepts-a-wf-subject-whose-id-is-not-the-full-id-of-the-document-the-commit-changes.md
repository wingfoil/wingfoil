## Summary
`scripts/check-governance.cjs` does not check that the id in a `wf()` subject is the full id of the Memory document the commit
changes. A hand `wf(bug): sync bug-316 [in-progress → in-review]` — short id — passes with 0 findings, although every other `wf()`
subject names the full id (AGENTS.md §5.1) and `workflow next` prints the full id (`expectedCommit`, `src/core/workflow-next.ts`).

## Steps to Reproduce
1. On a task branch of `release/0.3`, commit a bug's status sync by hand with the short id in the subject — as `task-312`'s
   `6ecfc503c`, `80ec071aa`, `a2edb2dc6` (`wf(bug): sync bug-254 [in-progress → in-review]`, …).
2. `npm run -s check:governance -- --base origin/release/0.3` → `gated: 0 findings`, `history: 0 findings`.
3. `git log release/0.3 --format=%s | grep "^wf(bug): sync"` → every one of them carries the full id.

## Expected Behavior
`check:governance` reports a `wf()` commit whose subject names an id that is not the full id of a document the commit changes (a
short id, a typo, another element), with the commit and the expected id; `memory history` keeps reading such a commit by its path.

## Actual Behavior
No check compares the subject's id with the changed document's id; the short subject passes. `memory history` reads the commit by
path, so nothing downstream breaks, and the drift goes unnoticed.
