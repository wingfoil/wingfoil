## Summary

`agent execute` reads the agent CLI's version with `version_args` after the run (`spec-016` §3.3 step 16, by design),
so an agent CLI that updates itself during the session is recorded at the version it updated to, not the one that
ran; and with a self-updating CLI the built-in's `verified_with` is a moving target.

## Steps to Reproduce

1. `sed -n 283,290p src/agent/launch.ts` (`main` at `bd55f70e`) → the post-run lookups run `version_args` and record
   its first non-blank line as `agent_version`; `spec-016` §3.3 step 16 (line 510) places them after the agent exits.
2. `task-236`'s by-hand pass of the `claude-code` built-in (run `adhoc/2`, 2026-10-14, its Execution Notes, "Version
   drift"): before the run `claude --version` → `2.1.296 (Claude Code)` and `readlink -f $(which claude)` →
   `~/.local/share/claude/versions/2.1.296`; the agent's own `claude --version` during the session said `2.1.296`;
   afterwards `readlink -f $(which claude)` → `…/versions/2.1.299`, and the run record's `agent_version` says
   `2.1.299 (Claude Code)`.
3. `spec-016`'s revision of 2026-10-14 (`task-236`) records the same: "`verified_with` stays `2.1.296`, the version
   the check was made with".

## Expected Behavior

The record names the version that ran: `version_args` is read before launch (and, if it changes, after the run too,
with both recorded), so a mismatch with `verified_with` is visible.

## Actual Behavior

The record misstates the agent's version whenever the CLI updates itself during a session.
