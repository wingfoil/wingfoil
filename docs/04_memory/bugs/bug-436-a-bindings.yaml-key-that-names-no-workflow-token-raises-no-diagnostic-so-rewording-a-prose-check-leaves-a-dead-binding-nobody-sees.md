## Summary

A `checks:` or `actions:` key in `.wingfoil/workflows/bindings.yaml` that no workflow token uses is accepted
silently. A prose check is keyed by its text (as `tokenName` cuts it, per the bindings.yaml header). If that check is
reworded, its old key stays in the file, bound to nothing. The reworded check then comes back as a
`W_WORKFLOW_UNBOUND_TOKEN` warning, but nothing reports the dead key. This repository notices only because
`test/core/workflow-manual-prose-checks.test.ts` pins the manual occurrences. A project without such a test never
notices.

## Steps to Reproduce

In a scratch repository, with `WF="node <checkout>/dist/cli.js"` (code build, `0.3.1`):

1. `git init -q s && cd s && git config user.name T && git config user.email t@t && $WF init --template Scrum`
2. `$WF workflow list --format json | node -e 'console.log(JSON.parse(require("fs").readFileSync(0)).diagnostics.length)'` → `0`.
3. Write a bindings file whose keys match no token of the scaffold's workflows, and commit it:
   ```
   printf 'checks:\n  no-such.check: { manual: true }\n  "a reworded prose check": { run: [node, -e, "0"] }\nactions:\n  no-such.action: { manual: true }\n' > .wingfoil/workflows/bindings.yaml
   git add -A && git commit -qm bindings
   ```
4. `$WF workflow list --format json | node -e 'console.log(JSON.parse(require("fs").readFileSync(0)).diagnostics.length)'` → `0`;
   `$WF workflow list >/dev/null; echo $?` → `0`.

`grep -rhoE "[EW]_BINDING[A-Z_]*" src/ | sort -u` lists only `E_BINDING_AGENT_CHECK`, `E_BINDING_BUILTIN_TOKEN`,
`E_BINDING_COLLECTION_KEY` and `E_BINDING_PARTIAL_INTERPOLATION`. None of them is about an unused key.

## Expected Behavior

The registry reports each binding key that no loaded workflow's `actions:` or `checks:` token names, as a warning on
the bindings file and key, for example `W_BINDING_KEY_UNUSED`. A dead key is then visible on every `workflow list`,
just as an unbound token is.

## Actual Behavior

Unused keys are accepted with no diagnostic, and exit code `0`.
