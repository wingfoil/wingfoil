## Summary

`wingfoil init --template Kanban` (and `--template Scrum`) writes `team.roles` as bare names —
`developer, reviewer, qa, architect, product-owner, tech-lead, approver` — with no `description`, although the DNA
schema accepts one per role (`RoleEntry` in `src/dna/schema.ts`: `name`, optional `description`). A summary generated
from the DNA, such as the cheat sheet of `dl-211`, can then say who does what only by role name. Found by the
cheat-sheet prototype (input given privately to the approver, 2026-11-04).

## Steps to Reproduce

1. In a scratch repository: `git init`, `wingfoil init --template Kanban --no-interactive` (pinned build 0.3.2).
2. `wingfoil dna show --format json` → `team.roles` = `[{"name":"developer"}, {"name":"reviewer"}, …]`, no
   `description`.
3. `grep -n -A8 "^  roles:" src/storage/templates.ts` → `dnaYaml(def)` writes the role list as `- name: <role>` lines, the same for
   every template (so Scrum is the same; Scrum was not run).

## Expected Behavior

Each scaffolded role carries a one-line `description` of its responsibility in that template's process (e.g. the
`approver` holds every approval gate), so the DNA states the roles it binds
directives to.

## Actual Behavior

Roles are names only.
