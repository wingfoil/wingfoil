## Summary

`spec-016` §2.2–§2.3 accept adapter manifests that cannot work, and `task-177`'s validator
(`src/agent/manifest.ts` `crossFieldIssues`, `src/agent/placeholders.ts` `placeholderIssues`) implements the spec
as written, so it accepts them too. §2.3 says where each placeholder is *legal*, never where one is *required*:

- `mcp.via: config-file` with no `{mcp_config_file}` in `launch.*.args`: the registration file is rendered and
  never handed to the agent, which runs without the `wingfoil` MCP server (`adr-012` refuses an adapter that
  cannot register it);
- `prompt.via: arg` with no `{bootstrap}` in `launch.*.args`: the agent starts without its bootstrap (likewise
  `prompt.via: file` without `{bootstrap_file}`);
- `session.id: assign` with `session.assign_args` that carry no `{session_id}`: the assigned id never reaches the
  agent, and the run record names a session that does not exist;
- `session.resume.supported: true` with no `session.resume.args`: resume is declared and has no argv (read from
  v0.4, §7).

Three related gaps in the same contract:

- §3.7 has no row for "the selected adapter is in neither directory". The code refuses it with `NOT_FOUND` and a
  worded message of its own (`src/agent/discovery.ts:144-146`); the spec gives the test nothing to pin.
- `prompt.via: stdin` is in the §2.2 enum but unreachable in format 1: `launch.interactive` is required, and `stdin`
  is legal only beside a headless-only launch, so every manifest declaring it is refused
  (`src/agent/manifest.ts:54-58`). The enum offers a value no valid manifest can hold.
- Discovery passes over some entries silently and lists others it can never load. `listAdaptersAtRev` skips a
  `.yml` file and a nested `custom/<dir>/<name>.yaml` without a word, and lists `custom/Bad Name.yaml` as adapter
  `Bad Name`, which `loadAdapter` then refuses as "not an adapter name". The finding said `agent list` should
  warn; in `spec-016` §5 `agent list` lists runs and waiting steps, not adapters, and no command lists adapters
  yet (`CORE_MODULES`' `agent` module has no operations). The warning belongs to whichever surface first
  enumerates adapters (`wingfoil init`'s install, a future `doctor`/`agent adapters`).

## Expected Behavior

A manifest that validates can launch: each `via` choice requires its placeholder in `launch.*.args`,
`session.assign_args` requires `{session_id}`, and `resume.supported: true` requires `resume.args` carrying it.
§3.7 has a row for an adapter found in neither directory. The format-1 enum holds only reachable values, or says
why it does not. Files under `.wingfoil/agents/` that are not adapters, and names outside the id class, are
reported where adapters are enumerated.

## Actual Behavior

All four broken manifests are accepted; the not-found refusal is unspecified; `stdin` is an enum value no valid
manifest can use; discovery ignores and mis-lists files without a word.
