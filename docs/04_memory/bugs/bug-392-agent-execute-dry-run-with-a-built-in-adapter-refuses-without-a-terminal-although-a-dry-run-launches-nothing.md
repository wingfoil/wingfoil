## Summary

`wingfoil agent execute --dry-run` with a built-in adapter (`claude-code`, `codex-cli`) refuses with `interactive
launch needs a terminal on stdin and stdout` when stdin or stdout is not a terminal, although a dry run only prints the
launch it would make and starts no agent; so an agent, a script or CI cannot use it to read the bootstrap it would be
given — the use `docs/agents.md` §5 offers it for, with that limit stated.

## Expected Behavior

A dry run prints its plan whether or not stdin and stdout are a terminal: the terminal check guards the spawn, which a
dry run does not make. If a dry run is meant to prove the launch would succeed, the plan says the terminal check would
fail instead of refusing (for instance a `warnings` entry), so the bootstrap and the run record stay readable. This
changes `spec-016`'s `--dry-run` paragraph ("runs steps 1–12 — every refusal included") first, for step 12.

## Actual Behavior

Exit `1` with `error: interactive launch needs a terminal on stdin and stdout`; nothing is printed. The v0.3 user
documentation records this as current behaviour (`docs/user-guide.md` §9.4, `docs/agents.md` §5's row for
`wingfoil://session/{role}/{element}/{state}`, written by `task-289`).
