# A conflicted merge committed with cleanup whitespace keeps git's Conflicts comment block as its final paragraph so co-author-identity reads no trailer there

## Summary

When a merge with conflicts is committed with `--cleanup=whitespace`, git keeps its `# Conflicts:` comment block in the
message, after the trailers. `git-conventions` §2/§8 and the tool pass that option on every commit. The block then
becomes the message's final paragraph. `task-352`'s `co-author-identity` check in `scripts/check-governance.cjs` reads
the trailers from the final paragraph, so on such a merge it finds no co-author. `trailer-paragraph` skips merges. A
wrong `Co-Authored-By:` or a `WingFoil-*` trailer on such a merge is therefore never judged.

## Steps to Reproduce

1. In a scratch repository, make a merge that conflicts and resolve it.
2. Run `git commit --no-edit --cleanup=whitespace --trailer "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"`.
3. The message reads: `Merge branch 'side'`, a blank line, the `Co-Authored-By:` line, a blank line, `# Conflicts:`,
   `#<TAB><file>`.
4. `git log -1 --format='%(trailers:key=Co-Authored-By,valueonly)'` prints the co-author, because git's reader skips
   comment lines. `co-author-identity` (once `task-352` is merged) reads only the `#` lines as the final paragraph and
   reports nothing.

## Expected Behavior

The governance check reads a merge's trailers as git does. Either it drops the lines starting with git's comment
character before taking the final paragraph, or it reports a message whose last paragraph is a `# Conflicts:` block.
Alternatively, `git-conventions` names the way to commit a conflicted merge without the block, for example `git commit
-m` or `-F` with the full message.

## Actual Behavior

The comment block is taken as the final paragraph. The co-author and any `WingFoil-*` trailer above it are not read,
and the merge passes unjudged.

## Notes

Found at `task-352`'s re-review after its merge of `main`. The developer's first merge commit had the block after the
pair. It was rewritten before any other commit (the merge `cb57e4121` carries no `#` line). The reviewer reproduced the
behaviour in a scratch repository. The cause is an existing practice, `--cleanup=whitespace` on a conflicted merge.
`task-352`'s final-paragraph reading of the co-author is what makes the trailers invisible. Severity low: it needs a
hand-resolved conflicted merge carrying an agent pair, and no commit on `main` shows it today.
