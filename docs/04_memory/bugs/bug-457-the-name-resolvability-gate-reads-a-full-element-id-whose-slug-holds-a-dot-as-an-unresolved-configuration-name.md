## Summary
`test/docs/name-resolvability.test.ts` classes a backticked token as an element id with `ELEMENT_ID`
(`test/docs/support/name-resolvability.ts:86`), whose slug part is `(?:-[a-z0-9]+)*` with no dot. A full element id whose slug holds
a file name — `task-312-fix-in-place-dna.yaml-…`, `bug-216-memory.yaml-id-pattern-…` — is therefore not an element id, falls through
to `CONFIG_PATH` (line 95) and fails the gate as an unresolved configuration name.

## Steps to Reproduce
1. On `release/0.3` (`f52abb6e2`), cite a full element id with a dotted slug in backticks in a document the suite reads, e.g. a
   Revision note of a tech-spec naming `task-312-fix-in-place-dna.yaml-edits-and-warnings-dead-setter-removed-tabs-kept-extra-paths-categories-accepted`.
2. `npx jest test/docs/name-resolvability.test.ts --maxWorkers=2` → the suite fails on that token as a configuration name.
3. In node, the two expressions on that id: `ELEMENT_ID` → `false`, `CONFIG_PATH` → `true` (the same for bug-255's full id).

## Expected Behavior
A full element id resolves as an element id whatever its slug holds: `ELEMENT_ID` admits `.` in the slug, as its `-plan` branch
already does, and the gate passes on a document citing a dotted full id.

## Actual Behavior
The gate fails, and a document must cite the element by its short id instead (97 element files under `docs/04_memory` have a dotted id).
