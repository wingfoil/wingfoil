## Summary
`bug-340`'s Expected Behavior has two parts: the out-of-frontier `--step` refusal lists the frontier keys, and an unscoped step key (for
example `bug-ingest.capture`) is accepted when exactly one frontier step has it (`spec-017` §4.9, §7.10). Release-planning ruling R8 for
`patch-v0.3.2` kept the first part for `task-330` (`details.frontier`) and deferred the second. No element holds the deferred part:
`grep -rln "unscoped" docs/04_memory/bugs/` finds `bug-340` and an unrelated bug only.

## Steps to Reproduce
1. On a project with one open instance whose frontier holds the step `bug-ingest.capture`, run `wingfoil memory add --type bug --title x
   --workflow <instance> --step bug-ingest.capture` with the key as the frontier lists it but without the scope the frontier prints.
2. The command refuses it as not on the frontier.

## Expected Behavior
An unscoped key that matches exactly one frontier step resolves to it in `memory add --step`, `agent execute --step` and `workflow finalize`;
two or more matches keep the ambiguity refusal that lists them; no match keeps the out-of-frontier refusal with `details.frontier`.

## Actual Behavior
Only the full key is accepted.
