## Summary

`bug-198` covers the CLI read commands in a repository with **no** `.wingfoil/` (they should give the
`WINGFOIL_NOT_INITIALIZED` refusal), and `task-174` gave `wingfoil mcp` that refusal for the same state. A
`.wingfoil/` that exists but is incomplete or invalid is a different state that neither covers, and there every
surface still leaks the absolute path of the file it tried to read: the DNA and Memory loaders read and label
`join(root, '.wingfoil', ...)` (`src/core/loaders.ts:165-166`, `:249`), so a missing file surfaces as Node's raw
`ENOENT: no such file or directory, open '<abs>/.wingfoil/dna.yaml'` and every validation issue is labelled
`(<abs>/.wingfoil/dna.yaml)`. Over MCP, each `wingfoil://memory/*` Resource read answers JSON-RPC `-32603` with
the raw `ENOENT` and the absolute path when `memory.yaml` is missing.

## Steps to Reproduce

With the code build on `main` at `d3724884`, in scratch git repositories:

1. `.wingfoil/` holding only a `.gitkeep`, committed:
   - `node dist/cli.js mcp </dev/null` → exit 1, `error: ENOENT: no such file or directory, open
     '<abs>/.wingfoil/dna.yaml'`;
   - `node dist/cli.js dna show` and `node dist/cli.js paths` → exit 1, the same line.
2. Same repository, `.wingfoil/dna.yaml` = `version: 1`, `project: {name: x}`, `modules: 5`:
   `node dist/cli.js mcp </dev/null` and `node dist/cli.js dna show` → exit 1,
   `error: E_VALIDATION modules (<abs>/.wingfoil/dna.yaml): Invalid input: expected array, received number;
   E_VALIDATION stacks (<abs>/.wingfoil/dna.yaml): ...` (four issues, each with the absolute path).
3. A repository scaffolded by `node dist/cli.js init --template Scrum`, then `git rm .wingfoil/memory.yaml` and
   commit: an `@modelcontextprotocol/sdk` stdio client on `node dist/cli.js mcp` →
   `readResource({ uri: 'wingfoil://memory/task' })` rejects with `MCP error -32603: ENOENT: no such file or
   directory, open '<abs>/.wingfoil/memory.yaml'`; `wingfoil://dna` reads fine.
   `node dist/cli.js memory search x` → `error: ENOENT: ... '<abs>/.wingfoil/memory.yaml'`.

(`<abs>` stands for the scratch repository's absolute path, printed in full by every command above.)

## Expected Behavior

A missing configuration file is reported as such, naming the repository-relative path
(`.wingfoil/dna.yaml is missing`, with what to do), and validation issues are labelled with the
repository-relative path, as the `HEAD:`-labelled loaders already do (e.g. adapters,
`HEAD:.wingfoil/agents/custom/fake.yaml`). Over MCP, a Resource read on an incomplete configuration answers with
a WingFoil error naming the missing file, not an internal error carrying a host path.

## Actual Behavior

Raw `ENOENT` text and absolute host paths reach the CLI's stderr and the MCP client, for every state between
"no `.wingfoil/`" and "a valid configuration".
