## Summary

The pinned build (`wingfoil-released`, 0.2.2) reports a `wf(…): amend` commit in `memory history` with `"operation":
null`, where the code build reports `"amend"`: 0.2.2 predates the `amend` verb, so a read on the pinned build — the
build `wingfoil-cli` §1 assigns the reads to — misreports every amendment.

1. At `main` `02800955`, built: `npm run -s wingfoil -- --version` → `0.2.2`.

   keeping the entries whose subject contains `amend` → `[{"sha":"d5cc135b","op":null,"subj":"wf(decision-log): amend
   dl-163-consumer-projects-feedback-so…"}]`.
3. `node dist/cli.js memory history dl-163-consumer-projects-feedback-sources-and-the-feedback-loop --format json`, the
   same filter → `[{"sha":"d5cc135b","op":"amend", …}]`.

## Expected Behavior

advances to a published build that reads `amend` (`release-planning`'s `advance-pinned-build`, `dl-095`), not when a
fix merges into `main`, where the code build already reads it.
