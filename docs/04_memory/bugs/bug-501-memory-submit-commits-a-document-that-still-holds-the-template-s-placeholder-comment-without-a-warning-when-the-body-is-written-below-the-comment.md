## Summary

When the body of a Memory document is written below a template placeholder comment instead of in its place,
`memory submit` commits the document with the comment still in it and says nothing; the commit body reports
"Carries content: the body". Reproduced on 0.3.2.

## Steps to Reproduce

On the pinned 0.3.2 build, in a throw-away repository (`git init`, `wingfoil init --template Kanban
--no-interactive`):

1. `wingfoil memory add --type bug --title "Probe"`; fill the required frontmatter.
2. Under a section, append body text below its `<!-- … -->` placeholder, leaving the comment.
3. `wingfoil memory submit <id>` → exit 0, no warning; the commit body says `Carries content: the body`.
4. `git show HEAD:<element file> | grep -c '<!--'` → 1.

## Expected Behavior

`memory submit` warns (on stderr and in `--format json` diagnostics) for every template placeholder comment left in
the body, naming its section; a type or project may make it an error.

## Actual Behavior

The comment is committed silently with the content.

## Notes

- Source: input given privately to the approver, 2026-11-05 (first seen on 0.2.2).
- By contract since `bug-146` (closed, v0.3): the templates say to replace the comments yourself and that `submit`
  commits the document as left. This asks for a check of that instruction, not a change of it.
- A placeholder comment is recognisable: the scaffold's comments are known from the type's `template.file`
  (`memory.yaml`), so the check compares against them rather than banning every comment.
