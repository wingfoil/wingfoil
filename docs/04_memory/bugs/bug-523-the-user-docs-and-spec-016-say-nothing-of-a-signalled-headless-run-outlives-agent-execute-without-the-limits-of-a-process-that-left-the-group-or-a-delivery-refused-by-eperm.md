## Summary

After `task-355`, `docs/cli-reference.md` (the headless `agent execute` paragraph) and spec-016 §3.3 step 15 say that
nothing of a signalled or timed-out headless run outlives `agent execute`. Two cases are outside that promise: a process
the agent moved out of its process group (`setsid`, a detached child), which the group delivery and the sweep do not
reach; and a delivery that the system refuses with `EPERM`, which `task-355`'s refactor turns into a warning line
(`could not send <SIGNAL> to the agent's process group <pgid>: <message>`) while the run goes on.

## Steps to Reproduce

1. On `main` after `task-355` merges: `grep -n "outlives" docs/cli-reference.md docs/04_memory/design/specs/spec-016-agent-execution.md`
   → the unqualified sentence in both.
2. `grep -n "could not send" src/agent/launch.ts` → the warning path where a delivery fails and the run continues.

## Expected Behavior

Both documents state the promise with its two limits in one clause: a process that left the agent's group is not
reached, and a refused delivery is reported as a warning.

## Actual Behavior

The promise is stated without qualification.
