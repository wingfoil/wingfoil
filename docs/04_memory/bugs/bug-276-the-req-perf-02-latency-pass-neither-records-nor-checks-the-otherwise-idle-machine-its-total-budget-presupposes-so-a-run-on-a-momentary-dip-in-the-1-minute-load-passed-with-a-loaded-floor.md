## Summary

Since `task-248` (`dl-146` option (C)), `test/cli/command-latency.test.ts` asserts the total p95 of `memory search`,
`dna show` and `memory history` against 1,000 ms as well as the marginal, and the SARD makes "an otherwise idle
machine" part of REQ-PERF-02's measurement conditions. Nothing in the pass records the machine's load or checks the
condition: whether a run is a valid REQ-PERF-02 measurement depends on how its operator judged "idle". During
`task-248` a run started on a momentary dip of the 1-minute load average passed while the machine was still loaded.

## Steps to Reproduce

On `main` at `f15096a2`:

1. `grep -rn loadavg test scripts src jest*.js` → nothing; `sed -n 92,102p test/cli/command-latency.test.ts` → the
   only opt-in output (`WINGFOIL_LATENCY_REPORT=1`) prints the floor, marginal and total distributions, with no load
   figure.
2. `sed -n 9,13p docs/02_requirements/03_sard/02_performance-nfr.md` → the measurement conditions, "on an otherwise
   idle machine", and `dl-146`'s figures (total p95 at most 287 ms idle, up to 1,028 ms at a 1-minute load of
   about 18).
3. `task-248`'s Execution Notes, "latency pass (AC 3)": run 2 started when a watcher saw the 1-minute load drop below
   2 (1.94, 5-minute 4.13); its floor was 886 ms (idle: 194 to 203 ms) and it passed, with a 12 ms margin on the
   `memory search` total. Run 3, after waiting for 1-minute < 2 and 5-minute < 3, measured a 194 ms floor.
4. `sed -n 72,73p docs/04_memory/design/dls/dl-146-*.md` → option (C)'s stated cost: "the total's assertion is only
   as meaningful as the "idle" condition is honoured by whoever runs the opt-in pass".

## Expected Behavior

The latency pass keeps the SARD's wording (the condition is defined by `dl-146`, its enforcement left open), and
makes a loaded run visible instead of silently valid: it records `os.loadavg()` (1- and 5-minute) before and after in
its report, and warns, or refuses to count the run, when the 5-minute load is high or the floor's p95 is far above
its idle value (e.g. over about 500 ms against an idle 200 ms).

## Actual Behavior

A pass on a loaded machine and a pass on an idle one print the same verdict and no evidence of the difference; the
idle check is whatever the operator chose ("1-minute load < 2" in `task-248`, which run 2 shows is weak).
