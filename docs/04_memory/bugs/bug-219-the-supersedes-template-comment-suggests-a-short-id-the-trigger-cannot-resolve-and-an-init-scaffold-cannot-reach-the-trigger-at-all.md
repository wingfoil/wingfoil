## Summary

Two gaps around the `supersedes:` trigger (`task-162`):

1. **This repository's templates suggest an id the trigger cannot resolve.** `.wingfoil/memory/templates/adr.md:7`
   and `tech-spec.md:7` comment `supersedes: "" # optional — id of the ADR this one replaces, e.g. "adr-002"`
   (`"spec-002"` for tech-spec). The trigger resolves the value as a full document id, so the short form the
   comment shows makes the approve fail.
2. **A `wingfoil init` project cannot reach the trigger.** The scaffolded templates have no `supersedes` field
   (`grep -rn supersed src/storage` → nothing), and the scaffolded `memory.yaml` gives every type the default
   machine `[draft, pending, approved]`, with no `superseded` state or `waiting` edge. The field cannot be added
   later either: `memory amend` refuses it (`AMEND_RESERVED_FIELDS`, `src/core/memory-amend.ts:34`).

## Steps to Reproduce

1. `sed -n 7p .wingfoil/memory/templates/adr.md .wingfoil/memory/templates/tech-spec.md` → the two comments above.
2. On a scratch repository with an `adr` machine `[draft, pending, accepted, superseded]`, `waiting: [accepted]`,
   an approver member and a `supersedes: ""` template field (`bug-218`'s setup), with `adr-002-b` existing:
   `memory add --type adr --title C`, set `supersedes: "adr-002"`, `memory submit adr-003-c`,
   `memory approve adr-003-c --reason "ok C"` → exit 1,
   `error: cannot approve adr-003-c: its supersedes: field names adr-002, which cannot be superseded: document not found: adr-002`.
3. Fresh scaffold: `git init && node <repo>/dist/cli.js init --template Kanban`, then
   `grep -c supersedes .wingfoil/memory/templates/*.md` → `0` for all seven templates;
   `grep -c "superseded\|waiting" .wingfoil/memory.yaml` → `0`.

## Expected Behavior

1. The comment shows a full id (`e.g. "adr-002-git-backed-storage"`), or the trigger accepts the numeric prefix
   when it names exactly one document of the type.
2. The `init` scaffold declares what `spec-001`/`spec-010` describe for `adr` and `tech-spec`: a `supersedes`
   field in their templates and a machine with the `superseded` `waiting` edge, or the documentation states that
   a new project must add both by hand.

## Actual Behavior

The documented short id fails the approve, and a new project has neither the field nor the edge.
