## Summary

`test/cli/dry-run.integration.test.ts` is the table that covers `--dry-run` on every operation registered `mutates:
true`. It runs each row's dry run with `--format json` only, which bypasses the console renderer. A console dry run
that crashes therefore passes the table. This is how the `workflow finalize --dry-run` crash of 0.3.0 shipped (the bug
filed with this one). `task-295` added console cases for four commands. Warning tests run three more without a plan check. That leaves
15 of the table's 22 rows never run in the console format.

## Steps to Reproduce

On `release/0.3` (`8e7fc43b`):

1. `grep -n "'--dry-run', '--format', 'json'" test/cli/dry-run.integration.test.ts` → line 286: the only dry run of
   the success rows.
2. `awk '/^const ROWS/,/^};/' test/cli/dry-run.integration.test.ts | grep -cE "^  [a-zA-Z]+: "` → `22` rows:
   `agentExecute`, `dnaSet`, `dnaAdd`, `dnaUpdate`, `dnaRemove`, `memoryAdd`, `memorySubmit`, `memoryApprove`,
   `memoryReject`, `memoryDeprecate`, `memoryPark`, `directiveCreate`, `directiveAssign`, `directiveRemove`,
   `workflowStart`, `workflowEnd`, `workflowFinalize`, `workflowAdopt`, `workflowRekey`, `workflowCreate`,
   `workflowRemove`, `memoryAmend`.
3. `sed -n 344,361p test/cli/dry-run.integration.test.ts` → the refusal cases, which assert an `error:` line and an
   empty stdout, never a printed plan. `grep -n "'--force', '--dry-run'" test/cli/dry-run.integration.test.ts` →
   lines 394 and 417. These are the only successful console dry runs in the file, `dna add --force` and `directive
   assign --force`. They assert exit 0 and the warning on stderr, not the plan on stdout. Outside the file, `grep -n
   "'--dry-run'\]" test/cli/agent-execute.integration.test.ts` → lines 275 and 405, the same kind of case for `agent
   execute`.
4. `grep -n "it('" test/cli/workflow-console-dry-run.integration.test.ts` → the console cases `task-295` added: `start`
   (characterization), `rekey`, `adopt`, `finalize`.

## Expected Behavior

Every row of the table also runs its dry run without `--format`. The check is exit 0, empty stderr, a non-empty plan
on stdout, and nothing written (`assertPersistenceUnchanged`). A mutating operation added later is then held to the
console path as well as the JSON one.

## Actual Behavior

The console plan is pinned for `workflow start`, `rekey`, `adopt` and `finalize` only, and outside the table
(`test/cli/workflow-console-dry-run.integration.test.ts`, `task-295` commit `95e864c9`). `dna add`, `directive
assign` and `agent execute` reach the console renderer only through warning tests. Spot checks found no further
crash today. In a scratch repository `init --template Scrum`-ed with `node dist/cli.js` at `8e7fc43b`, console
`--dry-run` of `dna set project.name --value X`, `memory add --type bug --title T`, `directive create --name
dry-rule`, `workflow create dry-flow --kind main` and `workflow start bug-ingest` each exited 0 and printed a plan,
and `git status --porcelain` stayed empty. So the defect is the missing guard, not a present crash.
