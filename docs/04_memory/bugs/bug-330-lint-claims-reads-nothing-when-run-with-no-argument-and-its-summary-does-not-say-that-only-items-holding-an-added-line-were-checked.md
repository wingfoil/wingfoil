## Summary

The claim lint (`scripts/lint-claims.cjs`) does read Memory task notes; what the B5 reports took for a skip
is two documented behaviours its output does not explain: with no `--base` and no file it reads nothing, and with
`--base` it checks only the items holding an added line, while its summary counts files read.

## Steps to Reproduce

On `main` at `29b8406a`:

1. `node scripts/lint-claims.cjs | tail -1` (also what `npm run lint:claims` runs) → `claim lint: 0 warnings in 0
   files (warn-only), 0 files read`, exit 0: nothing says a range or a file is needed.
2. Positive case, task notes are read: `node scripts/lint-claims.cjs --base be0a59ab^1 | tail -2` → a warning on
   `docs/04_memory/v0.3/task-224-add-readme-badges-reproducible-terminal-demo-drives-example.md:165` and `claim lint:
   1 warnings in 1 file (warn-only), 4 files read`.
3. `node scripts/lint-claims.cjs docs/04_memory/v0.3/task-229-create-github-release-once-npm-has-version-sweep.md |
   tail -1` → `1 warnings in 1 file …, 1 file read`: linted whole, the file has an item that `--base` on the task's
   own branch did not report (`task-229`'s notes record `--base 30b268a3` → `0 warnings`), because that item held no
   added line.
4. `sed -n 24,29p scripts/lint-claims.cjs`: the usage documents both behaviours; the printed summary does not.

## Expected Behavior

With no `--base` and no file the lint says so (a usage line on stderr, or exit 2 as for bad usage), and the
summary distinguishes files read from items checked (e.g. `… 1 file read, 3 items with added lines checked`), so a
report of "0 warnings" cannot be mistaken for a skipped document. The kit's and the gates' invocations pass
`--base`.

## Actual Behavior

As in steps 1 and 3.
