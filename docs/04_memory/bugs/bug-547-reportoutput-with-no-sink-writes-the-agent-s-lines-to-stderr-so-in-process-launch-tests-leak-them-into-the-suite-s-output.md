# reportOutput with no sink writes the agent's lines to stderr so in-process launch tests leak them into the suite's output

## Summary

Since `task-336`, a headless agent's output is forwarded line by line through `reportOutput`
(`src/validation/warning.ts`): to the output sink the CLI registrar installs (`withOutputSink`), or, when none is
installed, straight to `process.stderr`. A test that runs `agent execute` in process, without installing a sink, lets
the launched fake agent's lines through to the terminal, so they appear among Jest's results in a full-suite run. Only
two test files install a sink (`grep -rln "withOutputSink" test` → `test/agent/launch-usage-sources.test.ts`,
`test/agent/launch-output.test.ts`).

## Steps to Reproduce

1. `grep -n -A4 "export function reportOutput" src/validation/warning.ts` (at `02ffe01ca`) →
   `109:export function reportOutput(line: string, stream: OutputStream): void {`, `110:  const sink = outputStore.getStore();`,
   `111:  if (sink !== undefined) sink(line, stream);`, `112:  else process.stderr.write(\`${line}\n\`);`.
2. `npx jest test/core/agent-execute.test.ts --maxWorkers=1 -t "AC 4: a real headless run with terminal: required"` →
   the test passes (`Tests: 40 skipped, 1 passed, 41 total`), and before Jest's summary the output carries the line
   `{"session_id":"7bd78c9f-…","model":"fake-model","usage":{"input":120,"output":45,"cache_read":10,"cache_write":5}}`:
   the fake agent's headless JSON document (`test/fixtures/agents/fake-agent.cjs:423`, written when `argv` holds
   `--headless`). The test is `test/core/agent-execute.test.ts:438`.
3. The whole file, `npx jest test/core/agent-execute.test.ts --maxWorkers=1` → `41 passed` and the same one line. Not
   counted here: the other in-process launch suites (`grep -rln "runAgent\|agentExecuteFn" test/agent test/core` lists
   nine files).

## Expected Behavior

A test's own launches leave no lines in the suite's output: either the in-process launch tests install a sink (or a
shared helper does), or a test run without a sink does not reach `process.stderr`. The CLI's behaviour — the agent's
lines on stderr, through the registrar's sink — is unchanged.

## Actual Behavior

The fake agent's output lines are printed among the test results, which makes a real failure's output harder to read
and looks like a stray warning.
