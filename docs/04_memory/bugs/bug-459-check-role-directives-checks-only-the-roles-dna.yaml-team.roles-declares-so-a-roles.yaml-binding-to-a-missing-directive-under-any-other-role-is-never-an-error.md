## Summary
`npm run check:role-directives` (`scripts/check-role-directives.cjs`) runs `directives list --role <r>` only for the roles `dna.yaml`
`team.roles` declares. A `roles.yaml` binding to a missing directive under any other role is never an error, and since `task-310` the
unfiltered `directives list` reports every dangling binding as a warning, which the script does not read. The script is also not in the
npm package (`package.json` `files` → `["dist","README.md"]`), so a project that uses WingFoil has no such check at all.

## Steps to Reproduce
1. In a project made with `wingfoil init --template scrum` (code build of `release/0.3` after `task-310`), add `ghost-directive` under
   `qa:` and a role `intern: [ghost-intern]` to `.wingfoil/roles.yaml` (`intern` is not in `dna.yaml` `team.roles`).
2. `wingfoil --format json directives list` → exit 0, warnings `directive 'ghost-directive' bound to role 'qa' has no directive file`
   and `directive 'ghost-intern' bound to role 'intern' has no directive file`.
3. `node scripts/check-role-directives.cjs --root <project>` → `role-directives: 7 roles checked, 2 with warnings` (approver, qa), exit 1;
   `intern` is never reported.

## Expected Behavior
The configuration check fails on every dangling binding of `roles.yaml`, whatever role it is under: it reads the unfiltered listing's
dangling-binding warnings (once the pinned build carries them), not only the `--role` view of the `team.roles` roles.

## Actual Behavior
Only the `team.roles` roles are checked; a dangling binding under another role passes the check with exit 0 for that role.
