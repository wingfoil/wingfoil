## Summary

`git-conventions` §1 rule 6 sets up the merge-forward worktree with `npm ci` alone, then runs
`node scripts/check-governance.cjs --base origin/main` there. The script needs the code build in `dist/`, and refuses
without it (exit 2). So step (3) of the rule cannot run as written.

## Steps to Reproduce

1. `git show main:.wingfoil/directives/custom/git-conventions.md | sed -n 160,163p` → step (1) is "`git fetch
   origin`, `git worktree add --detach <path> origin/main`, `npm ci` there", and step (3) is "`npx jest
   test/lint/version-bump.test.ts` and `node scripts/check-governance.cjs --base origin/main`".
2. `grep -nE '"(prepare|postinstall)"' package.json` → nothing, so `npm ci` builds no `dist/`.
3. `git show main:scripts/check-governance.cjs | sed -n 205,212p` → the script requires `dist/memory`, `dist/core` and
   others. On `task-366`'s branch it refuses at once with `error: …/dist is not built: run npm run build first` (the message quotes the command), exit
   2 (reproduced by `task-366`'s review in a fresh worktree).

## Expected Behavior

Step (1) of rule 6 builds the code: `npm ci` and `npm run build` there. Step (3) then runs the governance check
without an error.

## Actual Behavior

An approver following rule 6 word for word gets exit 2 from step (3), and must know to build first. The
accepted-finding sentence that `task-366` adds to rule 6 (`bug-448`) depends on step (3) running.
