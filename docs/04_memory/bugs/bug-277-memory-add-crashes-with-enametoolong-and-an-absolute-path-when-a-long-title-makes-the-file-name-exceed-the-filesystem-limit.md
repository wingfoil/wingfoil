## Summary

`memory add` builds the document's file name from the title's slug (`slugifyTitle`, `src/memory/add.ts`) with no
length limit, so a long title produces a file name over the filesystem's limit (`NAME_MAX`, 255 bytes on Linux) and
the command fails with Node's raw `ENAMETOOLONG` error, which names the absolute path, instead of a WingFoil refusal.

## Steps to Reproduce

On `main` at `5d716f28`, in a scratch repository:

1. `git init`, set a local identity, then `node dist/cli.js init --template Scrum`.
2. `node dist/cli.js memory add --type bug --title "<a 249-character title, 'word' repeated 50 times>"`.
3. The command exits 1 with `error: ENAMETOOLONG: name too long, open '/tmp/<scratch>/docs/memory/bug/bug-001-word-word-...-word.md'`
   (the absolute path of the scratch repository on stderr).
4. `git status --short` is empty and `git log --oneline | wc -l` is 1 (the init commit): nothing is written or
   committed, and a retry with a shorter title gets the same id.

## Expected Behavior

Either the slug is bounded so that the file name always fits (a declared maximum length, cut at a word boundary,
deterministic per REQ-SYS-07, with the full title kept in the `title` field), or the title is refused before any
write with a WingFoil error naming the limit and the field, at exit 2, with no absolute path on stderr.

## Actual Behavior

Exit 1 with Node's raw error text and an absolute host path, the class `bug-251` and `bug-245` describe for
configuration reads.
