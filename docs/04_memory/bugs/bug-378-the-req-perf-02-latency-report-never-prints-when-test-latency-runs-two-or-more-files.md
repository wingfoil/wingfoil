## Summary

With `WINGFOIL_LATENCY_REPORT=1`, `npm run test:latency` is meant to print the REQ-PERF-02 suite's report (the load
window, the `machine:` idle verdict and the per-command distributions), which release-health's Q12 reads. The suite
prints it with `console.log` in an `afterAll`, and when the latency pass runs two or more test files that output
does not reach the log. The pass has run three files since `task-283`, and two before it, so release-health cannot
read REQ-PERF-02 from it at all: Q12 comes out `not-measurable` ("printed no latency report") on every run.

## Steps to Reproduce

On `main` at `327a7b01`:

1. `grep -n "LATENCY_SUITES:" test/latency-suites.cjs` → three files: `test/cli/command-latency.test.ts`,
   `test/cli/workflow-next-command-latency.test.ts` and `test/core/workflow-next-latency.test.ts`.
2. `grep -n "console.log\|process.stdout.write" test/cli/command-latency.test.ts
   test/cli/workflow-next-command-latency.test.ts test/core/workflow-next-latency.test.ts` → the REQ-PERF-02 suite
   prints `latencyReport(…)` with `console.log` (in its `afterAll`, under `WINGFOIL_LATENCY_REPORT === '1'`); the two
   `workflow next` suites print their lines with `process.stdout.write`.
3. The W3 B8 gate ran `WINGFOIL_LATENCY_REPORT=1 npm run test:latency` twice on `e9c71f1a` (a loaded run, exit 1,
   and an idle one, exit 0, 3 suites, 18 tests). Both logs carry the two `workflow next` lines and neither carries the
   report: no `machine:` line at the start of a line, no `floor (--version):` line and no per-command `marginal p95`
   line (`grep -c "^[[:space:]]*machine: " gate-w3b8-latency.log gate-w3b8-latency1.log` → `0`, `0`; the

4. `grep -n "function parseLatencyReport\|function q12" scripts/release-health/measure.cjs`: `parseLatencyReport`
   returns `null` when no line matches `^[ \t]*machine: `, and `q12` then reports `not-measurable` with "npm run
   test:latency printed no latency report (exit …; WINGFOIL_LATENCY_REPORT=1 was set)".

The coordinator observed the mechanism in this environment while reviewing `task-283` (follow-up item 13): jest
showed no `console.log` output when it ran two or more test files, while `process.stdout.write` always showed.

## Expected Behavior

With `WINGFOIL_LATENCY_REPORT=1`, every `npm run test:latency` run prints the REQ-PERF-02 report whatever the number
of files the pass selects, and release-health's `parseLatencyReport` reads it, so Q12 measures REQ-PERF-02 at the
v0.3 release-health.

## Actual Behavior

The report is printed only when the REQ-PERF-02 suite runs alone; in the pass as configured it never appears, and Q12
cannot be measured.
