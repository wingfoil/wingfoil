## Summary

Two `where` shapes that can never select anything load without a diagnostic:

- **`where.type` under a Memory `iterate_over`.** The candidates of `iterate_over: <T>` are documents of type `T`
  (`spec-017` §4.6), so a `where.type` naming another type (`iterate_over: task`, `where: { type: bug }`) or a type
  `memory.yaml` does not declare matches nothing, and the phase is vacuously complete. `workflowCoreDiagnostics`
  (`src/core/workflow-core-checks.ts`) checks `where.type` only for a selection (`over === undefined`); its comment
  gives the reason — with `iterate_over`, `type` "may be a collection entry's field" — which holds for a collection
  reference (`dna:`, `bindings:`) and not for a Memory type.
- **An empty type list in a selection.** `E_PHASE_SELECTION_UNTYPED` (`src/core/workflow-diagnostics.ts`) checks only
  that the `type` key exists (`hasOwnProperty`), so `where: { type: [] }` is accepted, and the per-value loop of
  `E_WORKFLOW_ELEMENT_TYPE_UNKNOWN` has no value to check. The selection selects nothing and the phase is
  vacuously complete.

`task-264` (`done`) closed `bug-282` for the selection and the typed actions; these two shapes are what its review
left.

## Expected Behavior

`spec-003` decides both: under a Memory `iterate_over`, a `where.type` is either refused (it can only repeat the
iterated type) or checked to equal it and to be a `memory.yaml` type; and a selection's `type` is non-empty
(`E_PHASE_SELECTION_UNTYPED` covers an empty list, or a new row does). `workflowCoreDiagnostics` and the per-phase
checks follow the table.

## Actual Behavior

Both shapes pass every load-time check and, at deduction, make the phase vacuously complete, so a typo or an empty
list silently skips a phase.
