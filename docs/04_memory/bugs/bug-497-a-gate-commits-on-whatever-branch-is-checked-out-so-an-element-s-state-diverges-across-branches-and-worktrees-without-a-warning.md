## Summary

`memory approve` (and every transition verb) commits on the branch that is checked out. An element submitted on one
branch and approved on another is `pending` on the first and `approved` on the second; in a repository with linked
worktrees, an approval run in a task's worktree lands on the task's branch. Nothing declares which branch an element's
state belongs to, and nothing warns. Reported by a consumer on 0.2.2; **not reproduced on 0.3.2** (the reproduction
needs a multi-branch set-up and was not attempted in the read).

## Steps to Reproduce

As reported (to re-run on 0.3.2 at triage):

1. Throw-away repository: `git init`, an identity, `wingfoil init --template Kanban --no-interactive`, a member
   holding `approver` added to `team.members`.
2. `wingfoil memory add --type bug --title "Probe"`, `wingfoil memory submit <id>` on the default branch.
3. `git switch -c other`, `wingfoil memory approve <id> --reason ok`.
4. `git log -1 --format=%s other` → the approve commit; `git show <default branch>:<element file> | grep '^status:'`
   → still the pre-approval state.

## Expected Behavior

The branch an element's state belongs to is declared (per type or per project, for example the integration branch),
and a transition run on another branch warns, or refuses unless told otherwise.

## Actual Behavior

The transition is committed on the current branch silently; the divergence is found later and the approval must be
cherry-picked.
