## Summary

`docs/agents.md`, the guide for agents in a project that uses WingFoil, sets rules but no level of process. Its table
of reads gives `wingfoil memory search --type <type> [--status <s>]` for current work and decisions and leaves the
status to the agent; it does not say that the elements an agent records stay in a pre-approval state until an approver
moves them, nor where knowledge given in a request (a rule meant for later) belongs. A consumer's agent read with
`--status approved` and found nothing in almost every step (reported on 0.3.0).

## Steps to Reproduce

1. `grep -n "memory search" docs/agents.md` → line 47: `memory search --type <type> [--status <s>]` for "current
   work and decisions", with no recommended status.
2. `grep -niE "pending|stays|until.*approv" docs/agents.md` → no match (read on the phase branch, 2026-11-05): nothing says an agent's own records wait for the
   approver.
3. No section says where a rule given in a request is recorded (a decision-log, a directive, or nowhere).

## Expected Behavior

The guide says which states count as current for each read (for example every non-deprecated state, not only the
approved one), that an agent's own records stay pending until an approver moves them and must still be read, and where
request-time knowledge goes; and it describes levels of process (a light and a strict one) a project can name.

## Actual Behavior

Each project picks a status filter and a level of process by itself; a strict filter hides the agent's own work.
