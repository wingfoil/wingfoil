## Summary

`src/core` and `src/agent` import each other (`src/core/index.ts` → `agent-execute.ts` → `src/agent` → `run-log.ts` →
`src/core/*`), so a module-level constant built from the other side's export can be `undefined` depending on which
module loads first; and the `*AtRev` loaders label a file `<rev>:<path>` with whatever rev string their caller passed,
so a caller that resolved `HEAD` first prints a 40-hex label.

## Steps to Reproduce

1. `task-228`'s Execution Notes: `launch.ts` held `NO_TOKENS` as a module constant built from `run-log.ts`'s
   `NOT_REPORTED`, which the cycle left `undefined` under one load order; `03a382dc` ("read NOT_REPORTED at call time
   (core/agent import cycle)") fixed that constant only.
2. On `main` `02800955`, built: a probe that requires one `dist/` module first, then `dist/core/index.js`, and lists
   every `CORE_MODULES` operation whose `fn` is not a function (the `task-228` reviewer's `order.cjs`) prints
   `core/agent-show  agent.agentShow.fn`, `core/agent-execute  agent.agentExecute.fn`, and `core/index  ok` when
   `dist/core/index.js` is loaded first.
3. `task-228`'s notes: "The AtRev loaders label a file `<rev>:<path>` with whatever string the caller passed, so a
   caller that resolved `HEAD` first gets a 40-hex label; `agent execute` rewrites it, other callers do not"; it
   printed the `dna.yaml` unknown-field warning under a full-sha label until `task-228` rewrote it to `HEAD:`.

## Expected Behavior

No import cycle between `src/core` and `src/agent` (or a test that loads every `dist/` module first, in turn, and
checks that `CORE_MODULES` and every exported constant are defined), and the `*AtRev` loaders take an optional
`label` parameter so the caller decides how the source is named; `agent execute`'s rewrite then goes away.

## Actual Behavior

The cycle exists; one constant was fixed by hand; labels depend on the caller's rev string.
