## Summary

Three gaps in how `dev-loop` and the plans carry their notes: `dl-115`'s plan half (a plan reaching `done` carries
`### Retrospective`) has no check, because plans are finalized by hand; `dev-loop`'s `done.checks.post`
`retrospective.present(…)` cannot be bound, because no binding placeholder carries the task's path (`{task.path}`);
and a decision-log that a task absorbs is handed to the task at `design` by no step, since `design` reads only the
`depends_on` tasks' notes.

1. `dev-loop.yaml` 1.6, phase `done`, `checks.post`: `"retrospective.present(the task's ### Retrospective
   subsection, …)"` with the comment "the file is the element's path, which no binding placeholder carries yet";
   `task-221`'s design decision 1: "unbound: the file it reads is the task's path, which no binding placeholder can
   carry today (a `{task.path}` interpolation does not exist)".
2. `task-221`'s developer notes (W3 B4 follow-up log): "dl-115 plan half (plan done needs `### Retrospective`) has no
   check — plans finalized by hand". No workflow phase finalizes a `plan` (`wf(plan): finalize` commits are written
   by hand, e.g. `a61e09a0`).
3. `task-197`'s inventory, row 14: the v0.2 plan's rule "a decision-log a task absorbs … is handed to the task
   explicitly at `design`, because `read_related` covers `depends_on` tasks only" lands nowhere: `dev-loop.yaml`'s
   `design` step (2) reads the Execution Notes of `depends_on` tasks only, and `dl-102` §4 (`task-221`'s criterion
   check) compares criteria with directives and ratified specs, not with absorbed decision-logs.
