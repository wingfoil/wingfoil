## Summary

`node scripts/e2e-smoke.cjs --candidate` (`task-219`) refuses to run whenever `git status --porcelain` prints
anything, untracked files included, so the release gate cannot pass on a checkout that holds untracked notes;
while it does not notice what does change the build: `npm pack`'s `prepack` (`tsc`) leaves modules of deleted
sources in `dist/`, and they are packed. Three wording defects ride on the same gate.

## Steps to Reproduce

1. On a clean checkout of `main` at `02800955`, built: `touch zz-untracked-note.txt`, then `node
   scripts/e2e-smoke.cjs --candidate --report <scratch>/r.md` → `error: --candidate: the working tree is not clean,
   so the build would not be the candidate commit: ?? zz-untracked-note.txt`, exit 1, before packing.
2. The check is `prepareCandidate`'s `effects.status()`, bound in `realCandidateEffects` to `git status --porcelain`
   with no pathspec (`scripts/e2e-smoke.cjs`). `scripts/write-build-info.cjs` decides the same question for the build
   stamp with `git status --porcelain --untracked-files=all -- <BUILD_INPUTS>` (`BUILD_INPUTS` = `package-lock.json`,
   `package.json`, `scripts/write-build-info.cjs`, `src`, `tsconfig*.json`), so the two disagree about what a clean
   candidate is.
3. Stale modules: `package.json` has `"prepack": "npm run build"`, `"build": "tsc -p tsconfig.build.json && node
   scripts/write-build-info.cjs"` and `"files": ["dist", "README.md"]`; `tsc` does not delete outputs whose source
   was removed, so a `dist/` built before a source file was deleted packs that file's module (`task-219`'s
   independent review).
4. Wording: the `e2e-smoke.yaml` `gate` phase `description` ("Run the smoke and record its report …") does not say
   the check smokes the packed candidate, though its binding is `[node, scripts/e2e-smoke.cjs, --candidate,
   --report, "{report}"]` (`bindings.yaml` 1.6, `e2e-smoke-passed`). `.wingfoil/WORKFLOW.md` ("so it runs per candidate
   and never in CI"), `release-publishing.yaml`'s `staging-rehearsal` description ("not in CI (dl-099 §4)") and
   `spec-015` ("not part of `publish.yml` or CI") say the staging rehearsal never runs in CI, while
   `.github/workflows/publish.yml`'s `stage` job runs `npm run publish:staging -- --tarball … --expect-commit
   "$GITHUB_SHA"`, which starts Verdaccio (its header comment, `stage →`).
