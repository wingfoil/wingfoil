## Summary

`idPatternIssues` (`src/validation/id.ts:156`) reports a malformed `id_pattern` (a token that is neither a
`{n}`-family token nor a field name, a dotted token, a literal outside `[a-z0-9-.]`). Its only caller is the
workflow loader (`src/workflow/schema.ts:64`). `memory.yaml`'s own `id_pattern` is a bare
`z.string().optional()` (`src/memory/schema.ts:146`), so a malformed token passes loading, and `memory add`
treats it as a missing field token and advises a `--set` that the CLI then refuses.

## Steps to Reproduce

1. `grep -rn "idPatternIssues" src | grep -v "^src/validation"` → `src/workflow/schema.ts:18` (import) and
   `:64` (call), nothing under `src/memory` or `src/core`.
2. `node -e "console.log(require('./dist/validation/id').idPatternIssues('bug-{n:0}-{slug}'))"` →
   `[ 'malformed token {n:0}' ]`.
3. On a scratch repository (`git init`, `node <repo>/dist/cli.js init --template Kanban`), set `bug`'s
   `id_pattern` to `"bug-{n:0}-{slug}"` and commit.
4. `node <repo>/dist/cli.js memory add --type bug --title "X"` → exit 1,
   `error: missing value for token {n:0}: give it with --set n:0=<value>`.
5. `node <repo>/dist/cli.js memory add --type bug --title "X" --set n:0=1` → exit 2,
   `error: invalid flag value: --set name "n:0" is not a field name ([a-z][a-z0-9_-]*)`.
6. `node <repo>/dist/cli.js memory search x` → exit 0: no command reports the configuration as invalid.

## Expected Behavior

Loading `memory.yaml` runs `idPatternIssues` on every type's `id_pattern` (`spec-009` Pass 2) and refuses a
malformed one with the type and the issue (`memory.yaml: types.bug.id_pattern: malformed token {n:0}`), so no
command gives advice that cannot be followed.

## Actual Behavior

The malformed pattern loads; `memory add` advises `--set n:0=<value>`, which the CLI's own `--set` name rule
rejects.
