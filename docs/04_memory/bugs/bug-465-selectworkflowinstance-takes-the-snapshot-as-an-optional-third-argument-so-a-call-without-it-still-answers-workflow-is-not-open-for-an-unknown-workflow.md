## Summary
`task-323` (w2 of `patch-v0.3.2`) corrects `selectWorkflowInstance` (exported by the package's `main`) to give spec-017 §10's
answers (`unknown workflow: <ref>` for a name that is no workflow, `workflow is not open: <ref>` for a loaded workflow or an instance
plan that is not open). To keep the patch backwards compatible, the approver ruled at `task-323`'s design gate that the snapshot the
answer needs stays an optional third argument: `selectWorkflowInstance(deduction, ref?, snapshot?)`. Called without the snapshot, the
function cannot tell an unknown name from a workflow that is not open, and keeps answering `workflow is not open` for both. The
TSDoc and the CHANGELOG say so, and that the snapshot becomes mandatory in v0.4.

## Steps to Reproduce
1. After `task-323`'s merge, call `selectWorkflowInstance(deduction, 'nope')` without the snapshot on a project with no workflow
   named `nope`.
2. The answer is `workflow is not open: nope`; with the snapshot it is `unknown workflow: nope`.

## Expected Behavior
In v0.4 the signature is `selectWorkflowInstance(deduction, snapshot, ref?)`: the snapshot is mandatory, every call gives §10's
answer, and the CHANGELOG records the breaking change of a `main` export.

## Actual Behavior
The snapshot is optional; a call without it gives an unreliable answer, documented but not refused.
