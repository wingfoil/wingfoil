## Summary

`spec-007` §2 is the canonical secret pattern table: ten YAML `regex:` strings
(`docs/04_memory/design/specs/spec-007-secret-hygiene-patterns.md`, lines 67-116). `SECRET_PATTERNS`
(`src/validation/secret-scan.ts:51`) re-types each one as a JS `RegExp`, with a comment quoting the spec string
above it, and translates the PCRE inline modifiers by hand: `(?i)` becomes the `i` flag, and on
`generic-api-key-assignment`, whose spec text holds a case-sensitive `(?-i:...)` group Node 22 cannot parse, the
key words are case-folded letter by letter (`caseless`, since `bug-228`). The tests pin the ids, the order and
the severities (`test/validation/secret-scan.test.ts:32-60`) and the behaviour on chosen inputs, but nothing
compares the spec's ten strings with the code: a later edit to either side can change what is matched without
any test failing. The `task-182` reviewer checked the current equivalence by hand.

   words and unflagged `RegExp`.

## Expected Behavior

A test fails when `spec-007` §2 and `SECRET_PATTERNS` disagree. Either it reads the ten `regex:` strings from the
spec, applies the declared translation (`(?i)`/`(?im)` to flags; the `(?-i:...)` case as `caseless`) and compares
sources, or it runs both forms over a shared corpus of positive and negative lines per pattern and requires the
same verdicts. The first is exact; the second survives a translation the first does not model.

reviewer.
