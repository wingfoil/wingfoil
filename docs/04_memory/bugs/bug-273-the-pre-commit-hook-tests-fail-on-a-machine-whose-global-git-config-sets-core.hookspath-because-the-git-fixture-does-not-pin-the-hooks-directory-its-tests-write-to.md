## Summary

Five `test/core` suites test what a verb does when a pre-commit hook refuses its commit, by writing
`<repo>/.git/hooks/pre-commit` into a fixture repository from `makeTempGitRepo` (`test/storage/helpers/git-fixture.ts`).
The fixture sets the identity, `commit.gpgsign` and `gc.auto` locally, but not `core.hooksPath`, and does not isolate
the global config. On a machine whose global config sets `core.hooksPath` (a common way to install team-wide hooks),
git never runs the planted hook and ten tests fail.

## Steps to Reproduce

On `main` at `f15096a2`:

1. `sed -n 36,51p test/storage/helpers/git-fixture.ts` → `init`, `user.email`, `user.name`, `commit.gpgsign`,
   `gc.auto`; no `core.hooksPath`.
2. `grep -rl 'pre-commit' test --include=*.ts | xargs grep -l hooks` →
   `test/core/{config-writer-confinement,core-index-arms,memory-supersede,memory-transition-commit-scope,write-guard-committed-paths}.test.ts`,
   each planting `join(repo, '.git', 'hooks', 'pre-commit')`.
3. A global config file holding only `[core] hooksPath = <an empty scratch directory>`, then
   `GIT_CONFIG_GLOBAL=<that file> npx jest <the five suites>` → `Test Suites: 5 failed`, `Tests: 10 failed, 67
   passed, 77 total`; `GIT_CONFIG_GLOBAL=<that file> npx jest test/core` → the same five suites fail, 10 of 2,345
   tests. Without the variable the five suites pass, 77/77.
4. With one line added to `makeTempGitRepo`, `git(dir, ['config', 'core.hooksPath', '.git/hooks'])`, step 3's run
   passes, 77/77 (change reverted after the check).

## Expected Behavior

The fixture repository's hook directory is the one its tests write to, whatever the developer's global git config
says: `makeTempGitRepo` (and `cloneTempRepo`, since `git clone` does not copy local config) sets `core.hooksPath`
to `.git/hooks`.

## Actual Behavior

The hook tests depend on the machine's global git configuration.

## Notes

- Low: the machine this was captured on sets no global `core.hooksPath` (`git config --global --get core.hooksPath` →
  exit 1), so the suite is green there; it fails for a contributor who uses global hooks.
- Several suites already isolate the global config for identity checks (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`
  in `test/core/approval-authority.test.ts`, `init.test.ts`, `directive-remove.test.ts`, `memory-approve.test.ts`);
  pinning the one key in the fixture is narrower and covers every hook test at once.
