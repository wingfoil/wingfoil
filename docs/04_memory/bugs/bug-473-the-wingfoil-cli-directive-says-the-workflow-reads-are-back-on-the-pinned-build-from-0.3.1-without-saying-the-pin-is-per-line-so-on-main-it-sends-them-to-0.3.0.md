## Summary

`.wingfoil/directives/custom/wingfoil-cli.md` (version 1.4) §1 says that while the pin was 0.3.0 the workflow reads ran
on the code build, and that "from 0.3.1 the reads are back on the pinned build". It does not say that the `dl-095` pin
is per line (`dl-159` A2 item 5). `main` pins `wingfoil@0.3.0`, and a merge forward keeps `main`'s pin
(`git-conventions` §1 rule 5), so on `main` the directive sends the workflow reads to 0.3.0, which refuses this
repository's `manual: true` check binding (`bug-414`). `AGENTS.md` §3 and `.wingfoil/README.md` were qualified with "the
pin is per line" in v0.3.2's `user-docs` phase; the directive, which is not in that phase's `produces:`, was not.

## Steps to Reproduce

From the repository root on `main` (`1db90b57f`):

1. `git show origin/main:package.json | grep wingfoil-released` → `"wingfoil-released": "npm:wingfoil@0.3.0"`;
   `git show origin/release/0.3:package.json | grep wingfoil-released` → `npm:wingfoil@0.3.1`.
2. `sed -n 50,55p .wingfoil/directives/custom/wingfoil-cli.md` → "… from 0.3.1 the reads are back on the pinned build
   and `npm run check:mcp` declares no known read failure."
3. `grep -n "per line" AGENTS.md .wingfoil/README.md .wingfoil/directives/custom/wingfoil-cli.md` → hits in
   `AGENTS.md` (line 110) and `.wingfoil/README.md` (line 31), none in the directive.

## Expected Behavior

The directive says the pin is read per line: the workflow reads run on the pinned build of a line whose pin is 0.3.1
or later, and on the code build of a line still pinned at 0.3.0 — as `AGENTS.md` §3 says.

## Actual Behavior

The directive states the rule without the line qualifier, which is false on `main` until v0.4's
`advance-pinned-build` moves `main`'s pin.
