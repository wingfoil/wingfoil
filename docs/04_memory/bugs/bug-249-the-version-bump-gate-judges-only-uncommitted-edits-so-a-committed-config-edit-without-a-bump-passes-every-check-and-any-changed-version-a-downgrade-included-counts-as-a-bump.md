## Summary

`task-183` closed `bug-143` with a version-bump check (`test/lint/helpers/version-bump.ts`,
`checkPendingVersionBumps`) that judges only the **pending** change: the working tree against `HEAD`. An edit
to `dna.yaml`, `memory.yaml`, `workflows.yaml` or `roles.yaml` that is committed without running the suite is
never judged afterwards, and on a clean CI checkout the working tree equals `HEAD`, so the check has nothing to
judge there. Separately, the check accepts **any** change of the YAML-read `version:` as a bump, including a
downgrade or a change of quoting alone.

## Steps to Reproduce

On `main` at `29d2aea2`:

1. `sed -n 112,130p test/lint/helpers/version-bump.ts` (`checkPendingVersionBumps`) → the loop skips every file for which
   `differsFromHead(root, path)` is false; `differsFromHead` is `git diff --quiet HEAD -- <path>`. Nothing
   compares two commits.
2. `grep -n 'version' scripts/check-governance.cjs` → one match, the `assign release {version}` subject rule;
   the script judges the `wf()` commits of the `--base` range (subject, bracket, body, authority, state rules,
   per its header), never a config file's `version:`.
3. `.github/workflows/ci.yml` runs the suite on a fresh `npm ci` checkout (`npm run prepublishOnly` →
   `npm test`): the working tree is `HEAD`, so `test/lint/version-bump.test.ts`'s repository probe passes
   whatever the pushed commits did. `governance.yml` does not exist yet (`ls .github/workflows` → `ci.yml`,
   `dependency-check.yml`, `publish.yml`, `scorecard.yml`); `task-208` (`backlog`) will add it and its Notes say
   "The config version-bump check (`bug-143`) is task-183's `test/lint/` suite, which `governance.yml` runs with
   the rest of the suite": true of the suite, but on CI that suite judges nothing.
4. Line 130 of the helper: `if (read.version !== headVersion) continue;`. With js-yaml,
   `node -e "const y=require('js-yaml');console.log(String(y.load('version: 1.0').version),String(y.load('version: \"1.0\"').version))"`
   → `1 1.0`: re-quoting `1.0` as `"1.0"` reads as a different version and passes as a bump, and so does
   `2.5` → `2.4`.

## Expected Behavior

A committed edit to one of the four versioned config files that leaves `version:` unchanged is caught where
commits are judged: a range rule in `scripts/check-governance.cjs --base <sha>` (for each of the four files whose
bytes differ between the merge-base and `HEAD`, the YAML-read `version:` must differ too), so the CI governance
run `task-208` builds enforces `bug-143` on what was pushed. A bump is a numeric increase, not any difference.

## Actual Behavior

Only an uncommitted edit is judged. A commit made without the suite passes every check, locally and on CI, and a
downgrade or a re-quoting satisfies the gate.
