## Summary

On a fresh `init --template Scrum` project with an agent that executes the step's role, `agent list --waiting` lists
`sw-life-cycle.inception` as waiting for that agent, but `agent execute --next` refuses it with `error: step
'sw-life-cycle.inception' has no element: give --element <type>:<id>`, and the step has no element that could be given.

## Steps to Reproduce

With the code build of `main` (`node dist/cli.js --version` → `0.3.1 (a8a2e93a…)`), 2026-10-27, in an empty git
repository with an identity (`git init -b main`, `git config user.name …`, `git config user.email …`):

1. `node <wingfoil>/dist/cli.js init --template Scrum; echo $?` → `0`.
2. `node <wingfoil>/dist/cli.js workflow start sw-life-cycle` → `started sw-life-cycle as sw-life-cycle-1-plan
   (active)`, `next step: sw-life-cycle.inception`, `scope: (none)`, `role: product-owner`.
3. `node <wingfoil>/dist/cli.js dna add team.agents --value claude --entry-adapter claude-code --entry-email
   noreply@anthropic.com --entry-executes_as product-owner,developer; echo $?` → `0`.
4. `node <wingfoil>/dist/cli.js agent list --waiting` → `waiting steps: 1` / `sw-life-cycle.inception  product-owner  claude`.
5. `node <wingfoil>/dist/cli.js agent execute --next --dry-run </dev/null; echo $?` → `error: step
   'sw-life-cycle.inception' has no element: give --element <type>:<id>` and `1`.
6. `node <wingfoil>/dist/cli.js agent execute --next --dry-run --element task:task-1 </dev/null` → `error: element not
   found: task:task-1`: the only way through is to name an element that exists and is unrelated to the step.

## Expected Behavior

A step `agent list --waiting` lists is one `agent execute --next` can run. For a step with no scope element on an
instance with no bound element, either the run targets the instance's own `plan` element (`plan:<instance-id>`, which
always exists and whose run log `<runs>/<element-id>.jsonl` (`spec-016` §5.1) can hold the record), or
`agent list --waiting` leaves such a step out, or marks it as needing `--element`, so the two commands agree.

## Actual Behavior

`stepTargetElement` (`src/agent/step.ts`, `grep -n "has no element: give" src/agent/step.ts`) falls back from
`--element` to the step's scope element to the instance's bound element, and refuses with `NO_STEP_ELEMENT` when there
is none; `agent list --waiting` selects every frontier step whose role an agent executes, without that condition
(`spec-016` §5, `grep -n "waiting\*\* = " docs/04_memory/design/specs/spec-016-*.md`). Both follow `spec-016` as
written (§3.2 step 2: `grep -n "NO_STEP_ELEMENT" docs/04_memory/design/specs/spec-016-*.md`), so the gap is in the
spec as much as in the code.
