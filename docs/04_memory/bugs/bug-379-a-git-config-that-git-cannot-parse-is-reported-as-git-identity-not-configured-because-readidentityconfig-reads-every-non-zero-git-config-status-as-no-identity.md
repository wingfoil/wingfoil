## Summary

When git cannot parse the repository's `.git/config`, every mutating command refuses with REQ-SEC-01's "git identity
not configured (user.name/user.email)", although the identity may be configured and the real cause is a broken
configuration file. Same class as `bug-377` (a git that cannot be run, fixed by `task-284`): the identity check reads
a failure of git as an unresolved identity.

## Steps to Reproduce

On `main` at `327a7b01`, in a scratch repository:

1. `git init`, set `user.name` and `user.email`, make one commit, then `node <build>/dist/cli.js init --template Scrum
   --no-interactive` → exit 0.
2. `echo '[user' >> .git/config`; `git status` → `fatal: bad config line 9 in file .git/config`, exit 128.
3. `node <build>/dist/cli.js memory add --type bug --title probe` → `error: git identity not configured
   (user.name/user.email)`, exit 1.

`grep -n "function readIdentityConfig" -A18 src/core/git-identity.ts`: the `git config -z --get-regexp` spawn runs
with stderr ignored, and any non-zero status returns an empty value map with `ran: true`. Status 1 (no matching key)
and status 128 (git refused the configuration) are not told apart, so `requireGitIdentity` reaches the unresolved
branch and returns `IDENTITY_ERROR`.

## Expected Behavior

A `git config` that exits with a fatal status (128) is reported as a failure of git reading its configuration, naming
git's own message (`bad config line 9 in file .git/config`), not as an unconfigured identity; status 1 keeps
REQ-SEC-01's message.

## Actual Behavior

The user is told to configure an identity that is already configured.
