## Summary

Since `task-209` a `memory submit` commit that carries more than the state move declares it in one body line,
`Carries content: {item}, {item}` (`spec-008` § "The Memory commit subject — the closed `wf()` operation list", paragraph "`memory submit` declares
the content it carries"; written by
`formatMemoryCommitMessage`, `src/memory/commit-message.ts`). Only the writer knows the line. `memory history`
(`src/memory/history.ts`, the entry shape the CLI prints) neither parses it nor returns it, and the governance check
(`scripts/check-governance.cjs`), which already reads each `wf()` commit's `Approver:` and `Reason:` lines, does not
compare it with the diff the commit carries. A hand-written or hand-amended submit can therefore omit the line, or
name content the commit does not carry, and nothing reports it.

## Steps to Reproduce

On `main` at `0962f85f` (`npm ci && npm run build`):

1. `grep -rln "Carries content" src scripts` → `src/core/index.ts` (a comment) and `src/memory/commit-message.ts`
   (the writer's `CARRIES_KEY`); nothing under `src/memory/history.ts`, `src/memory/audit.ts` or `scripts/`.
2. Control: `grep -c "Reason:\|Approver:" scripts/check-governance.cjs` → `22`: the script reads commit bodies, so
   step 1's pattern would have found a reader of the line there.
3. `node dist/cli.js memory history <bug-278's id>` on this capture's branch → the `submit` entry for `cbf4e0de`
   holds `sha`, `author`, `timestamp`, `operation`, `from`, `to`, `approver`, `reason`, `subject`, `wingfoil`, and no
   field for the carried content, though `git log -1 --format=%B cbf4e0de` shows `Carries content: frontmatter field
   'release-origin', frontmatter field 'severity', the body`.

## Expected Behavior

The declaration is read back where the other declared body lines are: `memory history` returns the carried items
(or `null` for a pure transition), and the governance check reports a submit whose `Carries content:` line is
missing, malformed, or disagrees with what `describeDocumentChanges` finds between the parent's and the commit's
copy of the document.

## Actual Behavior

The line is written and never read; a submit that misdeclares its content passes every check.

## Notes

- Low: the tool writes the line from the same comparison the check would make, so tool-written commits are right
  by construction; the gap is hand-written and amended commits, which this repository still makes (`git-conventions`
  §8 amends every tool-written commit to add trailers).
- Commits written by the pinned build (0.2.2) carry no such line (`grep -rl 'Carries content'
  node_modules/wingfoil-released/dist | wc -l` → `0`), so a check must not demand it of submits older than
  `task-209`, the same staging the governance check already applies to history before its introduction commit.
