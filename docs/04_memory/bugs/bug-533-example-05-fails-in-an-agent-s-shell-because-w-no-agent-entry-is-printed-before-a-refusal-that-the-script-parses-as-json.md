# Example 05 fails in an agent's shell because W_NO_AGENT_ENTRY is printed before a refusal that the script parses as JSON

## Summary

Once `task-334` is merged, `docs/examples/05-ci-json-exit-codes/run.sh` exits `1` in a shell that carries an agent marker
(`CLAUDE_CODE_CHILD_SESSION`). `resolveOperationAgentContext` reports `W_NO_AGENT_ENTRY` right after membership, before
a later refusal (`document not found`). The script's `expect_exit` merges stderr into the JSON it parses. `spec-008` §6
lists `W_NO_AGENT_ENTRY` among the warnings on a successful command, so printing it ahead of a refusal may go beyond the
spec.

## Steps to Reproduce

1. With `task-334`'s build, in an agent's shell: `TMPDIR=<scratch> bash docs/examples/05-ci-json-exit-codes/run.sh`.
2. Observed by `task-334`'s review: exit `1`, `FAIL: json error object: expected 'document not found: task-999-nope', got ''`.

## Expected Behavior

Either the attribution warnings are reported only on the path that commits, or the example reads stdout alone (as a
reader would) and is run as `bug-529` rules for the approving examples.

## Actual Behavior

The warning comes before the refusal and breaks the JSON the example parses.
