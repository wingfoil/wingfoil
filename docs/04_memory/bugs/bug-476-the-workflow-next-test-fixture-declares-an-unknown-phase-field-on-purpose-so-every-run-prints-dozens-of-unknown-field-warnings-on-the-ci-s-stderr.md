## Summary

`test/core/workflow-next.test.ts` builds a fixture `dev-loop` workflow whose first phase declares `directives:` on
purpose (line 127). The workflow loader ignores the field and prints `Warning: … unknown field(s) ignored:
phases[0].directives` every time the fixture is loaded, so a single run of the suite writes dozens of such lines to
stderr, and the CI log carries them (ci run 41484515244). The tool behaves as designed; the noise is the defect: a
real loader warning in the same log reads like one more of these and passes unseen.

## Steps to Reproduce

From the repository root on `main` (`1db90b57f`), with the code build:

1. `sed -n 121,127p test/core/workflow-next.test.ts` → `name: dev-loop`, … `directives: [ code-review ]` under the
   first phase.
2. `npx jest test/core/workflow-next.test.ts --maxWorkers=2 2>&1 | grep -c "unknown field(s) ignored"` → 27.

## Expected Behavior

The suite's stderr carries no warning a test causes on purpose: the test that relies on the field asserts the warning
(capturing stderr), and the others use a fixture without the unknown field.

## Actual Behavior

27 unknown-field warnings per run of this file, repeated in every CI log.
