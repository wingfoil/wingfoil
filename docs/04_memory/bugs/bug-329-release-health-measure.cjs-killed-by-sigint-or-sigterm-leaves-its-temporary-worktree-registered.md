## Summary

`scripts/release-health/measure.cjs` runs its commit-dependent checks in a throw-away worktree under
`/tmp/wf-release-health-*/tree` and removes it only on a normal return; it installs no signal handler, so a run
interrupted with `SIGINT` or `SIGTERM` leaves the worktree registered in the repository.

## Steps to Reproduce

On `main` at `29b8406a`:

1. `grep -nE "SIGINT|SIGTERM|process\.on" scripts/release-health/measure.cjs` → only the header comment (lines
   25–27): "A run killed by a signal (SIGINT, SIGTERM, SIGKILL) leaves its worktree registered; remove it by hand
   with `git worktree remove --force /tmp/wf-release-health-<suffix>/tree`". The positive case: the same pattern over
   `scripts/publish-staging.cjs` matches its teardown handlers (`installTeardownHandlers`, `task-083`).
2. `sed -n 194,210p scripts/release-health/measure.cjs`: `mkdtempSync(join(tmpdir(), 'wf-release-health-'))`, `git
   worktree add --detach`, and the removal in the function's own `finally`, which a signal's default action never
   reaches.

## Expected Behavior

`SIGINT`, `SIGTERM` and `SIGHUP` remove the worktree (`git worktree remove --force`) and the temporary
directory, then re-raise the signal, as `publish-staging.cjs` does; `SIGKILL` stays documented as the one case left
to the user.

## Actual Behavior

As in step 1: documented, not handled.
