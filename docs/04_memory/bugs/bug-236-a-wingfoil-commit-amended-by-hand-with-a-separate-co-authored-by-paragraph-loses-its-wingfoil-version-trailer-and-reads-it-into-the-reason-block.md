## Summary

Since `task-192` every WingFoil commit body ends with its own trailer paragraph, `WingFoil-Version: <semver> (<sha>)`
(`src/storage/commit.ts:126-130`), after the `Approver:`/`Reason:` paragraph. When such a commit is amended by hand
the way this repository's commits are usually written, with a **blank line** and then `Co-Authored-By: …`, the
`WingFoil-Version:` line is no longer in the final paragraph:

- `parseReasonBlock` (`src/memory/commit-message.ts:247-257`) ends the reason at the final trailer paragraph, now
  the `Co-Authored-By:` one, so it reads `WingFoil-Version: …` into the reason;
- `parseVersionTrailer` reads only the final paragraph, so `memory history`'s `wingfoil` field
  (`src/memory/audit.ts:445`) becomes `null`;
- git's own reader agrees: `%(trailers:key=WingFoil-Version,valueonly)` returns empty;
- `check-governance` flags the commit, since a `WingFoil-Version:` line inside a reason is one of its refusals
  (`test/cli/check-governance.test.ts:202-214`): loud, but only after the commit exists.

`git commit --amend --no-edit --trailer 'Co-Authored-By: …'` appends to the existing trailer paragraph and keeps
all three readers right. Nothing an agent or a contributor reads says so.

Separately, CLAUDE.md §5.1 ("Whitespace is normalized") says the normal form is "git's own `cleanup=whitespace`,
which `git commit -m` applies regardless". That is no longer true of git nor of the tool: `git commit -m` applies
the configured `commit.cleanup`, and the tool passes `--cleanup=whitespace` explicitly for that reason
(`src/storage/commit.ts:126-130`, `bug-051`).

## Steps to Reproduce

On `main` at `0b297169`, after `npm run -s build`, in a scratch git repository:

1. Commit with a tool-shaped message: subject, blank, `Approver: A <a@b> (approver)`, `Reason: fine.`, blank,
   `WingFoil-Version: 0.3.0 (abc1234)`. `git log -1 --format='%(trailers:key=WingFoil-Version,valueonly)'` →
   `0.3.0 (abc1234)`.
2. `git commit --amend -F` the same message plus a blank line and `Co-Authored-By: C <c@d>` →
   the same `git log` prints an empty value.
3. On that body, `parseReasonBlock` → `"fine.\n\nWingFoil-Version: 0.3.0 (abc1234)"`; `parseVersionTrailer` → `null`.
4. Re-commit the step 1 message, then `git commit --amend --no-edit --trailer 'Co-Authored-By: C <c@d>'` → the
   body ends `WingFoil-Version: …` / `Co-Authored-By: …` in one paragraph; `parseReasonBlock` → `"fine."`,
   `parseVersionTrailer` → `"0.3.0 (abc1234)"`, `%(trailers…)` → `0.3.0 (abc1234)`.
5. `git -c commit.cleanup=strip commit -m "$(printf 's\n\nReason: x\n# kept?')"` → the `# kept?` line is gone:
   `-m` does not apply `whitespace` regardless.

## Expected Behavior

The documents that tell agents and contributors how to write and amend WingFoil commits (CLAUDE.md §5.1, the
`git-conventions` directive `task-178` adds, `dl-119`) say how to add a trailer to a tool commit
(`--amend --trailer`, never a new paragraph), and state the cleanup rule correctly.

## Actual Behavior

The documented practice produces commits whose reason, history and git trailers are all wrong, and CLAUDE.md
misstates `git commit -m`'s cleanup.
