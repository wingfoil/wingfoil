## Summary

`task-335` launches a headless agent `detached` (D6: its own session and process group on POSIX), but `--timeout`'s
`SIGTERM` and grace `SIGKILL`, and every forwarded signal, go to the agent's pid only (`src/agent/launch.ts`,
`takeOverSignals`' `send` → `child.kill(signal)`). The agent's children, such as the `wingfoil mcp` server it starts and
its tool subprocesses, survive the agent. Before the change, an interactive Ctrl-C reached the whole foreground group.

## Steps to Reproduce

1. On `task-335`'s branch at `0caf6ea81` (not yet merged into `main`), the spawn options for a headless launch are
   `stdio: ['ignore', 'pipe', 'inherit']`, `detached: true` (`src/agent/launch.ts`).
2. A minimal reproduction with the same options: a parent spawns `agent.cjs` (which itself spawns `sleep 30`) with
   `detached: true` and that stdio, then sends the agent `SIGKILL`. Output: `agent exit SIGKILL`, and `pgrep -x sleep`
   still lists the `sleep 30` child.

## Expected Behavior

A headless run's timeout and forwarded signals reach the agent's whole process group on POSIX
(`process.kill(-child.pid, signal)`), at least for the grace `SIGKILL`, so no child of the agent outlives the run.
Windows keeps its current behaviour.

## Actual Behavior

Only the agent's pid receives the signal; its children keep running after `agent execute` returns.

- `task-355` (L2, `depends_on: [task-335]`) changes `takeOverSignals` and `send`: the natural owner.
