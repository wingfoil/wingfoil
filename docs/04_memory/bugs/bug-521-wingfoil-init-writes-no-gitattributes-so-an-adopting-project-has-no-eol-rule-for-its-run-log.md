## Summary

`wingfoil agent execute` appends one JSON line per run to `<paths.runs>/<element-id>.jsonl` and commits it
(spec-016). `bug-318` asks for an eol rule for that log; `task-355` adds it to this repository's own
`.gitattributes`. `wingfoil init` writes no `.gitattributes`, so a project that adopts WingFoil has no eol rule for
its run log: on a checkout with `core.autocrlf=true` the committed lines can be converted, and two operators can
produce diffs that differ only in line endings.

## Steps to Reproduce

1. `grep -rn gitattributes src/ | grep -i init` → no output: no init path writes or mentions the file.
2. In an empty git repository, `node dist/cli.js init --template Scrum` (and again with `Kanban`) → exit `0`, and
   `ls -a | grep -c gitattributes` → `0` (merge build of 2026-11-09).

## Expected Behavior

`wingfoil init` adds `<paths.runs>/*.jsonl text eol=lf` to the project's `.gitattributes`, creating the file when
absent and leaving existing lines alone, or the user guide says why it does not and gives the line to add.

## Actual Behavior

No `.gitattributes` is written and the user guide does not mention one.
