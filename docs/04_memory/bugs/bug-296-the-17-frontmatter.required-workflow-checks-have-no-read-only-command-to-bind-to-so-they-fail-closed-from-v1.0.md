## Summary

The workflows of this repository declare `frontmatter.required: […]` as a post-check 17 times (the check that the
Memory elements a phase created carry their required fields). `workflows/bindings.yaml` leaves the token unbound on
purpose — "the prose checks (`frontmatter.required: […]`, …) have no command that asserts them today" — so each is a
`W_WORKFLOW_UNBOUND_TOKEN` warning, which "in v1.0 fails closed (dl-090 Q2 (c))". No shipped command can be bound to
it: the template's `frontmatter.required` list is enforced only inside `memory submit` (a mutating verb, at the
moment of the transition), and no read-only command checks the required fields of an element, or of the elements a
step created, at `HEAD`. Unless one exists before checks are executed (P4.12, v1.0), 17 phases cannot pass their own
post-check.

On `main` at `c485e433` (`npm ci && npm run build`):

1. `node dist/cli.js workflow list` (JSON) → 61 diagnostics, 0 errors; 17 are `W_WORKFLOW_UNBOUND_TOKEN` with the
   message `check token 'frontmatter.required' has no built-in or bindings.yaml binding`.
2. `grep -rnE '(pre|post):.*"frontmatter\.required' .wingfoil/workflows/custom/*.yaml | wc -l` → `16`, plus one list
   item in `service-ingest.yaml` (`- "frontmatter.required: [title, provider, kind, owner_role, verify]"`): 17 uses,

3. `node dist/cli.js memory --help` → the verbs `add`, `amend`, `approve`, `deprecate`, `history`, `park`, `reject`,
   `search`, `submit`; `node dist/cli.js --help` lists no `validate`, `check` or `doctor` command.

## Expected Behavior

A read-only command (or a core operation exposed to bindings) checks that an element at `HEAD` — or each element a
step created — carries its type's `template.frontmatter.required` fields, with the phase's extra fields from the
check's argument list (e.g. `[title, release, kind]`), exits `0`/`1`/`2` as `dl-090` Q4 requires, and
`bindings.yaml` binds `frontmatter.required` to it before v1.0 turns unbound checks into failures.

## Actual Behavior

The check is declared 17 times and assertable by nothing; it is visible only as a warning today, and would fail
closed under v1.0's rule.
