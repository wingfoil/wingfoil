## Summary

`scripts/release-health/compare.cjs` settles the previous run's `RH-<previous version>-NN` proposals against
`retro-<previous version>`, and settles every proposal as `not adopted` when that retrospective does not exist. A
patch skips the retrospective (`dl-092` Q2 (ii)) and its proposals are disposed of by the next minor's retrospective
(`dl-167` (a), `ready`; `retrospective.yaml` 1.7 `explore`), so whenever the previous run is a patch the report states
`not adopted` for proposals that are only pending.

## Steps to Reproduce

1. `sed -n 47,51p scripts/release-health/compare.cjs` → the settle rule: "`declined`, no row or no retrospective → not
   adopted (the last two: no disposition recorded)".
2. `sed -n 726,729p scripts/release-health/compare.cjs` → the retrospective read is
   `retro-${previous.release.version}`, from the `decision-log` type's path.
3. `sed -n 486,489p scripts/release-health/compare.cjs` → with no retrospective the row is `settled: 'not adopted'`,
   `note: 'no disposition recorded (no retrospective)'`.
4. `ls docs/04_memory/design/dls/ | grep retro` → `retro-v0.1.md`, `retro-v0.2.md`, `retro-v0.3.md`: no
   `retro-v0.3.1`, and none will exist (`grep -n "a patch skips the retrospective" .wingfoil/workflows/custom/retrospective.yaml`).
5. `grep -n "^### RH-v0.3.1" docs/08_health/release-health-v0.3.1.md` → `RH-v0.3.1-01`, `-02`, `-03`, which v0.3.2's
   `compare` will settle against the missing `retro-v0.3.1`.

## Expected Behavior

A proposal of a patch run whose disposition is still owed is reported as pending, for example `pending: disposed of
by the next minor's retrospective (dl-167 (a))`, not `not adopted`. At the next minor's run, whose previous run is the
last patch, the patches' proposals are settled against the retrospective that disposed of them: the one `explore`
read their reports into, which is written after that minor's `compare` runs.

## Actual Behavior

v0.3.2's `release-health` will report `RH-v0.3.1-01..03` as `not adopted` (step 3), and v0.4's will do the same for
v0.3.2's proposals, although `retro-v0.4` is the element that disposes of both.

## Notes

- The choice between the two halves of the expected behaviour is small but real: a `pending` label is mechanical;
  settling a minor run's patch proposals needs either a second pass after the retrospective, or settling them one run
  later. If the approver wants to rule on it, it belongs with `dl-167`'s ratification.
- Not reachable before `patch-v0.3.2`'s `release-health`, the first run whose previous run is a patch with
  proposals: v0.2.2 had no `release-health` run.
- Related: `dl-089` §4 (settle), `docs/08_health/report-layout.md` "Previous proposals", `dl-167` (a), `bug-362`
  (the retrospective's row format compare reads).
