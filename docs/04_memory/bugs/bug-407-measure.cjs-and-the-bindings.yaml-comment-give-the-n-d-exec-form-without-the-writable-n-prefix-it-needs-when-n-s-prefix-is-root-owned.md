## Summary

The release-health measure is documented to run under the pinned Node with `n -d exec 22.12.0`, but on a machine where `n`'s default prefix is owned by root that form needs `N_PREFIX` pointing at a writable directory, and neither the script header nor the bindings comment says so.

## Steps to Reproduce

1. `sed -n 41,43p scripts/release-health/measure.cjs`: the `n -d exec 22.12.0` form, no `N_PREFIX`.
2. `sed -n 128p .wingfoil/workflows/bindings.yaml`: the same form.
3. `release-health-rel-v0.3-plan` S2: the measure ran with `N_PREFIX` set to a writable directory because the default prefix was root-owned.

## Expected Behavior

The documented command states the `N_PREFIX` requirement (or the `npx -p node@22.12.0` alternative is given first).

## Actual Behavior

A reader following the documented form gets a permission failure from `n` and must find the variable alone.
