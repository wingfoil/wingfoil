## Summary

The release gate's version check accepts a build stamp that does not name the released commit. `runSmoke` compares
`wingfoil --version` with `--expect-version` through `versionOfStamp` (`scripts/e2e-smoke.cjs:183-187`,
`:204-207`), whose pattern `^(\S+) \((?:[0-9a-f]{7,64}(?:-dirty)?|unknown)\)$` takes `(unknown)` and `(<sha>-dirty)`
as well as `(<sha>)`, and returns only the semver. `publish-staging.cjs` passes `expectedVersion` and nothing about
the commit (`scripts/publish-staging.cjs:417`). So a tarball whose `dist/` was built by `tsc` alone (no
`dist/build-info.json`, stamp `unknown`) or from a modified tree (`-dirty`) passes the staging smoke
(`spec-015` §3 stages 2–3) and goes on to `promote`.

## Steps to Reproduce

On `main` at `0b297169`, after `npm run -s build`:

1. The pattern, extracted from the script and applied:
   `versionOfStamp('0.3.0 (abc1234)')`, `('0.3.0 (unknown)')`, `('0.3.0 (abc1234-dirty)')` → `0.3.0` all three;
   `('0.3.0')` → `null` (the bare semver is accepted by the separate equality test beside it).
2. A `dist/` without its build record: copy `dist/` and `package.json` to a scratch directory, delete
   `dist/build-info.json`, run `node <copy>/dist/cli.js --version` → `0.2.2 (unknown)`, which step 1 accepts for
   `--expect-version 0.2.2`.
3. `grep -n 'runSmoke' scripts/publish-staging.cjs` → `runSmoke({ command: 'wingfoil', env, expectedVersion: version, … })`:
   no expected commit is passed.

## Expected Behavior

In `publish.yml` the staged tarball's `wingfoil --version` is exactly `<version> (<GITHUB_SHA>)`: the job knows the
commit it built, so the smoke can require it, and `unknown`, `-dirty` or another sha fail the stage. A local run
of `e2e-smoke.cjs` without an expected commit may keep today's leniency.

## Actual Behavior

Any stamp with the right semver passes, including `unknown` and `-dirty`.

## Notes

- The pipeline builds with `npm run prepublishOnly` (`npm run build && npm test && npm run lint`) on a fresh
  `npm ci` checkout, so today's `publish.yml` produces a clean `(<sha>)` stamp; the gap is that the gate would not
  notice if it stopped doing so (a build step changed to `tsc` alone, a step that writes into the tree before
  `npm pack`). Medium because this is the last check before the npm publish and `dl-111`'s point is that the
  stamp names the commit.
- Shape of the fix: an `--expect-commit <sha>` option (or `expectedCommit` in `runSmoke`), passed by
  `publish-staging.cjs` from `GITHUB_SHA` in CI, requiring the full stamp; tests for `unknown` and `-dirty`
  refused when it is set.
- No existing bug covers it (`grep -rlE 'versionOfStamp|-dirty|\(unknown\)' docs/04_memory/bugs` → `bug-118`,
  closed, the dirty-target guard, unrelated).
