## Summary

A summary generated from a new project's DNA cannot state what the product is for: `wingfoil dna show --format json`
in a project made by `wingfoil init --template Kanban` returns `project` as `{name, description, methodology}` only.
The finding came from the cheat-sheet prototype of `dl-211` (input given privately to the approver, 2026-11-04), which
read it as "`dna show` has no vision or north-star field". The schema does have one: `spec-002` declares
`project.north_star` as `project`'s one `[SPEC]` field (Product Brief North Star, REQ-SYS-07), `src/dna/schema.ts`
accepts it, and this repository's `dna show` prints it. What is missing is the field in the scaffold `init` writes,
so a new project never learns it exists.

## Steps to Reproduce

1. In a scratch repository: `git init`, `wingfoil init --template Kanban --no-interactive` (pinned build 0.3.2).
2. `wingfoil dna show --format json` → `project` holds `name`, `description`, `methodology`; no `north_star`.
3. `grep -n "north_star" src/storage/templates.ts` → no hit; `grep -n "north_star" src/dna/schema.ts` → the optional
   field.
4. In this repository, `npm run -s wingfoil -- dna show --format json | grep -o '"north_star"[^,]*'` → the value.

## Expected Behavior

The `init` scaffold writes `project.north_star: ""` with a one-line comment saying what it holds (the product's goal or
north-star measure), as it does for `name` and `description`, so `dna show` and the generated summaries of `dl-211`
have a declared place to read it from.

## Actual Behavior

The scaffold omits the field; a project fills it only if its author already knows the schema.
