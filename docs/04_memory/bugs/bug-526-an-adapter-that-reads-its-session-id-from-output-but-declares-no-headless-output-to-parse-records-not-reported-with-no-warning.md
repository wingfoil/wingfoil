## Summary

An adapter that declares `session.id: output` but whose `launch.headless.output` is `none` (or that has no headless
block) gets no stdout reader. Its headless runs record `session` `not-reported` and print no warning. `spec-016` §2.6
says that "No id found … yield `not-reported` and one `warning:` line", which arguably covers this case: the
configuration cannot work and nothing says so.

## Steps to Reproduce

1. At `task-356`'s head: `grep -n "output: none reads nothing" test/agent/launch-session-output-bounds.test.ts` → the
   test "output: none reads nothing: not-reported, no warning", which pins the silence.
2. Declare a custom adapter with `session: { id: output, field: id }` and `launch.headless.output: none`, and run it
   headless: the record says `not-reported`, stderr has no warning.

## Expected Behavior

Either the manifest's second validation pass refuses `session.id: output` without a headless `output` of `json` or
`jsonl`, or a headless run of such an adapter prints the one warning §2.6 describes. `spec-016` §2.6 states which.

## Actual Behavior

The run records `not-reported` silently.

## Notes

Low: no shipped adapter has the combination (`claude-code` takes its id from `--session-id`, `codex-cli` declares
`jsonl`). Introduced by `task-356`; found by its review (finding 5). The test named above is that task's own (not a red
file); the fix changes it.
