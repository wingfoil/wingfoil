## Summary

`errorDetails` (`src/core/error-details.ts`), the renderer of a refusal's structured details, reads only
`details.diagnostics` and `details.issues`; every other key a `CoreError` carries in `details` reaches neither the
human output nor `--format json`.

## Steps to Reproduce

On `main` at `0da232cb`:

1. `sed -n 34,49p src/core/error-details.ts` → `diagnostics`, else `issues`, else `[]`; its header comment (line 25)
   says "Anything else in `details` is ignored".
2. `grep -rn "details: {" src --include=*.ts | grep -v "issues\|diagnostics" | head` → errors that carry other
   structured keys, which `errorDetails` drops.

## Expected Behavior

Either `spec-005` §3 states that only `issues` and `diagnostics` are rendered (so a writer of another key knows it is
internal), or the renderer passes the other keys through to the JSON envelope.

## Actual Behavior

As in step 1: the rule exists only in a code comment.
