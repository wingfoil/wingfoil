## Summary

`codex-cli` runs record the session id as `not-reported` and declare resume unsupported (`task-237` ruling D-3),
although Codex prints the session id (`/status`, the exit line) and keeps it in its rollout file, so a `codex-cli`
run cannot be resumed through `agent execute`.

## Steps to Reproduce

1. The `codex-cli` built-in (`task-237`): `session.id: none`, `resume.supported: false`, `usage.from: none` (ruling
   D-3 of 2026-10-14: no option assigns a session id and no command prints a past session's id to a `command` + argv
   lookup); `codex resume --help` → `Usage: codex resume [OPTIONS] [SESSION_ID] [PROMPT]`.
2. `task-237`'s by-hand pass (run `adhoc/2`, 2026-10-14): `/status` showed `Session 01a13aef-8d19-72d3-a7b3-6b7f53a61e6d`;
   `/exit` printed `codex resume 01a13aef-…`; the rollout `~/.codex/sessions/2026/10/14/rollout-…-01a13aef-….jsonl`
   exists; the run record has `session` `not-reported`.

## Expected Behavior

With v0.4's resume (`spec-016` §7), the adapter learns the session id (for example from the rollout file of the run's
start time and working directory) and records it, and `resume.supported` becomes true for `codex-cli`.

## Actual Behavior

The id is visible to the user and not to WingFoil.
