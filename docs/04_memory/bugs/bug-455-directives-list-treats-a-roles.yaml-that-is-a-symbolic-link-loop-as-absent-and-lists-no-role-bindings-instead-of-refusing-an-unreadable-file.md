## Summary

`directives list` reads `roles.yaml` only when `documentExists` (`existsSync`) says it exists
(`src/core/directives-list.ts:205`); a `roles.yaml` that is a symbolic-link loop reads as absent, so the command lists every
directive as unassigned at exit 0 instead of refusing an unreadable file.

## Steps to Reproduce

1. In a project made with `wingfoil init --template scrum`, on the code build of `release/0.3` (`0.3.1 (d3aee04b…)`).
2. `rm .wingfoil/roles.yaml && ln -s roles.yaml .wingfoil/roles.yaml` (a link to itself).
3. `wingfoil --format json directives list` → exit 0, every entry with `"roles":[]` and `"assignment":"unassigned"`.

## Expected Behavior

An unreadable `roles.yaml` is refused like the other configuration readers since `task-309`: `error: .wingfoil/roles.yaml cannot be
read (ELOOP)`, exit 1; only a truly absent file (ENOENT, a dangling link) reads as "no roles.yaml".

## Actual Behavior

`existsSync` returns false for a link loop, so the read is skipped and no error surfaces.
