## Purpose

The `dependency-check` GitHub Actions workflow (`.github/workflows/dependency-check.yml`, `task-190`) runs on a `schedule` trigger. It runs npm ci, check:lockfile, check:audit and check:audit:all daily, so lockfile drift and new advisories are seen between releases (dl-069, dl-105).
GitHub disables a scheduled workflow after 60 days without repository activity, and failure emails for scheduled
runs reach only the user who last changed the cron, so a disabled or failing check would go unnoticed. This
element records the setting and how to read its state (`bug-252`, `dl-105` R2 (c)).

## Configuration

- Workflow file: `.github/workflows/dependency-check.yml`; its cron string and triggers are in the file header.
- State on 2026-10-06: `active` (the approver's `gh api …/actions/workflows` listing).
- No secret is involved: the workflow reads the repository only.

## Verification

`verify` prints the workflow's `name` and `state`. `active` is the expected value; `disabled_inactivity` or
`disabled_manually` means the check no longer runs. The latest run's conclusion is visible at `url`.

## Management

Re-enable a disabled workflow from the Actions page (or `gh workflow enable dependency-check.yml`), then run it once by hand
(`gh workflow run dependency-check.yml`). Check the state at each release-planning. Retire with `memory deprecate` when the
workflow engine takes the cadence over (`dl-105`) or the workflow is removed.
