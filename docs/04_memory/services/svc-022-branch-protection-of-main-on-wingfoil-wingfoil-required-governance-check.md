## Purpose

Makes the governance check binding (`git-conventions` §9, `dl-103-governance-enforced-outside-the-agent` §1 (C)).
`.github/workflows/governance.yml` (`task-208`) runs `scripts/check-governance.cjs` over every range pushed to `main`
and every pull request into it; without this protection a failing run only reports, and a pull request with a
`wf()` commit that breaks the declared grammar, an approval without authority, or an approve carrying an AI
co-author could still be merged. This element is `task-208`'s AC 5, which `task-278` (`bug-308`'s fix: no false
positive on non-linear history) unblocked.

## Configuration

Set by the approver on 2026-10-15 with `gh api -X PUT repos/wingfoil/wingfoil/branches/main/protection`:

- **Required status check:** `governance`, the job of that name in `.github/workflows/governance.yml`.
- **Strict (branch up to date before merging):** off.
- **Enforce for administrators:** off. The approver pushes to `main` directly, and a required check cannot be green
  on a commit before that commit is pushed, so administrators bypass it; pull requests into `main` are gated. A
  direct push is still checked by the workflow's `push` run, after the fact.
- **Force pushes:** blocked. **Deletion of `main`:** blocked.
- **Required pull request reviews:** none.
- No secret is involved: the protection is a repository setting, and the check runs with the workflow's read-only
  `contents: read` permission.

## Verification

`verify` prints the six values. On 2026-10-15 it printed
`{"admins":false,"checks":["governance"],"deletions":false,"force":false,"reviews":false,"strict":false}`, the
configuration above. `checks` must list `governance`; a missing protection (`gh api` answers 404 `Branch not
protected`) means the check no longer binds.

## Management

- **Owner:** the `approver` role; only the approver changes this setting (`dl-103` §1 (C)).
- **Change:** `gh api -X PUT repos/wingfoil/wingfoil/branches/main/protection` with the full new body (a PUT replaces
  every field), or Settings → Branches; then this element's Configuration, so the two never disagree. If the
  `governance` job is renamed in `governance.yml`, the required check must be renamed with it, or every pull request
  waits for a check that never reports.
- **Lift temporarily** (e.g. for a history rewrite the approver rules, which needs a force push):
  `gh api -X DELETE repos/wingfoil/wingfoil/branches/main/protection`, then re-apply the same values and re-run
  `verify`; record both dates here.
- **Retire:** `memory deprecate` if the rule moves elsewhere (e.g. a repository ruleset), naming the replacement in the
  `Reason:`.
