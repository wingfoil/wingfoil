## Description

`bug-222`: when the CLI's stdout goes to a pipe and the output is larger than the pipe buffer (64 KiB on
Linux), it is cut short and the process still exits 0. `exitWith` (`src/cli/exit.ts`) calls
`process.exit(code)` right after `process.stdout.write(...)` (`src/cli/registrar.ts`,
`src/cli/init-command.ts`), and a pipe write is asynchronous, so whatever is still queued is dropped.
`wingfoil memory search --format json | jq` gets truncated JSON on this repository (65,536 or 81,920
bytes piped against 227,487 to a file), the `docs/user-guide.md` §10 example is already over the limit,
and `spawnSync`-based tests receive unparsable output. The released 0.2.x behaves the same.

## Acceptance Criteria

- (red-first) A test spawns the built CLI with a payload larger than 64 KiB, through a pipe and through
  `spawnSync`, and parses the whole output: it is complete and the exit code is unchanged, on every run.
- (red-first) The error path keeps its exit code (1/2) and its complete stderr under a pipe.
- (characterization) `spec-005` §1's single exit function is kept: every exit still goes through
  `exitWith` (or its replacement), and the exit-code contract (REQ-INT-04) is unchanged; if the function's
  shape changes, `spec-005` is amended with a dated Revision note.
- (characterization) `docs/user-guide.md` §10 and `docs/examples/` pipe examples run to completion with a
  large result; any example that relied on a short result is noted.
