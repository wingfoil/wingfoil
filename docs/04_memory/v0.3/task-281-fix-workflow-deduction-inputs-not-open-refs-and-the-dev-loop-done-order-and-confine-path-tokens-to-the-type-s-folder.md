## Description

Fix five inherited v0.3 bugs that were `triaged` with no task, all in the workflow deduction and the commands around it:

- `bug-300`: after a re-entry, an older hand-written bracketed submit hides a later bracketless CLI submit from
  `spec-017` §4.8's state rule, so `dev-loop.review` stays `missing=state` after a re-submit.
- `bug-301`: `readDirty` (`src/core/workflow-deduction.ts:311`) does not list `.wingfoil/dna.yaml` among the
  uncommitted inputs (`W_UNCOMMITTED_INPUTS`, `spec-017` §1.2), though `dna:` collections and `next`'s holders are
  read from it.
- `bug-313`: `dev-loop.yaml`'s `done` orders `memory.approve` → `git.merge` → `git.remove_worktree` →
  `element.set_state(done)` (`sed -n 194,198p .wingfoil/workflows/custom/dev-loop.yaml`), while practice approves,
  finalizes and syncs the bugs on the task branch before the merge.
- `bug-325`: `memory add --set <token>=<value>` substitutes a value with `..` segments into the type's `path` pattern,
  so the document can land anywhere under the project root, `.wingfoil/` included (`workflow start --set` too).
- `bug-326`: `workflow next` and `workflow finalize` answer `unknown workflow: <ref>` for a plan that exists but is
  not open, where `workflow end` and `spec-017` §10 say `workflow is not open: <ref>` (`src/core/workflow-next.ts:525`
  answers it only for a workflow name; `src/core/workflow-start-end.ts:325` also for a known instance).
