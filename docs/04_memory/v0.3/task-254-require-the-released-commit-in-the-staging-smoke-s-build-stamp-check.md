### design (architect)

- `depends_on: []`. Read `task-192`'s Execution Notes (point 9: `--expect-version X` accepts `X (<sha>)`
  and a bare `X`; `publish-staging.cjs` passes through it), `bug-235`, `dl-111` (`ready`) and `spec-015`
  §3 (`status: approved`). The build record's `commit` is the full `git rev-parse HEAD`, `<sha>-dirty`
  or `unknown` (`scripts/write-build-info.cjs` `computeBuildInfo`), so the expected stamp is compared
  as an exact string with the full sha `GITHUB_SHA` carries.
- **Shape.** `runSmoke({ expectedCommit })` / `e2e-smoke.cjs --expect-commit <sha>` (requires the
  version; must be 7–64 lowercase hex, so `unknown`/`-dirty` can never be what is expected).
  `publish-staging.cjs --expect-commit <sha>` validates before anything starts and forwards it through
  `effects.smoke(env, version, commit)`. `publish.yml`'s stage step passes `--expect-commit "$GITHUB_SHA"`.
- **Decision for the approver — explicit flag, no `GITHUB_SHA` fallback inside the script.** The workflow
  names the commit on the step (the determinism directive prefers declared over inferred input), and an
  unset `GITHUB_SHA` expands to `--expect-commit ""`, which `parseArgs` refuses (exit 2): the stage fails
  closed instead of running unchecked. A local `npm run publish:staging` without the flag keeps today's
  check and logs `no --expect-commit: the build stamp's commit is not checked`. `ci.yml` untouched.
