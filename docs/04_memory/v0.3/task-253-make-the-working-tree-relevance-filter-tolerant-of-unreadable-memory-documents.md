## Description

`bug-230`: `filterRelevantMemoryDocuments` (`src/core/relevance.ts`), exported from the package entry point,
still reads the working tree through the strict primitives. One malformed Memory document makes it throw for
every element, and a symlinked document is dropped with no report, where every other Memory scan has been
tolerant since `task-171` (`W_MEMORY_UNREADABLE`). `RelevantMemoryResult` has no diagnostics channel.

## Acceptance Criteria

- (red-first) with a malformed Memory document and a symlinked one in the working tree, the filter returns the
  relevant readable documents and reports each of the two as `W_MEMORY_UNREADABLE` (repository-relative path)
  through a diagnostics field of its result; it never throws on another document's content.
- (characterization) `selectRelevantMemoryDocuments` stays pure, and the ranking of readable documents is
  unchanged (existing relevance tests green).
- (characterization) the design chooses between the two fixes the bug names (tolerant scan plus a diagnostics
  field, or removing the working-tree reader in favour of ranking a snapshot) and records why; a removal is a
  public API change and is noted in `docs/cli-reference.md`'s library notes or `CHANGELOG.md` if they cover it.
