## Description

`wingfoil workflow next` has lost its headroom on REQ-PERF-03 (`< 1,000 ms (p95)`, its total and its marginal cost
over process start-up alike, `dl-146` Q3). The opt-in latency suite measured it at the W3 B7 gate, idle (load about
2):

| Head | `npm run test:latency`, `workflow next` p95 (n = 25) |
|---|---|
| B6 gate `1c66ef31` | 476 ms (min 373, max 478) |
| `856f3489` (`task-280`'s head: `main` `32d8871b` plus tests only) | **1,005 ms** (min 487, max 1,027), over budget |
| `507848a5` (`task-281`'s head) | 968 ms |
| B7 gate `6e454f40` | 911 ms (min 567, max 922), load 1.86-2.16; 900 ms in the gate's own run |

`main` without B7's code is as slow, so B7 did not cause it: the cost grows with the repository (`git rev-list --count
1c66ef31..32d8871b` → 148 commits on `main` before B7's merges, 379 to the gate `6e454f40`), and `bug-309` (48 git spawns per call; the directives read one `git show` each; the
snapshot's commit resolved nine times) is where the time goes. This task cuts the spawns per call until the p95 is
back under the budget with margin, without touching the budget.
