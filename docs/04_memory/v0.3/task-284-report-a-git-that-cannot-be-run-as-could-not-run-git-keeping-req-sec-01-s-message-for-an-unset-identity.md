## Description

Every state-mutating command runs `requireGitIdentity` first (REQ-SEC-01, `src/core/git-identity.ts`), which reads
the identity with one `git config -z --get-regexp` spawn in `readIdentityConfig`. That function catches every
failure of the spawn and returns an empty map (`sed -n 31,44p src/core/git-identity.ts` at `b8dcb2df`), so a git that
cannot be run at all (`ENOENT`, `EACCES`, `EPERM`) is reported with REQ-SEC-01's message, `git identity not
configured (user.name/user.email)`, and the user is sent to fix a configuration that may be right (`bug-377`: seen on
2026-10-15 with Codex CLI 0.145.0's default sandbox, where Node's spawn of `git` failed with `EPERM`). This task
separates the two cases: a spawn failure gets its own refusal naming the cause; REQ-SEC-01's message stays for an
identity git reports as unset.

## Acceptance Criteria

- (red-first, `bug-377`) When `git` cannot be spawned, `requireGitIdentity` refuses with `could not run git:
  <cause>`, where `<cause>` is the spawn error's code and message (for example `spawnSync git EPERM`), mapped to
  exit `1` on the CLI, and the command writes nothing. It fails on `main` at `b8dcb2df`, where the message is
  REQ-SEC-01's.
- (characterization, REQ-SEC-01) When git runs and `git config --get-regexp` matches no key (its exit `1`), the
  refusal is still exactly `git identity not configured (user.name/user.email)`, exit `1`; the existing tests of
  `test/core/git-identity.test.ts` and `test/core/identity-preflight-committer.test.ts` pass unchanged.
- (red-first, `bug-377`) A test runs a mutating CLI command with an unrunnable `git` first on `PATH` (an empty
  directory as `PATH`, giving `ENOENT`, or a non-executable file named `git`, giving `EACCES`) and asserts the new
  message, exit `1` and an unchanged working tree; the positive case (git on `PATH`, identity configured) passes the
  check.
- (characterization) `npm test` (coverage > 80 %, non-regressing), `npm run lint`, both `tsc` and `npm run docs:api`
  stay green.
