## Description

Implements `dl-149`: every WingFoil file declares its format in a `format:` key, distinct from
`version:` (the content revision, `dl-047`/`task-183`). An absent key reads as `format: 1`; the
format of a file kind is bumped only on a backward-incompatible change of that kind. Urgent for v0.3,
because v0.3 makes workflows executable and grows their schema (`task-185`), so the key must exist
before the first incompatible workflow file does.

File kinds: `dna.yaml`, `memory.yaml`, `roles.yaml`, `workflows.yaml`, each workflow file, directive
frontmatter, Memory template frontmatter. Agent adapter manifests already carry `format`
(`task-177`, `ADAPTER_MANIFEST_FORMAT`) and are the model.

## Acceptance Criteria

- (red-first) each file kind's schema accepts an optional integer `format:`; a file with no `format`
  loads exactly as today (read as format 1). Every configuration file in this repository and every
  `init` scaffold loads unchanged.
- (red-first) a file whose `format` is greater than the highest this build reads is refused with an
  error naming the file, its format, the highest supported one and "upgrade WingFoil", at the exit
  code `spec-005` assigns to an invalid configuration.
- (red-first) a non-integer or non-positive `format` is refused as a schema error naming the field.
- (red-first) `wingfoil init` writes `format: <current>` in every configuration file, workflow file,
  directive and Memory template it scaffolds, and the scaffold round-trips its own loaders.
- (characterization) the supported formats are declared once per file kind, as constants next to
  `ADAPTER_MANIFEST_FORMAT`, all `1` in this release.

  and the bump rule; the "config-file format version" annotations on `version:` in `dna.yaml` and
