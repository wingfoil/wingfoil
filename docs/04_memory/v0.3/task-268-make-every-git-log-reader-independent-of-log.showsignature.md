## Description

Closes `bug-291`: with `log.showSignature=true` in any git configuration level and signed commits, git prints the
signature status on stdout among a `git log`'s formatted lines. `memory history` then exits 1 ("creation commit No
signature is not present in the history walk …"), because its readers (`walkGitLogFields` in
`src/memory/git-log.ts`, the `--follow` probes `CREATION_PROBE_ARGS` / `PATH_PROBE_LOG_ARGS` in
`src/memory/history.ts`) parse those lines as commits. `task-220` fixed `agent show` alone
(`src/core/agent-show.ts`: `--no-show-signature` and a sha-shaped line check); the deduction's `git log` in
`src/core/workflow-deduction.ts` has the same exposure.

## Acceptance Criteria

- (red-first) With `log.showSignature=true` and a signed commit in an isolated scratch repository (no global or
  system config of the developer read or written), `memory history <id>` exits 0 and reports the same entries as
  with `log.showSignature=false` — the reproduction of `bug-291`.
- (red-first) Every `git log` / `rev-list`-style reader in `src/` that parses formatted output passes
  `--no-show-signature` (or an equivalent that ignores the setting), and a parsed commit name that is not a full
  sha is refused as `IO` rather than used; a test enumerates the readers (`grep -rn "'log'" src` or a shared
  helper) so a new reader without the flag fails.
- (characterization) Output of every touched command is byte-identical with `log.showSignature=false`.
